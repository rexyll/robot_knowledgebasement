# 外部工程项目集成与知识化治理规范

- 状态：执行中
- 建立日期：2026-11-14
- 适用范围：本知识库引用、评估、复用或可能引入的外部机器人软件/硬件工程仓库
- 关联根计划：00-01；全局 Guide G-08、G-11、G-15、G-16、G-17、G-20、G-25；全局 Limit 4、7、12、17、18

## 1. 目的

本知识库是机器人行业知识、方法、架构、来源和验证证据的统一入口，不是所有外部工程源码的集中存储库。外部工程项目默认保持独立仓库，通过项目档案、精确版本引用、技术映射、审查报告和测试证据建立关联。

## 2. 默认策略

1. **知识优先纳入，源码默认不复制。** 优先整理独立撰写的原理、接口、架构、测试方法、适用边界、故障案例和已验证结论，并链接上游仓库。
2. **保持工程仓库独立。** 驱动、控制器、仿真器、SDK 适配和产品工程保留自己的版本、依赖、CI、发布与问题跟踪。
3. **精确追溯。** 每条结论应尽可能记录仓库 URL、分支、commit SHA、文件路径、访问日期、工作流/测试 Run ID 和证据等级；可变的 main/master 链接不能替代 commit pin。
4. **证据分级。** 明确区分静态审查、用户报告、上游 CI、目标仓库构建、单元/集成测试、仿真、SIL、HIL、实机和产品验收。一个等级的通过不得推导为更高等级通过。
5. **适用边界透明。** 记录目标硬件、型号/固件、OS/ROS 发行版、编译器、依赖版本、实时预算、通信协议和安全责任。未验证项标为未知/待验证/阻塞。
6. **避免重复建设。** 知识库保留可复用的概念和验证结论；具体工程实现、源代码、二进制和完整日志保留在各自项目，知识库只保存必要的摘要、链接和受控证据索引。

## 3. 源码引入准入门

任何源码复制、subtree、submodule、vendor 或其他形式的源码引入，均须逐项满足：

- 取得适用于拟引入文件的明确许可证；核查文件级例外、第三方代码、测试夹具、脚本、文档、模型/数据和 SDK 资源。
- 完成许可证兼容性、版权/NOTICE、专利条款、再分发方式和目标仓库许可证审查；许可证不明时只链接、不复制。
- 固定上游 commit，并建立文件级来源清单与变更差异记录。
- 完成依赖、构建选项、平台/版本矩阵、工具链、SBOM 和漏洞扫描评估。
- 完成目标仓库接口适配、构建、测试、故障注入和回归；实时性、安全功能和硬件兼容必须有与目标平台相符的证据。
- 说明后续同步策略、上游安全更新责任、维护人和退出/替换方案。
- 获得用户对具体引入范围和目标分支的明确授权；在独立分支提交审查，不得因“测试通过”自动合并 main。

使用 Git submodule 或仅保留链接，不代表许可证、供应链、兼容性或安全审查已经通过。

## 4. 外部项目档案最低字段

每个项目在 `docs/audits/External-Project-Registry.md` 登记：项目名称、上游 URL、目标知识章节、用途/不适用范围、当前处理方式、审查日期、精确版本、许可证状态、依赖/构建状态、测试证据等级、已知阻塞、允许动作、禁止动作、下一步和证据链接。

## 5. 任务状态约定

- **仅登记**：已建立链接和档案，尚未完成技术审查。
- **静态审查**：已阅读指定文件，但未构建或运行。
- **基础测试待复核**：有测试通过报告或用户报告，仍需核对测试范围、commit、日志和失败项。
- **兼容性评估**：正在验证目标仓库接口、依赖、构建和行为。
- **准入待审批**：技术/合规门槛已完成，仍需用户明确授权。
- **已引入**：仅在许可、验证、审批和 PR 合并全部完成后使用。
- **阻塞**：明确记录阻塞原因和解除条件。

## 6. 维护规则

项目版本、许可证、CI、支持平台和维护状态变化时，更新项目档案和日期快照。不要覆盖旧结论；追加新记录并说明哪些旧判断已失效。知识库中的外部项目档案不替代上游项目自身的 TaskPlan、Issue、PR 或安全公告。
