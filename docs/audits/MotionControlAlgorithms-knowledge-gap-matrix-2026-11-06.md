## 3. 处理原则

1. 不复制上游源码、测试、脚本、benchmark 或其实现片段。上游仓库整体许可证在本轮审查时仍未确认；按根计划 G-08 只保留链接和独立分析。
2. 对目标已有文章优先增补，不建立平行重复正文；每个新增专题必须先检查索引和主归属。
3. 上游的算法名称/接口设计可作为审查线索，不能直接当作目标机器人适用结论。必须说明模型假设、坐标系、采样周期、执行器限制、状态估计来源和失败模式。
4. 所有控制算法按单元测试、模型/仿真、SIL、PIL/HIL、目标实机分级记录证据；没有执行的测试不得标记通过。
5. CiA 402/EtherCAT 等通用协议模型不代表任意厂商设备兼容；必须核对型号、固件、EDS/ESI、PDO 映射、比例换算、时序和故障恢复。
6. 软件停止命令、CBF、碰撞监控或仿真结果均不自动构成 STO、独立安全回路或功能安全认证。

## 4. 建议执行顺序

1. **PID 与基础闭环**：采样/离散化、饱和与 anti-windup、微分滤波、级联控制、单位/符号/方向检查、噪声与时延。
2. **轨迹生成与时间参数化**：梯形/S 曲线、jerk 约束、多轴同步、TOPP 类方法、在线重定时和执行器限幅。
3. **运动学与动力学**：SE(3)、DH/POE、雅可比、数值 IK、动力学与参数辨识。
4. **状态估计到控制闭环**：估计延迟/协方差/异常值如何影响控制器，补齐控制与定位的接口。
5. **底盘与机械臂控制专题**：统一模型、接口、调参、约束和工况测试。
6. **MPC/QP/CBF 与特种机器人**：在基础模型与失败降级路径明确后深化。
7. **驱动/总线集成和 HIL**：逐型号验证，不把 SIL/模拟 API 当成实机互操作。
