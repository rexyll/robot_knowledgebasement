# 视觉感知算法

> 把像素/点云变成"世界上有什么、在哪、在动"的结构化信息，喂给规划与交互。是 [[学习型机器人算法]] 与传统视觉的分界线——现在感知主流就是深度学习。

## 感知任务谱系

| 任务 | 输出 | 机器人用途 | 代表模型 |
|---|---|---|---|
| **目标检测（2D）** | 框+类别+置信度 | 行人/货物/电梯门识别 | YOLOv8/11、RT-DETR |
| 实例/语义分割 | 像素级掩码 | 可行驶区域、动态物滤除（SLAM 用） | YOLOv8-seg、SAM/SAM2（零样本） |
| 3D 检测 | 3D 框/点云簇 | 障碍物尺寸估计 | PointPillars、CenterPoint、OpenPCDet |
| 点云分割聚类 | 障碍簇 | LiDAR 感知（无学习也可用） | 欧式聚类、Ground 拟合（Patchwork） |
| 跟踪 | 时序轨迹 | 行人速度估计→避障预测 | SORT/DeepSORT、ByteTrack |
| 里程计/深度估计 | 位姿/深度图 | VIO 补充 | DROID-SLAM、Depth Anything |
| VLM 开放词汇 | 任意文本查询 | "找出红色货架"（长尾场景） | CLIP、YOLO-World、GroundingDINO |

## 端侧部署链（→ [[计算平台]] · [[视觉软件栈]]）

```
训练: PyTorch + COCO/自采数据(标注 Label Studio/Isaac 合成数据)
导出: → ONNX(算子检查!) → TensorRT(FP16/INT8 量化, 校准集 500-1000 张)
端侧: Jetson Orin 上 YOLOv8n 640×640 ≈ 30-60fps; RK3588 NPU ≈ 15-30fps(RKNN)
工程: 输入前处理 GPU 化 + 输出后处理(NMS)减少 CPU 瓶颈 + 多路相机复用 batch
```

## LiDAR 感知流水线（无相机参与的传统强项）

```
原始点云 → 地面分割(Patchwork/RANSAC平面) → 非地面点云
→ 聚类(欧式聚类/DBSCAN, 体素加速) → 障碍簇(质心/包围盒)
→ 跟踪关联(匈牙利+KF) → 速度/类别 → 代价地图/预测
低算力机型: 直接投影 2D 扫描线做 2D 聚类(扫地机/商用清洁)
```

## 多传感器融合感知

- **前融合**：LiDAR+相机原始数据联合网络（BEV 范式，BEVFusion）——强但贵
- **后融合**：各传感器独立检测后按位姿+时戳融合（联合卡尔曼/加权投票）——工程主流（AMR 常用）
- 时间对齐是生死线：10ms 错位 = 高速下 1.5cm 误差 → [[视觉软件栈]] 同步章节

## 机器人感知的特化需求（与自动驾驶差异）

1. **近场低矮障碍**：0.05-0.5m 的线缆/桌腿（LiDAR 盲区）→ 深度相机+超声波补 → [[深度相机]]
2. **窄场景高精度**：±5cm 对接 → AprilTag/二维码地标识别（快准稳）→ [[充电桩与自动充电]]
3. **语义交互**：电梯按钮、门把手 → 关键点检测+机械臂（复合机器人）
4. **算力受限**：整栈 <15W → 蒸馏+量化+关键帧跳检
5. **动态人识别优先级最高**：安全相关，漏检致命 → 多冗余（LiDAR+相机+触边）

## 细节加深（V2）
- **许可证红线**（台账 #71/#75，快照 2026-11-01）：Ultralytics YOLO = **AGPL-3.0（商用闭源需企业许可）**；Depth Anything V2 的 B/L 档 = CC-BY-NC。商用闭源替代：YOLO 系列的老版本权重（YOLOv5 早期 GPL 争议同样存在）→ 稳妥走 OpenPCDet（Apache-2.0）/PointPillars（MIT，#73）自训。
- **3D 检测工具箱**：OpenPCDet（#72，Apache-2.0）是 PointRCNN/PV-RCNN 官方实现；轻量部署选 PointPillars（#73，MIT，带 ONNX/TensorRT 导出）。
- **SAM2/Depth Anything**（#74/#75）：分割/深度基础模型，机器人上主要用于标注加速与半监督——直接端侧实时跑仍然吃力。
