# 实时系统与嵌入式

> "实时"= 在确定时间上限内完成响应（不是"快"）。机器人控制分 1kHz 硬实时（电流环）→ 100-1kHz 准实时（底盘）→ 10-50Hz 软实时（导航决策）→ 秒级（云）四层（→ [[AMR整体架构]]）。

## Linux 实时化路线

| 路线 | 延迟量级 | 代价 | 用途 |
|---|---|---|---|
| 标准 Linux | 毫秒级抖动 | 无 | 导航/感知/业务（非硬实时） |
| **PREEMPT_RT 补丁**（2024 起已并入主线内核 6.12） | <100μs | 少量吞吐 | ros2_control 1kHz 关节控制、底盘 |
| Xenomai 3 / RTAI | <50μs | 双内核复杂 | 严苛伺服 |
| RTOS（FreeRTOS/Zephyr/RT-Thread） | μs 级确定性 | 无 Linux 生态 | MCU 电流环、安全逻辑 |
| 裸机 | 确定性最强 | 开发苦 | 极简固件 |

- Zephyr：Linux 基金会 RTOS，安全认证版（Zephyr Safety），人形/无人机 MCUL 侧在扩散
- MCU 侧选择（AMR 底盘）：STM32F4/H7（主流）、GD32（国产替代）、ESP32（带 WiFi 的辅助）

## 实时性指标

| 指标 | 含义 | 典型要求 |
|---|---|---|
| 最坏执行时间 WCET | 单次最大耗时 | 电流环 <50μs |
| 抖动（Jitter） | 周期漂移 | 控制环 <10μs |
| 响应时延 | 事件→动作 | 急停 <10ms（机械） |
| 调度延迟 | 就绪→运行 | PREEMPT_RT <50μs |

## 通信总线（嵌入式层）

| 总线 | 速率 | 实时性 | 场景 |
|---|---|---|---|
| UART/串口 | 115.2k-3Mbps | 无保证 | 主控↔MCU（最常见，配 CRC+心跳） |
| **CAN / CAN FD** | 1M / 5Mbps | 仲裁确定性（ID 优先级） | 电机、BMS、车身 |
| EtherCAT | 100M | <1μs 同步 | 多轴机械臂 |
| RS485 | 115.2k | 轮询 | 传感器慢速链 |
| SPI/I2C | 板级 | — | 板内传感（IMU） |
| 100BASE-T1 车载以太网 | 100M | TSN 扩展 | 新一代集中式架构 |

## 工程模式：双脑架构（主控+MCU）

```
Linux(Jetson/x86)                MCU(STM32)
  ROS2 导航栈                      底盘固件
  输出: Twist(v,ω) 100Hz  --串口/CAN-->  运动学解算+PID 1kHz → FOC
  里程计/状态       <--状态帧 50Hz---    编码器积分+BMS+急停链
  心跳协议: >200ms 无心跳 → MCU 自动刹停 (失联保护)
```

- 协议设计要点：帧头+CRC+序号+心跳；命令幂等；参数区（PID/轮距）可在线调
- [[项目-清洁机器人]] 与 [[项目-amr]] 均为此模式（ROS2 主控 + 底盘 MCU）

## 嵌入式工程实践

1. 看门狗分层：任务级软狗 + MCU 硬狗（独立时钟源）
2. Flash 分区：A/B 双分区 + 空闲回滚 → [[云端协同与OTA流程]]
3. 日志：MCU 日志走 UART 环形缓冲，主控聚合上云
4. EMI：电机 PWM 干扰 IMU/编码器 → 屏蔽与布局（硬件层 [[IMU]] 振动问题同源）

## 细节加深（V2）
- **FreeRTOS 官网**（台账 #90）：MIT 许可（2017 起），MCU RTOS 事实标准；**Zephyr 官网**（#91）：Apache-2.0，Linux 基金会背书+安全认证路线，新一代首选。
- **PREEMPT_RT 已并入主线**（6.12+，台账 #29 kernel.org RT 目录）：Ubuntu 24.04 装 `linux-image-rt-amd64` 即得；验证用 `cyclictest`（目标 max<200μs）。
- **双脑协议三条铁律**（两内部项目实践汇总）：心跳超时自刹停（MCU 侧独立实现）、命令幂等（重发不重复执行）、参数区分运行时/掉电保存两区。
