# 09-09 网络通讯设计（从0搭建 · 第九步）

> 机器人网络三层：**车内网**（传感器/双脑）、**车外网**（车↔开发机/云）、**时间同步**。初学者只在第三层摔跤（时间不同步，TF 报错刷屏）——本章把三层一次配平。

## 1. 车内网（样机实际就两条）

| 链路 | 介质 | 协议 | 带宽需求 |
|---|---|---|---|
| Jetson ↔ LiDAR | USB3 / 以太网 | 厂商驱动 | 2D LiDAR ~1Mbps；3D 20-100Mbps |
| Jetson ↔ MCU | USB（CDC 串口） | 自定义帧/micro-ROS | 115200-921600 baud 足够 |
| Jetson ↔ 深度相机 | USB3 | UVC/厂商 | 30fps 深度 ~100Mbps |

> USB 线是故障率最高的部件：**买带屏蔽的短粗线+扎带固定**；Jetson USB 口带锁扣优先。CAN 车型 → [[实时系统与嵌入式]] 总线节。

## 2. 车外网（开发/运维通道）

```
开发期拓扑(推荐):
  开发PC ──(WiFi 路由器 AP 模式)── Jetson
    ├─ SSH: jetson 固定 IP(路由器 DHCP 绑定 MAC)
    ├─ ROS2 多机: 同网段+同 ROS_DOMAIN_ID
    └─ 可视化: Foxglove/RViz2 over WiFi
生产期演进:
  车队 → 5G CPE/站点 AP → 网关 → 云 (→ [[云平台与IoT通信]])
  弱网兜底: zenoh-bridge-ros2dds (台账 #22) 替代 DDS 组播跨网段
```

- **ROS_DOMAIN_ID 纪律**：同一现场每人/每车一个 ID（0-101），默认 0 会串台——两台车同 ID 会互相收到对方话题，鬼故事制造机。
- **WiFi 选型**：办公路由器即可开发；产线部署换工业 AP（漫游 <50ms），2.4G 穿墙强但带宽窄，点云走 5G WiFi。
- **安全底线**：SSH 密钥登录禁密码；车端开放端口只有 SSH+必要服务（→ [[功能安全体系]] 网络攻击面）。

## 3. 时间同步（多机系统生死线）

| 方案 | 精度 | 用途 | 工具 |
|---|---|---|---|
| chrony (NTP) | 1-10ms | 车队级同步（默认选它） | chrony-project.org（台账 #33） |
| LinuxPTP (PTP) | <1ms（需硬件时间戳网卡） | 传感阵列高频融合 | linuxptp（#34） |

```bash
# 车端配置(chrony 客户端指向开发机/网关为源):
sudo apt install chrony
echo "server 192.168.1.10 iburst prefer" | sudo tee /etc/chrony/sources.d/robot.sources
chronyc tracking   # 验证: System time 偏差 < 10ms
```

> 为什么必须同步：TF 树按时间戳查变换，车与开发机差 200ms → RViz 全红报 Extrapolation；多机融合定位差 10ms = 高速下 1.5cm 空间误差（→ [[多传感器融合定位]]）。

## 6. 细节加深（V2）
- **DDS 多机排障三板斧**：① `ROS_DOMAIN_ID` 是否一致；② 防火墙 `sudo ufw allow` DDS 端口段（7400-7600/udp）或干脆 ufw disable 开发期；③ WiFi 组播被 AP 抑制 → 换 Cyclone 单播发现或 zenoh 桥（快照经验，来源 zenoh 官方文档 #22）。
- **带宽预算表**：2D SLAM 全栈上云遥测 <100kbps；远程接管视频 2-4Mbps；OTA 差分包按仓库大小。部署前对照 AP 标称吞吐×0.5（实际折损）。
- **IP 规划模板**：网关 .1 / 开发机 .10-19 / 车 .100-149 / 充电桩 .150-159 / 电梯盒 .160-169——写进部署文档，现场少吵架。
