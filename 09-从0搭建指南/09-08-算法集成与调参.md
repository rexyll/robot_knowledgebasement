# 09-08 算法集成与调参（从0搭建 · 第八步）

> 目标：车能建图、能定位、能自主跑到点位。路线固定为：**slam_toolbox 建图 → 保存地图 → AMCL/定位 → Nav2 导航 → 按官方调参指南收敛**。原理深水区在 [[SLAM总览]] 与 [[Nav2导航框架]]，本页是"怎么落"。

## 1. 集成顺序（每步有验收）

```
Step1 建图: slam_toolbox 在线模式
  $ ros2 launch my_robot mapping.launch.py   (teleop 推车走)
  验收: 回环闭合, 地图墙线笔直 → [[建图流程]] SOP
Step2 存图: ros2 run nav2_map_server map_saver_cli -f mymap
  产出 mymap.pgm + mymap.yaml → 入库版本管理
Step3 定位: map_server + AMCL(或 slam_toolbox localization 模式)
  验收: 抱起车放回任意点 → 重定位成功(粒子云收敛)
Step4 导航: Nav2 全家桶
  $ ros2 launch nav2_bringup navigation_launch.py
  RViz2 设 2D Goal Pose → 车自主到达
Step5 调参: 按官方 Tuning Guide 迭代 (见下表)
```

## 2. 初学者调参表（按出现频率排序）

| 症状 | 参数/位置 | 药方 |
|---|---|---|
| 车在原地左右摆头 | controller: `dwb` 或换 `regulated_pure_pursuit` | 走直线多的场景直接用 RPP（Nav2 官方推荐重载场景） |
| 到点过冲/反复微调 | `xy_goal_tolerance`/速度 | tolerance ≥ inflation_radius；接近段限速 |
| 擦墙/撞门框 | costmap `inflation_radius` | = 车对角半径 +5cm；`footprint` 填实测轮廓 |
| 动态障碍不避 | obstacle layer `raytrace/obstacle range` | 检查 `/scan` 是否进 costmap（`ros2 topic hz`） |
| 规划路径穿危险区 | Keepout Filter | Nav2 mask filter，区域与 [[多机协同与调度算法]] 规则同源 |
| 建图回环断裂 | slam_toolbox `minimum_travel_distance` | 减小采样距离；地图过大时开 `map_update_interval` 加大 |

> 官方 Tuning Guide 有完整对比表与 RMW 性能数据（台账 #27，快照 2026-11-01）；中文系统实战推荐鱼香ROS《动手学ROS2》第十章（#43 已验证）。

## 3. 融合定位上线（第二步迭代）

跑通 Nav2 后，把 odom 升级为 `robot_localization` ekf 融合（轮计+IMU）：配置维数不重复原则、`map→odom` 由 AMCL 发布——细节与模板见 [[多传感器融合定位]] 与 [[卡尔曼滤波]]。验收：原地快速旋转 10 圈，航向漂移 <5°。

## 6. 细节加深（V2）
- **先仿真后真车**：Nav2 官方 TurtleBot3 仿真包（Gazebo Harmonic，台账 #37）里把上面 5 步先走通一遍，参数搬上真车起点就有 80 分——真车调试成本是仿真 10 倍。
- **调参最小闭环**：每次只改 1 个参数 → 记录（参数/行为/结论）三列表 → 回归跑同一条路径。改 5 个参数再出问题等于从头再来。
- **`use_sim_time` 三兄弟**：仿真/真车配置不同步是「Gazebo 里好好的上车就疯」的第一原因。
