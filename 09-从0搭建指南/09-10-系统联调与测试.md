# 09-10 系统联调与测试（从0搭建 · 第十步）

> 目标：从"能跑"到"可靠地跑"。三层测试网（契约→冒烟→行为）+ 一套现场回归剧本。方法论与两内部项目实践见 [[构建与CI工具链]]。

## 1. 联调顺序（自下而上，禁止跳级）

```
L0 硬件点检: 电压/电流逐点测(→09-03) + 传感数据 ros2 topic hz 全绿
L1 驱动联调: /scan /imu /odom 频率与数值合理性(手动推车看数据)
L2 控制闭环: /cmd_vel 下发 → 车动 + odom 回传一致(误差 <5%)
L3 导航闭环: 09-08 的 Step1-5 全通过
L4 故障注入: 拔 LiDAR/杀驱动节点/断网 → 车应安全停(不是疯跑)
L5 现场回归: 固定剧本跑 N 轮(见 §3)
```

## 2. 三层测试网（落地形态）

| 层 | 测什么 | 工具 | 断言示例 |
|---|---|---|---|
| 契约 | 话题/服务/消息形状 | `ros2 interface show` + schema 比对脚本 | `/odom` 必含 pose+twist；cmd_vel 限幅 |
| 冒烟 | 单节点起得来+数据活着 | launch_testing + `ros2 topic hz` 断言 | /scan 10Hz±10% 持续 30s |
| 行为 | 整车业务场景 | Gazebo（台账 #37）或真车剧本脚本 | 10 个点位循环 50 次成功率 ≥98% |

**仿真先行**：Gazebo Harmonic 安装（#37）+ TurtleBot3 仿真里跑同一套行为测试，真车只做验收（成本 10 倍原则 → [[09-08-算法集成与调参]]）。

## 3. 现场回归剧本（样机期标准 6 项）

| # | 场景 | 通过标准 |
|---|---|---|
| 1 | 50m 直线往返 ×10 | 到位误差 <10cm，无超时 |
| 2 | 绕场一周（含回环区） | 定位无跳变（map→odom 修正 <15cm） |
| 3 | 动态人穿越 ×20 | 减速或绕行，碰撞=0（轻触不算，护边触发即停） |
| 4 | 断网 30s 继续任务 | 任务完成，恢复后状态对账正确 |
| 5 | 急停/恢复 ×10 | 急停响应 <10ms（机械），恢复后无残留错误 |
| 6 | 连续 2h 自主循环 | 无人工干预；日志无未捕获异常 |

## 4. 工具与观测（出问题时看什么）

- **Foxglove Studio**：话题可视化+回放（网页版免装）；RViz2 同级备选
- **rosbag2**：`ros2 bag record -a` 全程录制——每次异常都有数据回放（→ [[ROS与ROS2]]）
- **日志纪律**：节点统一 logger 级别（INFO 常态/DEBUG 按需），错误码收敛成表（参照 [[项目-清洁机器人]] 7 错误码契约）
- **黑匣子**：急停/碰撞前后 30s 单独 rosbag 分片（→ [[功能安全体系]] 取证）

## 7. 细节加深（V2）
- **故障注入脚本模板**：`kill -9` 随机杀一个节点 → 断言「车在 T+2s 内速度归零」——比写 100 个正常用例更能暴露架构问题（两内部项目均有此实践：amr 的 capability_fault_injection、清洁机 SIM_VERIFICATION）。
- **真车测试安全三条**：① 场地物理隔离（围挡/人盯守）；② 遥控优先级高于自主（随时接管）；③ 每次上电先空轮架起跑 5min（→ [[09-03-电子电气设计]] 电源验证后再落地跑）。
- **回归数据化**：每轮剧本跑完自动生成 markdown 报告（通过率/平均耗时/异常码 Top3），连续 3 轮全绿才允许进入下一阶段。
