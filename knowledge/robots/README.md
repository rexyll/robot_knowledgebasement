# 机器人分类与应用导航

本目录按**机器人产品类型与典型应用领域**组织知识卡，帮助读者识别机器人系统的任务对象、工作环境、运动/操作形态和能力边界。它是类型导航入口，不是完整行业清单，也不替代机械、传感器、控制、软件、算法、标准和产业章节的专业正文。

## 1. 分类口径：多个维度交叉，不强行归入单一树

机器人类型存在多维交叉。同一产品可以同时属于多个维度，例如仓储AMR可能是移动机器人、物流机器人、室内自主机器人，并搭载机械臂成为移动操作机器人。阅读和新增条目时，至少区分：

| 分类维度 | 典型取值示例 | 主要回答的问题 |
|---|---|---|
| 应用行业/任务 | 工业制造、仓储物流、清洁、医疗康复、农业、建筑、能源巡检、公共安全 | 为谁、在什么业务中工作？ |
| 运动形态 | 固定式、轮式、履带式、足式、飞行、水下、空间、软体/连续体 | 如何移动或改变构型？ |
| 操作能力 | 仅移动、搬运、抓取/操作、加工/作业、人机协作、遥操作 | 与环境和对象如何交互？ |
| 自治与控制方式 | 遥控、远程监督、半自主、自主、多机协同 | 谁在何种边界内做决策？ |
| 部署环境 | 工厂、仓库、商业建筑、家庭、户外、医疗机构、危险/受限环境 | 受到哪些环境与基础设施约束？ |

这些维度是描述属性，不是相互排斥的产品类别。不要把“应用行业分类”与“运动学/运动形态分类”混成一个互斥树；也不要把自治等级当成所有机器人通用且已经标准化的单一分级。

## 4. 新增类型卡的最低要求

新增类型或细分领域时，至少说明：
1. 定义、边界、别名及与相邻类型的区别；
2. 典型任务、对象、工作空间和部署环境；
3. 运动/操作形态、自由度或关键机构（适用时）；
4. 典型感知、计算、能源和通信配置；
5. 自治方式、人工介入和系统运行约束；
6. 主要失效模式、安全风险、法规/标准适用性；
7. 代表性产品/实现及其型号、地区、版本和来源（有可靠证据时）；
8. 与机械、电子、软件、算法、应用和产业章节的链接；
9. 未覆盖内容、待核实主张和更新日期。

厂商产品案例不能代表整个机器人类型；营销名称不能替代可解释的技术分类。涉及医疗、工业协作、无人机、危险环境等监管场景时，必须区分一般技术介绍与具体产品/场景的合规结论。

## 5. 当前范围限制

当前目录中的知识卡仍需逐篇核验。分类入口和链接整理不构成全类型覆盖完成，也不构成任何产品的性能、安全、法规或量产验收结论。新增类别应先检查是否属于现有条目的子类、交叉属性或独立技术主题，避免重复建页。
