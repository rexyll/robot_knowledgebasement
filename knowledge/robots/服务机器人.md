# 服务机器人

> 服务机器人是按任务用途划分的机器人类别，不是某一种底盘或软件架构。ISO 8373:2021 将其定义为执行对人或设备有用任务的机器人；实际产品可以是移动、固定、穿戴或其他形态，也可能包含人机交互或远程操作环节。分类时必须同时看预期用途、工作环境、自动化程度和适用法规，不能把“服务机器人”简单等同于 AMR 加语音交互。

## 1. 定义与分类边界

### 1.1 标准定义

ISO 8373:2021 的术语体系分别定义工业机器人、服务机器人和医疗机器人。服务机器人执行对人或设备有用的任务；工业机器人以工业自动化应用为边界；医疗机器人按其预期作为医疗电气设备或医疗电气系统使用来界定。具体产品的归类应以标准原文、预期用途和适用法规为准。

IFR 的市场统计进一步区分专业服务机器人、消费服务机器人和医疗机器人：
- **专业服务机器人**：用于专业场景，通常需要经过培训的操作人员；例如商业配送、公共场所清洁、消防搜救等。
- **消费服务机器人**：面向普通消费者，正常设置和使用不要求专业操作培训；例如家用清洁、草坪维护和部分陪伴/交互产品。
- **医疗机器人**：IFR 按独立类别统计，不应简单并入一般专业服务机器人市场。

IFR 的统计分类是市场统计口径，不等于产品法规分类，也不替代具体系统的安全风险评估。IFR 还说明，某些应用统计可能包含受用途或法规约束的机器人设备；因此不能仅凭市场统计标签推断某产品满足 ISO 对机器人的全部定义。

### 1.2 主要应用领域

| 应用领域 | 典型任务 | 主要工程关注点 | 分类提醒 |
|---|---|---|---|
| 酒店、餐饮与楼宇配送 | 物品递送、房间/楼层间运输 | 人员混行、交接、门禁/电梯、清洁维护 | 需区分楼宇内配送与公共道路配送 |
| 接待、导览与远程呈现 | 信息查询、导览、远程巡查/沟通 | HRI、语音/屏幕交互、隐私、网络质量 | 交互能力不代表具备自主移动能力 |
| 公共空间清洁 | 地面清洁、区域巡检 | 清洁效果、环境适应、人员安全、耗材管理 | 详见 [[清洁机器人]] |
| 医院与实验室物流 | 药品、标本、耗材运输 | 院内流程、洁污分区、追溯、门禁和感染控制 | 涉及医疗用途时需单独判断医疗器械/医疗机器人边界 |
| 安防、巡检与搜救 | 巡逻、异常发现、远程观察 | 感知可靠性、通信中断、误报漏报、人工接管 | 安防用途还涉及隐私、数据和当地法规 |
| 教育、陪伴与辅助 | 教学互动、辅助任务、社会交互 | 儿童/脆弱人群保护、可解释交互、隐私 | 不能仅凭“陪伴”名称推断产品安全等级 |
| 农业、园区与专业作业 | 搬运、巡检、采摘或辅助作业 | 户外环境、地形、天气、作业工具和风险控制 | 按实际任务与应用标准分类 |

上述领域是应用地图，不是穷尽式分类。一个产品可能同时跨越多个场景；应按主要预期用途建立主归属，再用交叉链接表达其他能力。

## 2. 与移动机器人、工业机器人和医疗机器人的关系

- **与移动机器人：** 移动是运动能力，不是服务用途的同义词。移动服务机器人常复用底盘、定位、建图、路径规划和车队管理技术，但服务场景还要处理人机共处、交接、门禁、电梯、用户体验和现场运营。参见 [[移动机器人]]。
- **与工业机器人：** 相似的机械臂构型可能因用途不同而归入不同类别。用于生产线自动化的操作机与用于餐饮/接待等服务任务的操作机，不能只按机械结构分类。具体边界参照 ISO 8373 与适用的工业机器人标准。
- **与医疗机器人：** 医疗用途必须独立识别预期用途、医疗器械属性、临床/监管要求和专用标准。医院内运行或运送物品本身，并不自动使所有机器人都成为医疗机器人；反之，涉及诊断、治疗、手术或康复的功能也不能按普通楼宇配送机器人处理。参见 [[医疗机器人]]。
- **与远程操作设备：** IFR 的部分应用统计可能覆盖具有人工控制或有限自主性的机器人设备。工程文档应明确自主功能、人工控制链路、失联状态和操作者责任，不应将远程操作包装为自主能力。

## 3. 典型系统架构

服务机器人没有统一的软件栈。以下是常见能力分层，项目应按任务删减或扩展：

1. **机电与能源层**：底盘/机构、驱动器、制动、供电、电池、充电、碰撞防护和维护接口。
2. **感知层**：里程计、IMU、激光雷达、相机、深度传感器、触边/防撞、麦克风、扬声器及任务专用传感器。
3. **定位与运动层**：定位、地图管理、路径/轨迹规划、动态障碍处理、速度控制和安全相关保护功能。导航避障不能代替安全功能。
4. **任务与交互层**：任务状态机、用户请求、语音/触屏/灯光提示、物品交接、异常解释、人工接管。
5. **设施与业务集成层**：电梯、自动门、门禁、呼叫系统、订单/工单、楼宇管理或医院信息系统。协议、认证、责任边界和故障降级必须逐项目确认，不存在可默认套用的统一接口。
6. **云端与运维层**：设备注册、远程监控、地图/配置管理、日志、OTA、权限控制、网络安全和售后工单。远程控制应有身份认证、授权、审计和失联处理。

服务机器人与 AMR 的共用模块可复用，但用户交互、作业流程和设施接口必须围绕实际服务任务重新定义。

## 4. 人机共处与社交导航

服务机器人通常在人群、狭窄通道、前台、电梯厅或开放公共区域运行。社交导航不是给所有产品设定一个固定的人体间距，而是根据场景、速度、机器人外形、可预测性、人员密度、可见性、制动能力和风险评估确定行为约束。

设计与验证至少应覆盖：
- 人员横穿、迎面会车、跟随、超越、排队和群体聚集；
- 盲区、儿童、轮椅和行动不便人员；
- 狭窄通道、门口、电梯厅、坡道和地面变化；
- 让行、等待、绕行、停止、人工接管和恢复任务的策略；
- 机器人运动意图提示、声音/灯光告知和用户交互失败；
- 传感器遮挡、定位丢失、网络中断和制动异常等故障场景。

社会导航代价函数、人体检测距离或速度限制都不是通用安全阈值。安全相关速度、保护区、停止性能和人员接近策略必须由完整应用风险评估、适用标准及实测证据确定，不能从论文演示或其他厂商产品直接移植。

## 5. 关键性能与验收指标

不提供跨产品通用的“典型负载、速度、定位精度、续航或交互距离”。不同机器人在载荷定义、地面条件、地图、速度模式、电池容量、任务占空比和测试方法上差异很大。项目应把指标写成可复现的测试条件：

| 指标类别 | 建议定义方式 | 必须记录的条件 |
|---|---|---|
| 任务能力 | 单次任务成功率、任务完成时间、交接成功率 | 任务定义、起终点、负载、人工介入规则、样本量 |
| 运行效率 | 单位时间有效任务数、等待/空驶/充电占比 | 班次、任务分布、拥堵、设施等待和统计窗口 |
| 导航表现 | 路线完成、定位可用性、重规划与恢复表现 | 地图版本、环境、人流、地面、传感器配置 |
| 安全表现 | 危险场景覆盖、停止/保护功能测试、故障响应 | 风险分析、测试工况、测量设备和通过准则 |
| 可靠性与维护 | 可用率、故障间隔、维修时间、耗材寿命 | 运行小时、故障分类、维护策略和统计口径 |
| 人机交互 | 请求识别、对话任务完成、误触发/误响应 | 语言、噪声、用户群体、隐私设置和人工兜底 |
| 设施集成 | 电梯/门禁/呼叫链路成功率与故障恢复 | 设施型号、协议版本、网络拓扑、现场权限 |
| 能源 | 任务能耗、充电窗口、低电量策略 | 电池版本、负载、环境温度、任务谱和电池健康状态 |

验收应以用户需求和现场运行设计域（ODD）为基准，区分供应商标称值、实验室测试值、现场试运行值和长期运营数据。

## 6. 安全、隐私与法规边界

服务机器人不是单一标准覆盖的产品类别。标准选择取决于机器人类型、预期用途、运行环境、危险源和销售地区：

- ISO 8373:2021 用于术语和分类，不是产品安全认证标准。
- ISO 13482 涉及个人护理机器人安全；是否适用需核对其范围和具体产品形态，不能扩展为所有服务机器人的通用合规证明。
- ISO 3691-4:2023 针对无人驾驶工业车辆及其系统；只有产品和应用落入其范围时才考虑适用，不能将其直接套用于所有公共空间服务机器人。
- 工业机器人应用、医疗用途、道路/户外运行、无线电设备、EMC、电池、网络安全、隐私和数据保护可能分别触发其他标准或法规。

至少建立以下风险与合规检查：
- 机械碰撞、夹挤、倾覆、坠落、坡道失控和制动失效；
- 电池、充电、过温、短路、火灾和维护隔离；
- 人员检测失效、盲区、定位/地图错误和通信丢失；
- 儿童、老年人、残障人士等特定用户的可预见误用；
- 摄像头/麦克风采集、个人信息处理、数据留存、访问控制和网络攻击；
- 远程操作者权限、人工接管、故障告警和事件记录。

具体合规结论必须结合目标市场、产品预期用途和正式标准/法规文本，由具备相应能力的人员审核。知识库中的标准列表不构成认证或法律意见。

## 7. 选型与部署流程

1. **定义服务任务**：明确用户、场所、物品/服务对象、任务频次、服务时间、交接方式和人工介入边界。
2. **定义 ODD**：记录室内/室外、地面、坡度、门宽、电梯、网络、人流、照明、天气和禁行区域。
3. **确定产品类别与监管路径**：区分普通服务、消费、医疗、工业车辆、道路运行或其他受监管用途。
4. **建立需求与测试矩阵**：将任务成功、效率、安全、隐私、设施集成和维护需求映射到验证方法。
5. **评估系统接口**：现场确认电梯/门禁/网络/业务系统的接口所有者、协议、授权、失效模式和降级策略。
6. **开展现场试点**：先在受控区域验证安全链和异常处理，再逐步扩大 ODD；记录失败、人工接管和维护负担。
7. **评估运营经济性**：以真实任务量、人工流程、设施等待、维护、耗材、停机和部署成本建立全生命周期模型；不使用脱离现场数据的统一租金或回本周期。
8. **建立持续运维闭环**：管理软件/地图/配置版本、故障工单、备件、培训、网络安全更新和退役计划。
