# 编码器与里程计

> 编码器测电机轴转角 → 结合轮径/减速比推算位移与航向 → 轮式里程计（Odometry）。便宜、高频、短时可靠，但有**打滑系统性漂移**，必须靠其他传感器纠偏。

## 编码器类型

| 类型 | 原理 | 分辨率 | 适用 |
|---|---|---|---|
| 增量式光电 | 光栅脉冲 A/B 相（90° 相差判向）+ Z 相清零 | 500-4096 PPR/圈 | 轮电机主流、便宜 |
| 绝对式 | 磁/码盘唯一编码（SSI/BiSS-C/多圈） | 12-17bit 单圈 | 关节、伺服、断电不丢位 |
| 磁编码器 | 霍尔阵列+ASIC（AS5047/MT6835） | 14-21bit | 小型机器人、BLDC 内置 |
| 旋变（resolver） | 电磁耦合模拟信号 | 等效 16bit | 高振动/高温（车规、重型） |

## 里程计数学（差速底盘）

```
v_left, v_right = ω_wheel × r_wheel / i_gear
v = (v_left + v_right) / 2
ω = (v_right - v_left) / W_wheelbase    (W = 轮距)
x += v·cos(θ)·dt;  y += v·sin(θ)·dt;  θ += ω·dt
```

- 累积误差模型：平移 ~1-2% 行驶距离；航向 ~0.1-1°/min（打滑/轮径误差主导）
- 阿克曼底盘：由转向角 δ 推 v, ω：`ω = v·tan(δ)/L`（L 轴距）→ [[底盘与运动机构]]

## 系统性误差源（标定对象）

1. **轮径有效值**：负载压扁 ~1-3% → 需负载态标定
2. **轮距实际值**：加工装配误差 → UMBmark 双向方形标定法
3. **打滑**：加速/满载/水地面 → 无解，只能靠外部传感器融合
4. **编码器齿隙**：减速器回差 → 反向死区补偿

## 融合角色（→ [[多传感器融合定位]]）

- IMU+轮计：航向互补（短时 IMU 准，长时轮计稳）
- LiDAR/视觉 SLAM 输出位姿 vs 里程计位姿 → 漂移观测
- AMCL 粒子滤波的运动模型就用轮计噪声模型（odom frame → map frame）→ [[卡尔曼滤波]]

## ROS 中的表示（→ [[ROS与ROS2]]）

- `nav_msgs/Odometry`：pose(map↔odom)、twist（v, ω）
- TF 树：`map → odom → base_link → wheel`，odom 连续但漂移，map 无漂移但可能跳变
- `diff_drive_controller`（ros2_control）内置里程计积分

## 轮计数据三形态（V3 · 附件整合）

> 来源：用户附件 PDF（Google Search 会话，2026-11-01 导出）。编码器数据由 MCU 经 micro-ROS 或串口发布，工程上有**三种递进形态**：

| 形态 | 消息类型 | 内容 | 谁来换算 |
|---|---|---|---|
| ① 原始脉冲计数 | `std_msgs/Int32MultiArray`（自定义 `/wheel_ticks`） | `[左轮累计ticks, 右轮累计ticks]`（如 [125432, 125390]，自开机/复位累计，前进增后退减） | **ROS 端**：距离 = ticks ÷ (PPR×4倍频) × 减速比 × 2πr——需轮径 D/减速比/线数 N 三参数 |
| ② 关节转速 | `sensor_msgs/JointState` | name=[left/right_wheel_joint]、position（累计弧度）、velocity（rad/s） | MCU 做完脉冲→弧度；ROS 端再做运动学 |
| ③ 车体速度 | `geometry_msgs/TwistStamped`（或完整 `nav_msgs/Odometry`） | base_link 系下 linear.x（m/s）+ angular.z（rad/s） | **MCU 固件内置差速运动学**（→ [[10-代码实例-底盘串口桥]] 同思路） |

- **选型口诀**：MCU 算力富余→发③（ROS 端最省心）；要保留原始信息/换算参数常改→发①；要兼容 rviz/joint_state_publisher 生态→发②。micro-ROS 固件常选①以降低 MCU 负担。
- ROS 无官方 `WheelTicks` 消息——①必须自定义消息或借用 Int32MultiArray（契约管理 → [[构建与CI工具链]]）。
