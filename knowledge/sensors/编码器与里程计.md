# 编码器与里程计

> 编码器测量轴或关节运动；里程计使用编码器和运动学模型估计机器人运动。它是相对运动观测，不是无漂移的绝对定位。

## 先修知识与学习目标

先理解角度、角速度、轮径、减速比、采样周期、坐标系和基本差速运动学。完成本页后应能读懂编码器数据表、把脉冲换算成轴角/轮速、理解里程计误差并设计标定和测试。

## 1. 编码器类型

| 类型 | 输出/原理 | 常见用途 | 必须核对 |
| --- | --- | --- | --- |
| 增量式光电/磁式 | A/B 相正交脉冲；部分产品有 Z/index | 轮速、关节速度和相对位置 | PPR/CPR 定义、通道数、输出电平、最大频率、方向、Z 相和抗干扰 |
| 单圈绝对式 | 在一圈内输出绝对角度 | 关节和伺服位置反馈 | 有效位数、接口、精度、线性、启动行为和数据更新率 |
| 多圈绝对式 | 记录多圈转数和单圈位置 | 断电后仍需恢复轴位置的应用 | 多圈计数机制、备用供电/能量采集、圈数范围和掉电行为 |
| 磁编码器 | 磁场与芯片检测角度 | 小型电机和关节集成 | 磁体位置/偏心、气隙、外部磁场和标定 |
| 旋转变压器（Resolver） | 感应式模拟角度信号 | 高温、振动或特定伺服系统 | 激励/解调、线缆、转换器和温度/振动性能 |

编码器选型要和安装位置一起考虑：装在电机轴、减速器输出轴还是车轮轴，会影响齿隙、传动弹性和最终可观测量。

## 2. PPR、CPR 与计数倍率

编码器分辨率标注可能使用 PPR、CPR、线数、脉冲数或 counts/revolution 等词，厂商和控制器对这些词的定义并不总是相同。必须在准确数据表中确认：
- 标注是每转 A 相周期数、每转脉冲边沿数，还是已经经过正交解码后的计数；
- 控制器使用 x1、x2 还是 x4 正交计数；
- 是否计算 A/B 两路、是否使用 Z 相；
- 计数位置在电机轴还是输出轴；
- 齿轮比定义是电机转数/输出转数还是相反。

增量式编码器的角度换算可写为：

`Δθ_motor = 2π × Δcounts / counts_per_motor_revolution`

若编码器位于电机轴且传动比定义为 `i = motor_revolutions / wheel_revolution`，则轮角位移为：

`Δθ_wheel = Δθ_motor / i`

轮地无滑移时，轮周位移近似为：

`Δs = r_effective × Δθ_wheel`

其中有效滚动半径需在实际载荷和地面条件下标定。不要将标称轮径直接视为有效轮径。

## 3. 差速底盘里程计

令左右轮在同一时间窗内的轮周位移分别为 `Δs_L` 和 `Δs_R`，轮距为 `b`：

`Δs = (Δs_R + Δs_L) / 2`

`Δθ = (Δs_R - Δs_L) / b`

对较小时间步，可以使用中点积分近似更新平面位姿：

`x_{k+1} = x_k + Δs × cos(θ_k + Δθ/2)`

`y_{k+1} = y_k + Δs × sin(θ_k + Δθ/2)`

`θ_{k+1} = wrap(θ_k + Δθ)`

该模型假设轮地运动可由平面差速模型近似描述。打滑、轮胎变形、悬架/脚轮拖曳、坡面、地面不平和结构柔性都会使真实运动偏离模型。

阿克曼底盘、舵轮、麦克纳姆和足式机器人应分别建立相应运动学，不能复用差速公式。参见 [[底盘与运动机构]]。

## 4. 主要误差源与标定

| 误差源 | 影响 | 建议方法 |
| --- | --- | --- |
| 有效轮径/滚动半径差 | 直线距离和左右轮速不一致 | 在代表载荷、轮胎压力/磨损及地面条件下测量 |
| 轮距/几何参数 | 转向角速度和航向累计偏差 | 依据底盘几何和双向轨迹试验估计 |
| 编码器计数或倍率配置错误 | 速度/距离出现固定比例误差 | 用已知角度/转数测试计数换算 |
| 齿隙、联轴器松动和轴系弹性 | 反向时死区、迟滞和瞬态误差 | 测量双向响应，检查机械连接和减速器参数 |
| 轮地打滑 | 编码器显示轮转但底盘并未按比例移动 | 设计加减速、转弯、湿滑/低附着工况；用外部观测融合 |
| 时间戳/采样误差 | 速度估算抖动、融合错时 | 硬件计数、同步时间戳、周期抖动和丢样测试 |

UMBmark 等方法可作为差速移动机器人几何标定的学习入口，但不能代替针对具体底盘、载荷、轮胎和地面的验证。标定参数要与车辆配置、轮胎更换和机械变更版本绑定。

## 5. 传感器融合与 ROS 数据接口

- 轮编码器适合提供高速相对运动约束；IMU 可补充短时角运动/比力信息；LiDAR、视觉或 GNSS 等外部观测用于约束长期漂移。
- 轮速协方差应反映载荷、地面、加减速和转弯条件，不要对所有工况填同一过度乐观的噪声。
- ROS 常见的 nav_msgs/Odometry 表达位姿和速度；header.frame_id 通常表示位姿参考坐标系，child_frame_id 表示被描述的运动主体坐标系。
- 常见 TF 关系为 map → odom → base_link；odom 连续但可漂移，map 到 odom 的修正可能变化。具体发布责任和时间戳要遵循所用定位架构。
- JointState 适合发布关节位置/速度/力矩状态；自定义原始 tick 消息必须明确单位、符号、溢出、复位和传动参数版本。

## 6. 验证与量产交付

至少建立以下检查：
- 编码器每转计数、计数倍率、方向、零点和最大输入频率；
- 轮径/有效半径、减速比、轮距和轴系配置；
- 低速/高速、正反转、启停和长时间运行；
- 典型载荷、偏载、转弯、坡面和不同地面；
- 时间戳同步、丢样、计数溢出、断线和重新上电；
- 外部真值对比、误差统计和参数版本记录。

量产资料包括编码器完整型号/订货号、数据表、安装图、线束与接口定义、固件计数配置、标定记录、检验工装和换件后的重新标定要求。

## 厂商与资源

既有调研中的编码器厂商/模组入口尚未形成同一测试条件下的对比表。采购时应优先取得制造商原始数据表和接口手册；代理商/电商页面只作检索入口，不代替正式规格。
