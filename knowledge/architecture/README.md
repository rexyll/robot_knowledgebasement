# Architecture | 系统架构与流程

本目录组织机器人系统级架构、跨模块职责边界，以及从启动到运行、协同和运维的端到端流程。它描述系统如何组合和协作；不替代具体算法推导、部件选型、软件框架说明、风险评估或产品级验证。

## 1. 系统架构

- [[AMR整体架构]]：工业场景AMR的参考逻辑架构、子系统职责、数据流、故障域和验证清单。该文档是参考视图，不是所有机器人类型的通用架构。
- 本目录当前以AMR为主要系统样例；机械臂、人形、特种及其他移动机器人仍需建立各自的系统边界、部署和接口视图，不能直接套用AMR图。

## 2. 典型流程

- [[建图流程]]：环境数据采集、地图构建、质量检查、版本和发布。
- [[导航流程]]：任务目标、定位、规划、控制、执行反馈与异常恢复。
- [[多机调度流程]]：车队任务分配、交通协调、共享资源和设施联动。
- [[云端协同与OTA流程]]：设备身份、遥测、配置分发、升级审批、执行、回滚和审计。

流程页面描述的是逻辑过程；具体实现应由项目的接口控制文件、状态机、网络拓扑、权限模型和版本基线约束。不得将流程图视为已完成的产品实现或现场验收证据。

## 3. 相关知识域与边界

- **算法原理与实现：** [algorithms](../algorithms/)；定位、感知、规划等算法的数学模型和具体实现细节归算法章节。
- **软件框架与工程实现：** [software](../software/)；ROS 2、驱动、通信中间件、软件架构和工程工具归软件章节。
- **安全与风险控制：** [safety](../safety/)；安全功能、保护器件和风险评估归安全章节。普通任务流程、ROS节点或云端指令不构成独立安全功能。
- **系统需求与验证：** 需求、接口、架构权衡、配置管理和V模型验证归系统工程章节；本目录中的流程需追踪到具体需求和测试证据。

## 4. 阅读与维护规则

1. 先明确机器人类型、预期用途、运行设计域（ODD）和系统边界，再选择对应架构或流程；不要将AMR示例推广为行业统一方案。
2. 每个架构/流程专题应说明输入、输出、参与组件、状态转换、异常路径、接口契约、权限/安全边界及验证方法。
3. 对标准、协议、软件版本和性能数字记录来源、版本、适用条件和核验日期；没有项目依据的固定频率、时延、容量或安全阈值不得写成通用要求。
4. 区分参考设计、历史项目档案、仿真结果、台架结果和现场验收；页面存在或链接可达不代表内容已被产品验证。
5. 新增非AMR系统样例时，先建立该类型的主架构文档，再链接其专属流程；跨目录内容保留单一主归属，避免复制出相互冲突的规范。
