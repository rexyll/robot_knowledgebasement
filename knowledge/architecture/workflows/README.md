# Workflows | 系统流程

本目录收录机器人系统从部署、运行到车队协同和远程运维的流程视图。它回答“系统参与者按什么顺序协作、数据与控制如何流转、异常如何进入处理路径”，不替代算法原理、软件组件手册、产品接口契约、风险评估或项目验收报告。

## 流程专题

| 生命周期 | 专题 | 内容边界 |
| --- | --- | --- |
| 部署期 | [[建图流程]] | 场地勘测、地图采集/优化、语义配置、评审发布与地图维护 |
| 运行期 | [[导航流程]] | 任务目标、定位、规划、控制、到位判定、异常恢复 |
| 车队运行期 | [[多机调度流程]] | 任务分配、交通协调、共享资源、设施联动与车队反馈 |
| 运维期 | [[云端协同与OTA流程]] | 设备身份、遥测、远程诊断、配置/软件升级、回滚与审计 |
| 全生命周期安全约束 | [[功能安全体系]] | 风险评估、安全功能需求、实现/验证证据与残余风险；不是通用 PLr/SIL 配置表 |

跨专题总览与算法/软件映射见 [[流程架构地图]]。

## 阅读顺序与适用边界

1. 先确认机器人类型、预期用途、运行设计域（ODD）、现场设施和系统边界；当前流程专题以 AMR 场景为主，不可直接套用于机械臂、人形、无人机或特种机器人。
2. 对移动机器人项目，通常先阅读建图，再阅读导航；涉及多车时增加多机调度；需要远程管理和软件维护时再阅读云端协同与 OTA。功能安全应从需求和风险评估阶段贯穿全生命周期，而不是最后附加。
3. 将流程页作为工作分解和评审入口。具体消息字段、状态机、权限、网络拓扑、超时/重试、故障策略和版本兼容性，必须由目标项目的接口控制文件、设计基线及测试用例定义。
4. 算法原理归 `knowledge/algorithms/` 等算法专题；软件框架与通信实现归 `knowledge/software/`；安全风险与保护措施归 `knowledge/safety/`；需求追踪和系统验证归系统工程章节。此处只维护流程视图及跨域链接。
5. 本目录文件存在或流程图可读，不代表对应产品已实现、已通过仿真/HIL/实机测试、符合标准或获准量产。任何性能阈值、安全距离、制动参数和升级策略均须绑定具体产品、工况、版本和验证证据。

## 维护规则

- 新增流程专题前先检查是否已有唯一主归属，避免在流程页复制算法、驱动或标准正文。
- 每篇流程至少说明适用范围、输入/输出、参与角色/组件、主要状态与异常分支、接口依赖、安全边界和验证方法；不适用项应说明原因。
- 固定频率、时延、容量、速度、精度、重试次数和灰度比例不得作为行业通用值，除非有适用标准或明确项目证据。
- 更新流程时同步检查 [[流程架构地图]]、相关算法/软件/安全链接和项目实例名称；对尚未核验的流程正文保留待审状态。
