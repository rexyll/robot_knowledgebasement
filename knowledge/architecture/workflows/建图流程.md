# 建图流程（部署期）

> 本页描述以工业 AMR 为主的地图工程流程：把已勘察的运行场地转换为可供定位、导航、调度和运维使用的地图资产。它是部署作业框架，不是某个 SLAM 软件的通用参数手册；算法原理见 [[SLAM总览]]、[[激光SLAM]]。不同机器人类型、传感器组合、场地和运行设计域（ODD）必须重新定义流程与验收条件。

## 1. 先定义地图交付物与边界

建图前先明确地图将被哪些系统消费，以及需要交付哪些互相独立的资产。不要把“地图”默认等同于一张 PGM 图片。

| 交付物 | 典型内容 | 需要明确的接口/版本 |
| --- | --- | --- |
| 几何地图 | 2D OccupancyGrid、3D 点云/体素/表面模型，或项目采用的其他表示 | 坐标系、原点、分辨率/点密度、范围、未知区域语义 |
| 定位地图/数据 | SLAM pose graph、关键帧/子图、特征地图或定位专用数据 | 算法实现、序列化格式、软件版本、传感器配置和兼容性 |
| 语义与导航图层 | 路网、通行方向、区域、Keepout/限速掩码、停靠点、充电位、电梯/门等设施关系 | 图层坐标基准、对象 ID、规则版本、消费端解释 |
| 部署配置 | 机器人/传感器外参、地图与 TF 关系、定位初始位姿、区域/楼层绑定 | 机型、硬件修订、参数集、软件版本 |
| 发布包与证据 | 文件清单、校验摘要、变更记录、评审/测试记录、发布与回滚信息 | 唯一版本、来源、权限、完整性和兼容性策略 |

地图分辨率是表达粒度，不等于定位精度、障碍物检测精度或机器人可安全通过的最小间隙。Nav2 的 OccupancyGrid/Map Server 只定义特定二维地图消息和加载/保存接口；它们不替项目定义语义图层、地图质量或现场安全验收。

## 2. 工程流程

### 阶段 A：需求与场地勘察

- 明确机器人型号/构型、传感器、载荷、预期任务、ODD、运行时段、人员/车辆混行情况和场地责任方。
- 收集 CAD/BIM、建筑平面图、消防/疏散资料、楼层与坡道、电梯/自动门、充电区和设施接口信息；将图纸作为勘察输入，不默认视为现场竣工实测。
- 现场核对墙体、玻璃/镜面、金属反射、重复纹理、长走廊、动态人流、地面反光/坡度/接缝、临时堆放物及光照/粉尘等影响因素。
- 记录禁入区、坠落/台阶、电梯井口、交叉口、消防通道和其他危险区域；围栏/Keepout 配置须由风险评估与现场责任方确认，不能只靠地图标注承担安全功能。
- 形成勘察记录、地图范围、采集路线草案、设施依赖、风险清单和待现场确认项。

### 阶段 B：设备与数据就绪

- 核对 LiDAR/相机/IMU/编码器型号、固件、视场、量程、安装姿态、遮挡、外参、时间戳和驱动版本；检查安装刚度、振动与线缆。
- 核对传感器数据、里程计和 TF 时间一致性，检查丢帧、时间跳变、坐标系命名、外参方向及数据质量。需要时先完成传感器标定和时间同步验证。
- 明确建图模式、定位模式及数据记录格式。2D 激光 SLAM、3D LiDAR/LIO、视觉/多传感器 SLAM 的输入、运动约束、回环能力和输出地图不同，不可只凭“2D/3D”标签替换算法。
- 确认采集控制方式与现场安全措施。遥控速度、加速度、路线、人员隔离和急停安排按机器人限制、扫描频率/视场、环境及风险评估确定；本页不规定统一速度上限。

### 阶段 C：数据采集与建图

- 依据场地结构设计覆盖路线，保证关键区域、连接通道、转弯、门区和跨区域连接得到足够观测；采集路线应兼顾传感器视场、运动激励、遮挡和回访可行性。
- 在合适位置形成可识别的重叠观测和回访机会。回环间距取决于环境可辨识度、轨迹漂移、传感器、速度、视场和算法配置；“每隔固定米数回访”不是通用规则。
- 对长走廊、重复货架、玻璃/镜面、大面积空旷区和动态人流等退化场景，单独记录数据与处理策略；必要时改变路线、增加辅助特征/反光标志、使用其他传感器或分区采集。
- 多楼层/多区域项目需定义楼层/区域坐标关系、连接设施及切换条件。不同机器人独立采集的地图不可仅凭“同一起点/相似路线”认定天然对齐。
- 保存原始传感器数据、时间戳、TF/里程计、参数快照、机器人配置、采集路线和异常日志，确保离线复查可复现。

### 阶段 D：优化、地图清理与几何评审

- 检查轨迹连续性、扫描匹配质量、回环约束、位姿图优化前后变化、局部重影/墙体弯曲、地图断裂和未观测区域。优化残差必须结合观测模型、权重、异常值处理和独立测量解释，不能把某个单一残差阈值作为普遍合格线。
- 只清理有证据确认的动态物体伪影；不要把真实固定设施、临时但长期存在的障碍或安全相关边界误删。
- 使用独立测量控制点、测距/全站仪/经核验的 CAD 基准等检查地图几何。明确坐标基准、测量不确定度、控制点分布、对齐方法和误差统计；CAD 图纸本身未必是现场真值。
- 地图尺度、平移/旋转、局部几何和闭环一致性应分别评价。单一“尺度误差百分比”或“回环残差厘米数”不能代表整体地图质量。
- 对 3D 地图检查点云密度、动态点、遮挡、地面/墙面结构和下游投影/切片方法；3D 点云不会自动成为导航可用的 2D 栅格地图。

### 阶段 E：语义、路网与设施配置

- 将几何地图与语义图层分开管理。按导航/调度系统的数据模型配置路网节点/边、方向、通行规则、区域、速度限制、Keepout、停靠点、充电对接位和设施接口。
- 门、电梯、升降机、自动充电、消防门等设施的状态与控制接口由设施集成规范定义；地图只表达空间/语义关系，不能替代联锁、权限和安全控制。
- 限速值、通行方向、会车/超车区和禁行区域应基于车辆能力、交通组织、风险评估和现场验证确定，不能从通用地图模板复制。
- 对每个语义对象定义稳定 ID、坐标系、有效范围、创建/修改责任人和版本兼容规则，避免地图升级后任务点或设施绑定静默漂移。

### 阶段 F：验证、发布与回滚

- 分层验证：地图文件/元数据检查 → 几何控制点复核 → 定位覆盖与重定位测试 → 导航/点位任务测试 → 设施与多机集成测试（如适用）→ 现场运行验收。
- 测试路线、速度、载荷、环境、人流、照明、传感器配置、机器人版本、软件参数和重复次数均需记录。报告分布、失败案例、置信区间/测量不确定度和限制条件，不只报告平均值或“成功率”。
- 定位成功率、点位到达误差、地图尺度/局部几何误差、地图覆盖率、任务超时、死锁和运行时长属于不同测试对象。多机死锁/满编队压力是车队系统验证，不是单独的建图地图验收指标；对接毫米级精度也应作为独立工艺/机械/控制测试。
- 发布地图包时包含文件清单、SHA-256 摘要、坐标/分辨率/原点元数据、机器人与传感器兼容矩阵、SLAM/地图工具版本、参数快照、变更记录、评审签署和测试证据。摘要用于检测内容变化，不等于发布者身份认证；需要可信分发时还需访问控制、签名/验证和密钥管理。
- 保留已发布版本及回滚方案；回滚必须同时检查地图、语义图层、定位参数、任务点和设施配置的版本兼容，不能只回滚一张图像。

## 3. 两种部署方式与混合方式

| 方式 | 说明 | 适用性与风险 |
| --- | --- | --- |
| 工程建图 | 使用目标机器人/传感器采集数据，工程师处理地图与语义配置 | 适合需要现场验证和交付证据的项目；工时取决于面积、楼层、障碍/动态程度、设施集成和验收范围 |
| 自主建图/免部署 | 机器人自主探索、扫描设备或其他数据源生成初始地图 | 适合产品已实现相应能力且运行环境受控的场景；仍需人工检查几何、语义、危险区和可导航性 |
| 混合建图 | 使用 CAD/BIM/既有地图生成初始底图，再用现场数据校准与补充 | 适合有可靠先验资料的场景；必须处理图纸版本、坐标基准、竣工偏差和现场变化 |

原稿中的“0.5–1 天场勘”“0.5 天采集”“2–5 天工程交付”“1000 m² 用时”等工时均缺少项目样本、人员配置和交付范围，已不作为行业基准。项目估时应按场地分区、数据采集、地图优化、语义配置、设施联调、复测和验收工作量拆分。

## 4. 地图运维

- **环境变化**：货架、隔断、设备或通道变化时，评估局部更新、重新采集或全量重建；不能假定持续建图算法会自动正确吸收所有变化。
- **动态物体与地图污染**：区分短时动态障碍、固定设施变化和定位异常；清理前保留原始数据及变更理由。
- **多机器人一致性**：统一地图坐标基准和发布源；多机器人地图合并/对齐须验证外参、时间、观测重叠和误差，不能只依赖云端单源分发。
- **版本管理**：地图、语义图层、定位参数、导航配置及设施映射采用可追踪的兼容版本；变更应有审批、灰度/回滚策略和现场复验。
- **持续监测**：记录定位丢失、重定位、地图匹配质量、局部规划异常和地图变更请求，按产品定义的阈值触发复核；不把单一协方差值作为地图健康的充分证据。

## 5. 关键验收维度（阈值由项目定义）

| 维度 | 建议定义/方法 | 不应混淆 |
| --- | --- | --- |
| 几何一致性 | 独立控制点、已知尺寸、闭环区域的平移/旋转/局部形变误差 | 地图像素分辨率、单次优化残差 |
| 地图覆盖与完整性 | 必需区域覆盖、未知区、遮挡、地图边界及关键通道可观测性 | 图像看起来连续 |
| 定位性能 | 在指定地图、路线、速度、环境和初始位姿条件下统计丢失/重定位、误差和恢复时间 | 建图算法离线优化成功 |
| 导航可用性 | 指定机器人包络、足迹、载荷和场景下的路线通过、到位及失败原因 | 地图几何误差 |
| 语义/设施正确性 | 路网方向、区域规则、点位、楼层切换、门/电梯/充电设施映射逐项核对 | 只检查地图图像 |
| 多机/运营能力 | 多机交通、共享资源、死锁恢复和任务完成率按车队系统测试计划验证 | 单机建图质量 |
| 发布完整性 | 文件摘要、版本、签名/权限、兼容矩阵、评审与回滚演练 | 只有 SHA 文件或版本号 |

验收阈值必须在测试前依据产品需求、风险评估、传感器/底盘能力、现场测量不确定度和合同约定确定，并注明测试方法、样本量、环境与软件/硬件版本。不得将原稿中的 <2%、2D <5cm、>99% @24h、±5–10cm、对接位 ±5mm 或“满编队 2h 死锁=0”直接当作行业标准。

## 6. 算法与实现注意事项

- [[激光SLAM]] 中的 slam_toolbox 相关功能以实际锁定分支/发行版为准。上游 ROS 2 文档描述其支持 2D pose-graph SLAM、序列化/反序列化、持续建图及基于 pose graph 的定位模式；具体插件、参数、文件兼容和部署能力仍需在目标版本复核。
- Nav2 Map Server/Map Saver 处理 OccupancyGrid 地图加载与保存。保存阈值、地图元数据和下游 costmap/过滤器配置应按目标发行版文档与项目参数核验。
- 3D LIO/SLAM 需要单独设计点云地图管理、动态点处理、地图配准、投影或体素化，以及导航消费接口。
- 手动添加/修改回环约束属于工程干预，必须保留原始数据、操作记录和优化前后对比，并安排独立复核，不能把手工“调直”当作几何真值。

## 8. 来源与版本边界

- [slam_toolbox ROS 2 官方仓库](https://github.com/SteveMacenski/slam_toolbox)：功能、pose graph、序列化与定位模式；仓库 README 的能力描述不等于目标机器人上的性能保证。
- [Nav2 Jazzy Map Saver](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/map_server/configuring_map_saver/)：地图保存服务及占据/空闲阈值参数。
- [Nav2 Jazzy Map Server](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/map_server/configuring_map_server/)：地图加载、地图 Topic 与 frame_id 配置。
- [ROS 2 nav_msgs](https://docs.ros.org/en/ros2_packages/humble/api/nav_msgs/index.html)：OccupancyGrid 与 MapMetaData 接口概念；使用时需匹配目标 ROS 发行版。
- [slam_toolbox mapper_params_online_async.yaml](https://github.com/SteveMacenski/slam_toolbox/blob/ros2/config/mapper_params_online_async.yaml)：仓库示例参数仅为特定配置样例，不能推广为通用推荐值。

本页未执行目标 SLAM 软件构建、数据集回放、机器人实机建图、定位/导航测试、地图发布签名验证或现场安全验收。
