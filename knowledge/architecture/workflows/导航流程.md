# 导航流程（运行期）

> 本页以工业 AMR 为主要示例，描述从任务接收到导航结果与异常闭环的系统流程。它不是通用机器人导航规范，也不是 Nav2 参数手册。执行前必须明确机器人构型、运行设计域（ODD）、载荷、环境、人员交互、设施依赖和安全架构。地图资产见 [[建图流程]]；算法原理分别见 [[多传感器融合定位]]、[[路径规划算法]]、[[局部规划与避障]]。

## 1. 导航系统边界与输入输出

导航是由多个有明确接口的能力协作完成的系统，不应简化成“全局规划器 + 局部规划器”。典型输入包括：

- 任务目标：目标位姿/路点、任务 ID、优先级、截止条件、允许区域及业务约束。
- 地图与语义：几何地图、路网/区域规则、Keepout/限速图层、设施与点位版本。
- 状态估计：位姿、速度、协方差或质量状态、里程计、时间戳、坐标系和定位有效性。
- 环境信息：传感器观测、动态障碍物、代价地图及其数据新鲜度。
- 机器人约束：足迹/外形、运动学、制动能力、载荷、速度/加速度限制和执行器状态。
- 安全与运营许可：独立安全系统状态、运行模式、区域授权、门/电梯/充电设施可用性。

典型输出包括路径/路由、速度或控制请求、导航状态、到位判定、失败原因、诊断数据及供任务系统消费的结果。输出必须带有明确的时间、坐标、版本和任务关联；“导航成功”不等于业务动作完成或安全功能已满足。

## 2. 运行时序与异常分支

1. **任务接收与仲裁**：验证任务身份、权限、有效期、目标点/路网版本、机器人模式和任务状态；由任务/车队系统解决资源预约、优先级与冲突。重复命令需具备幂等或去重策略。
2. **前置条件检查**：检查定位质量、地图与语义版本、传感器健康、制动/驱动状态、载荷、能源余量、区域/设施可用性及安全系统许可。阈值由产品需求、风险评估和测试确定。
3. **定位初始化与持续监测**：确认定位来源、坐标系、时间戳、协方差/质量状态及数据新鲜度。定位无效或跳变时，不得继续使用过期位姿盲目规划；应按产品风险策略暂停、受控停止、重新定位或请求人工处理。
4. **路由/全局规划**：根据地图表示、机器人运动学、足迹、代价地图、区域规则和任务约束生成路线/路径。大型场地可采用路网路由与局部自由空间规划组合；算法和插件应按机器人类型、场景与版本选型。
5. **路径可行性与局部控制**：检查路径有效性和环境变化，由控制器按当前状态与约束生成控制请求；速度、加速度、转向和控制周期须由底盘能力、制动性能、采样/执行时延与现场测试确定。
6. **动态障碍与路径更新**：感知/代价地图更新后，系统可等待、限速、绕行或重新规划。应区分短时阻塞、永久封路、传感器失效和地图错误；重规划触发条件与频率由场景、算力和安全分析定义，不设置跨项目固定值。
7. **到位与业务交接**：目标检查器根据位置、朝向、速度、稳定时间、目标类型和测量误差判定到位。普通导航到点、货架/充电对接和工艺定位是不同任务，应分别定义容差、感知基准、机械接口与验收方法。到位后由业务状态机执行顶升、取放、开门、充电等动作，并确认动作结果。
8. **结果上报与任务结束**：关联任务 ID、地图/配置版本、完成状态、异常码和必要证据；任务系统确认后再推进后续任务。通信中断时按命令有效期、任务阶段和风险策略处理，恢复后进行状态对账，不能重复执行非幂等动作。
9. **异常恢复与升级**：对规划失败、控制器无效输出、定位丢失、进展停滞、障碍持续阻塞、TF/传感器数据过期、设施超时和通信中断分别定义检测、有限恢复、重试上限、停止条件与人工升级。旋转、倒车、清空代价地图等恢复动作必须先检查空间、人员和安全许可，不能作为无条件默认动作。

## 3. 组件职责与接口

| 组件/能力 | 主要职责 | 关键接口与边界 |
|---|---|---|
| 任务/车队管理 | 任务分配、优先级、资源预约、任务取消/抢占 | 负责运营级冲突协调，不替代车端实时避障或安全控制 |
| 定位与状态估计 | 提供位姿、速度、质量状态和坐标变换 | 必须声明参考系、时间戳、有效性和失效行为 |
| 地图/路由服务 | 提供几何地图、路网和语义约束 | 地图、路网、点位与设施映射需版本兼容 |
| 感知与代价地图 | 汇总静态/动态障碍和可通行性 | 数据源、更新周期、过期检测和未知区域策略需明确 |
| 全局规划器 | 计算从起点到目标的路线/路径 | 处理运动学、足迹、代价、区域和规划失败状态 |
| 局部控制器 | 将路径和实时状态转换为控制请求 | 输出约束、时限、无效输出处理与底盘接口需定义 |
| 行为/任务编排 | 管理导航阶段、条件分支、恢复和取消 | 行为树/状态机只是编排机制，不自动提供安全保证 |
| 安全相关控制系统 | 根据风险评估执行保护、停止和重新启动条件 | 独立于普通导航软件的安全职责、接口和验证必须明确 |
| 诊断与记录 | 记录状态、时延、故障、配置和任务结果 | 日志可追溯且有时间同步、权限和数据保留策略 |

## 4. 坐标系、时间与状态一致性

移动机器人常见坐标关系为：

`map → odom → base_link → sensor frames`

- `map` 通常作为全局参考，定位修正可能导致相对 `odom` 的变换变化。
- `odom` 应提供连续的局部运动参考，但会随时间漂移，不能当作长期无漂移的全局真值。
- `base_link` 固连于机器人本体；传感器坐标系通过经标定的静态或可变外参连接。
- 典型移动平台由里程计来源发布 `odom → base_link`，定位组件结合该变换发布 `map → odom`。实际系统必须避免多个节点同时争用同一变换的发布权。
- 所有消息与变换需明确时钟域、时间戳来源、缓存范围和超时策略。仿真时间与真实时间不能混用；TF 查询失败、外推异常或数据过期必须成为可观测故障，而不是简单放宽容差掩盖问题。

上述约定参考 REP 105。机械臂、无人机、多楼层或多机器人系统可能需要不同/扩展的坐标树，不应直接照搬单车 AMR 配置。

## 5. 速度、避障与安全边界

不得将固定速度表、距离阈值或控制频率作为行业通用 SOP。运行限制应由以下因素共同确定：

- 机器人质量、载荷、质心、轮胎/地面附着、坡度、制动器和驱动器能力；
- 感知视场、检测距离、目标速度、盲区、遮挡、误检/漏检与数据时延；
- 控制/通信端到端时延、执行器响应、定位误差和足迹膨胀；
- 人员暴露、交叉口、窄道、门/电梯、货架和其他现场风险；
- 适用标准、风险评估、保护装置配置及现场验证结果。

普通局部规划器、代价地图、行为树或碰撞监视软件不能自动等同于经过验证的安全功能。保护区、急停、STO、制动与安全相关速度监控的实现和验证应归入 [[功能安全体系]]、[[安全防护器件]]，并按产品风险评估确定。导航软件不得绕过或屏蔽安全装置；软件发出零速度命令也不能单独证明机器人已安全停止。

## 6. 导航验证与指标定义

测试前应将需求转化为可重复的测试用例，并记录机器人型号/硬件版本、软件与地图版本、载荷、速度配置、场地、照明/人流、传感器、网络、测试路线、样本量和失败处理。至少区分：

| 维度 | 建议测量内容 | 不可替代的证据 |
|---|---|---|
| 定位质量 | 绝对/相对位姿误差、漂移、丢失与重定位时间 | 单次轨迹或算法内部协方差 |
| 路径规划 | 可行率、规划时延、路径代价、规则约束满足情况 | 仅展示一条成功路径 |
| 路径跟踪 | 横向/航向误差、速度跟踪、振荡和超调 | 控制器设定频率或仿真截图 |
| 动态避障 | 检测覆盖、误检/漏检、最小间距、停止/绕行行为及边界工况 | 仅统计平均任务成功率 |
| 到位/对接 | 位置/角度/速度容差、稳定时间、重复性和工艺接口 | 将普通导航到点误差等同于毫米级对接精度 |
| 任务可靠性 | 成功率、超时、取消、恢复次数、人工介入和故障分布 | 不说明任务定义/样本量的百分比 |
| 系统实时性 | 端到端时延、抖动、丢帧、过期数据和CPU/GPU负载 | 单一节点频率或平均值 |
| 安全验证 | 安全功能响应、停止距离/时间、保护装置和故障反应 | 普通导航日志或软件零速度输出 |

验收阈值应在测试前由产品需求、风险评估、合同和测量不确定度确定。不得将旧稿中的 20 Hz、50 cm 偏航阈值、5–30 s 重规划周期、±5–10 cm 到位精度、±5 mm 对接精度、50 m/45 s、>99.5% 成功率或速度利用率 ≥70% 作为通用标准。

## 7. Nav2 参考实现边界

Nav2 Jazzy 文档展示了可组合的导航服务器与插件，包括 Planner、Controller、Behavior、Smoother、Route、Costmap、Lifecycle Manager、Collision Monitor、AMCL 和 Docking 等。其职责应按锁定发行版和具体配置核对：

- Behavior Tree Navigator 负责导航任务编排；示例行为树不是产品完整策略，恢复、重试、门/电梯、充电和业务动作需要按应用设计。
- Planner Server 提供全局规划插件接口；Controller Server 管理控制器插件并生成速度请求。Nav2 文档中的默认控制频率只是特定配置默认值，不是行业建议或产品验收值。
- Costmap 及其层/过滤器表达规划使用的环境信息；地图数据过期、传感器失效和未知空间策略仍由系统设计决定。
- Collision Monitor 可作为导航链路中的碰撞监测组件，但不能仅凭启用该节点就宣称达到功能安全等级或满足保护距离。
- Lifecycle Manager 管理节点配置/激活/关闭，不等于整机安全状态机。
- 路网规划、Docking、Waypoint Follower 等功能需核对目标发行版、插件、接口和产品集成方式。

Nav2 是参考软件框架，不等于所有机器人都应使用 ROS 2/Nav2，也不代表采用其默认参数即可达到现场性能或安全要求。
