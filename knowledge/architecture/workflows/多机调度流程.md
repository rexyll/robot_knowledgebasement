# 多机调度流程

> 从"一张订单"到"N 台机器人各司其职"的全流程。系统组件见 [[调度系统RMS]]，算法见 [[多机协同与调度算法]]，本页串业务时序。

## 全流程时序

```
1. 任务进入
   WMS/WES/业务系统 → RMS (REST/MQTT): 出入库单/搬运单/清扫工单
   任务结构: 起点区+终点区+优先级+截止时间+货物类型+载荷匹配要求

2. 任务预处理
   ├─ 拆解: 大任务→子任务链(取货→搬运→放货), 建依赖图(DAG)
   ├─ 校验: 点位有效/区域开放/电梯可用
   └─ 入池: 优先级队列(急件插队, 老化加权防饿死)

3. 分配周期(1-5s)
   ├─ 候选集: 空闲/即将空闲车(当前任务 60s 内完成为预测空闲)
   ├─ 打分: 行驶时间+电量+返程顺路+载荷匹配 → [[多机协同与调度算法]]
   ├─ 批量匹配: 匈牙利/贪心
   └─ 下发: VDA5050 order 或私有 cmd → [[调度系统RMS]]

4. 路径资源预约
   路网段锁申请 → 冲突则等待/绕行 → 死锁检测(申请环) → [[多机协同与调度算法]]

5. 执行监控
   ├─ 车端状态回报 1-2Hz(state 消息): 位置/电量/动作/错误
   ├─ 异常处理: 车故障→任务回收重派; 超时→告警; 电量不足→中途换车(交接点)
   └─ 优先级仲裁: 急件抢占(在途任务挂起回池)

6. 完成与结算
   动作确认(顶升/货叉/拍照留证) → 任务关闭 → WMS 回执 → KPI 累计

7. 充电与待命(穿插)
   机会充电窗口 / 低电强制回充 / 待命点均衡分布(避免扎堆热点)
   → [[充电桩与自动充电]]
```

## 多楼层/跨楼场景增量流程

```
楼层图×N + 电梯对接:
1. 到电梯厅点位 → 调用电梯 API(IoT 盒子: 选层/开门)
2. 确认电梯到达+门开(光幕安全) → 进梯 → 车内定位(计程/惯性/梯内标识)
3. 到目标层 → 出梯确认(离梯点位+方向校验) → 切换地图与路网
风险点: 电梯超时/门被人为挡住/梯内定位漂移 → 超时重试+告警人工
```

## 异常处理矩阵

| 异常 | 检测 | 处置 |
|---|---|---|
| 车辆故障 | 心跳丢失/错误码 | 任务重派、车标记隔离、维保工单 |
| 任务超时 | 预计完成时间模型 | 告警→重派或降级 |
| 交通死锁 | 申请链环检测 | 强制解锁+重排+事后复盘规则 |
| 拥堵 | 区域车辆密度 | 入口限流(闸机式调度) |
| 电梯故障 | 对接超时 | 楼层任务暂停+人工通知 |
| 云网中断 | 心跳超时 | 车端自治(完成当前任务→待命)，恢复后状态对账 |

## KPI 闭环（→ [[性能指标体系]]）

- 实时看板：车队在线率、任务队列深度、各区域拥堵热力、充电桩占用
- 日报：吞吐量、P95 任务时间、故障 Top5、死锁复盘
- 调优回路：历史轨迹回放 → 仿真重跑新策略 → A/B 上线（→ [[仿真平台]]）

## 细节加深（V2）
- **调度参数三阈值**（上线必配）：等待超时（任务 P95×2）、拥堵密度（区域车数/m²）、电量阈值（下一任务能耗×1.5 与 20% 取大）——三个数出问题就是现场三类事故。
- **灰度扩容法**：3 台跑一周 → 5 台 → 10 台；每级记录拥堵热力图——直接上满编队等于把所有调度 bug 放大器一起打开。
