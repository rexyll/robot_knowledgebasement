# 路径规划算法（全局路径与运动规划）

> 路径规划根据环境模型、起点/目标、机器人形状和运动约束，寻找满足碰撞与任务约束的几何路径或状态序列。**几何路径（path）不等于带时间参数的轨迹（trajectory）**；路径规划也不必然要求先有完整静态地图。图搜索、采样、运动原语、优化和覆盖规划解决的问题不同，不能只凭“路径更短”判断算法优劣。

## 1. 规划问题先定义什么

规划前至少明确：

1. **状态空间**：二维位置 (x,y)、平面位姿 (x,y,theta)、三维位姿、机械臂关节空间，或包含速度/时间的更高维状态。
2. **环境表示**：占据栅格、代价地图、几何障碍、点云/体素、可通行区域、拓扑路网，或随时间变化的预测障碍。
3. **机器人模型**：圆形/多边形足迹、非完整约束、最小转弯半径、最大曲率、倒车能力、关节限位和碰撞模型。
4. **目标与代价**：可行性、距离、时间、能耗、转向、倒车、风险/间隙、舒适度或任务收益；代价权重必须说明单位和归一化方法。
5. **约束及不确定性**：硬碰撞约束、未知空间、定位误差、地图误差、动态障碍和规划超时行为。
6. **输出接口**：几何路径、状态序列、可行运动原语、速度剖面或完整时间参数化轨迹。

常见层次：
- **全局路径规划**：在地图/路网中寻找跨较长距离的路线，通常不负责逐周期生成电机命令。
- **局部规划/控制**：在当前观测和有限预测窗口内跟踪路线并处理动态障碍，见 [[局部规划与避障]]。
- **轨迹生成/时间参数化**：为路径分配速度、加速度、曲率与时间，见 [[轨迹优化与运动控制]]。
- **覆盖路径规划**：要求区域被工具/传感器工作范围覆盖，不只是从起点到终点，见本页第 5 节。

## 2. 图搜索与栅格规划

| 算法 | 基本方法 | 最优性/适用前提 | 常见限制 |
|---|---|---|---|
| BFS | 按层扩展无权图 | 边代价一致时可找到边数最少的路径 | 不适合直接处理非均匀代价 |
| DFS | 深度优先遍历 | 用于可达性/结构遍历；一般不保证最短路径 | 结果受邻接顺序影响 |
| Dijkstra | 从起点按累计代价扩展 | 非负边权下求图上的最短路径 | 对大量无关节点也可能扩展；不能替代运动学可行性检查 |
| A* | 使用 f(n)=g(n)+h(n) 引导搜索 | 在相应图搜索条件下，启发函数可采纳且算法正确处理已访问节点/重复节点时可保证图上的最优解 | 性能依赖图、代价、启发函数与重复访问策略；最优的是所定义离散图上的路径 |
| Weighted A* | 将启发项加权以偏向目标方向 | 在特定实现/假设下可得到有界次优结果；界和实际效果依赖算法版本与启发条件 | 不能把某个权重写成通用工程默认，也不能笼统承诺“只损失少量最优性” |
| D* / D* Lite | 复用先前搜索信息，在边代价变化后增量修复路径 | 适合图结构相对稳定、局部边代价不断变化且需要重复重规划的任务 | 不自动预测动态障碍；仍需更新地图/代价、设置触发与超时行为 |
| Theta* | 在栅格搜索中利用视线可达父节点产生 any-angle 路径 | 可减少栅格方向约束；结果与可视线检测、栅格碰撞模型相关 | 不等于连续空间的全局最短路径；需对线段与机器人足迹进行碰撞验证 |
| Jump Point Search（JPS） | 在特定规则网格上跳过对称路径扩展 | 对满足其假设的均匀代价规则栅格可减少搜索节点 | 依赖网格邻接、代价均匀性和切角/障碍规则；不应直接用于任意加权代价地图 |

### 2.1 A* 的启发函数与“最优”边界

- g(n)：从起点到节点 n 的已知累计代价。
- h(n)：从 n 到目标的估计剩余代价。
- f(n)=g(n)+h(n)：用于决定扩展优先级的估价。

若 h(n) 不高估从 n 到目标的真实最小代价（可采纳），并且搜索实现正确处理重复节点/重新打开节点等条件，A* 可以保证在所定义离散图上找到最优路径。若启发函数一致，许多图搜索实现可避免重新打开已关闭节点。启发函数还必须与边代价量纲和下界相容。

**不要把“欧氏距离/曼哈顿距离一定可采纳”当成脱离代价模型的事实。** 如果路径代价还包含转向、风险或其他附加项，需证明所选启发仍是总代价的下界；如果存在代价折扣或非标准转移，也需要重新检查。

Weighted A*、启发函数权重和搜索终止条件会影响路径代价与求解时间。任何次优界都应写清算法版本、权重定义和理论条件；工程参数要通过目标地图和机器人基准集测试，而不是采用固定的 epsilon=1.5。

### 2.2 复杂度的表达边界

对含 V 个节点、E 条边的无权图，BFS/DFS 的遍历复杂度通常写作 O(V+E)。使用二叉堆优先队列的 Dijkstra 常见上界表达为 O((V+E) log V)，但实际实现、图结构、权重范围和数据结构会影响精确复杂度。A* 的运行时间依赖启发函数与搜索空间；不能用“通常快 10–100 倍”作为算法复杂度或产品性能结论。

## 3. 采样规划与运动学约束规划

| 算法/框架 | 核心思路 | 适用特点 | 重要边界 |
|---|---|---|---|
| PRM | 在自由状态空间采样，建立可连接的路图，再查询图路径 | 固定环境中多次起终点查询、复杂高维状态空间 | 采样密度、近邻策略、碰撞检测与路图构建成本决定效果 |
| RRT / RRT-Connect | 从起点树或双向树随机扩展，逐步探索状态空间 | 高维/复杂约束空间寻找可行路径 | 标准 RRT 找到可行路径不等于最短/最平滑；结果受采样、距离度量、扩展步长和碰撞检查影响 |
| RRT* / Informed RRT* | 在 RRT 基础上重连以改进路径代价；Informed 变体限制后续采样区域 | 在其假设和采样/连接条件成立时具有渐近最优性质 | 渐近最优不等于有限时间内达到最优；真实机器人仍需轨迹平滑、动力学验证和时间参数化 |
| Hybrid A* | 在含朝向的状态空间搜索运动原语，并按运动模型检查碰撞 | 汽车式/阿克曼等存在转弯半径、不能原地旋转的移动平台 | 结果依赖运动模型、离散化、控制集、碰撞检查与解析扩展设置 |
| State Lattice | 预定义满足模型约束的状态/控制原语，形成可搜索状态格 | 非圆形足迹、倒车、特定差速/全向/阿克曼/足式等运动约束 | 需要设计和验证控制原语覆盖性、分辨率与碰撞检测；“支持任意运动学”仍需自定义模型/控制集 |

### 3.1 OMPL 的定位

Open Motion Planning Library（OMPL）是采样式运动规划算法库，包含 PRM、RRT、RRT*、KPIECE 等多种规划器和 SE(2)、SE(3)、欧氏空间等状态空间。OMPL 本身不替项目决定机器人几何、状态边界、碰撞场景、有效状态检查器、运动验证器或优化目标；这些要由应用集成层提供。

OMPL 常用于机械臂/高维运动规划，也可用于移动机器人状态空间研究。它不是“40 多个算法一个库就通吃”的现成产品配置；规划器选择和碰撞检测接口必须在目标机器人/环境上配置和验证。当前官方文档列出的版本与安装/依赖要求需随部署 tag 或 commit 锁定。

## 4. Nav2 全局规划接口与 Smac

Nav2 的 Planner Server 通过规划 action 接受起点/目标和 planner ID，规划插件返回 nav_msgs/Path。Behavior Tree 可以调用 ComputePathToPose 等 action 节点。该 Path 通常是一列带坐标系/时间戳的位姿，不包含完整速度剖面或执行器时序；下游控制器仍需做跟踪、速度约束和必要的轨迹处理。

Nav2 Smac Planner 官方文档列出三种基于 A* 的规划插件：

| 插件 | 状态空间/规划方法 | 官方文档描述的主要适用平台 |
|---|---|---|
| Smac 2D | 栅格 A*，可代价感知 | 圆形差速/全向机器人 |
| Smac Hybrid-A* | SE(2) 状态，使用 Dubins 或 Reeds-Shepp 等运动模型 | 阿克曼/类汽车、腿式等运动学受限平台 |
| Smac State Lattice | 使用配置的状态格与运动原语 | 非圆形或具有特定运动学约束的差速、全向、阿克曼、腿式及自定义平台 |

这些是 Nav2 具体版本中的插件能力，不代表其他规划框架也采用同样接口。不同 Nav2 发行版和 Rolling 文档可能存在插件、参数和行为差异；部署时需按目标发行版确认。

### 4.1 路径与轨迹的接口边界

- Planner Server：负责规划请求与插件管理。
- ComputePathToPose：通过 action 提供起点、目标、planner ID 等输入，输出 nav_msgs/Path。
- Controller Server：消费路径与局部代价信息，生成速度/运动控制命令。
- 速度/轨迹处理：根据速度、加速度、曲率、制动能力和控制周期生成可执行时序；不能把一个无时间参数化的路径当成已验证轨迹。

## 5. 全覆盖路径规划（Coverage Path Planning）

覆盖规划的目标是让指定工作区域被传感器/工具的有效工作范围充分扫过，例如清洁、割草、喷涂、除雪、巡检和排雷。它与点到点路径规划不同：通常需要区域分解、作业条带生成、条带访问顺序和障碍绕行/续作策略。

### 5.1 常见方法

- **Boustrophedon Cellular Decomposition**：根据环境几何将自由空间分成单元，各单元内生成往复式条带，再在单元邻接图上规划访问顺序。经典工作证明了该方法在其建模假设下的完备性；真实清洁/巡检覆盖仍受工具有效宽度、边界处理、障碍、定位和跟踪误差影响。
- **条带/往复式覆盖**：按有效工作宽度、作业重叠、边界和地形约束确定条带间距；不能固定采用“工作宽度×0.9”或统一 10% 重叠。
- **单元访问顺序**：可构建单元邻接图，或近似求解 TSP/广义 TSP 等顺序问题；精确最优性、转场距离与作业方向约束需分别定义。
- **障碍与续作**：动态障碍进入区域时记录未覆盖单元/条带与当前作业状态，再依据安全策略、障碍消失和重新定位质量恢复任务。

覆盖率必须定义分母和计量方式：可按区域面积、有效工具扫掠面积、任务点/地块、作业质量或未覆盖区域计算。验收阈值属于产品需求/行业规范/合同条件，不能把 95% 写作所有清洁机器人通用标准。

## 6. 代价地图、约束和代价设计

路径规划中的总代价不应不加区分地写成固定的“距离 + alpha 离墙 + beta 转向 + gamma 倒车”。实际系统可能包含：

- **硬约束**：超出地图/状态边界、碰撞、运动学不可达、禁止区域、单向通道；
- **软代价**：路径长度、靠近障碍的代价、转向变化、倒车、坡度、地面类型、区域偏好、速度限制等；
- **不确定性裕度**：地图精度、定位协方差、足迹误差和感知延迟造成的安全间隙；
- **层间分工**：代价地图负责环境/区域成本表达，规划器将代价纳入搜索或优化；安全相关距离和保护区域仍需由风险评估与验证确定。

Nav2 Costmap2D 文档中常见层包括 Static、Obstacle、Inflation，以及可选 Voxel、Range 等；Costmap Filters 包括 Keepout、Speed 等。具体插件和默认值会随 Nav2 版本变化。

**Inflation Layer 的作用**是对障碍物周围施加指数衰减代价，并在机器人内切半径范围内设置致命代价；它不是简单的速度相关膨胀。若产品需要速度相关的安全间隙，应将机器人动力学、延迟、制动能力、感知不确定性和安全需求纳入单独的设计/监控逻辑，不能仅通过调大 inflation radius 替代安全设计。

## 7. 选型与验证

规划器选择至少比较以下条件：

| 条件 | 需要回答的问题 |
|---|---|
| 环境模型 | 静态地图、部分未知、动态障碍、拓扑路网还是三维障碍？ |
| 机器人运动学 | 是否可以原地转向？是否需要倒车？是否有最小转弯半径、非圆形足迹或足式接触约束？ |
| 地图与离散化 | 分辨率/状态格是否足以表达障碍、足迹和定位误差？粗化后是否丢失窄通道？ |
| 目标代价 | 最短距离、时间、风险、能耗、舒适度、覆盖率或任务顺序哪个最重要？ |
| 计算资源 | 在目标 CPU/GPU、负载、地图规模和规划频率下能否满足 deadline？ |
| 下游执行 | 规划结果是否可由局部控制器跟踪？是否需要速度剖面、曲率连续和可停车性？ |
| 失败处理 | 无路径、规划超时、地图变化、定位跳变、障碍遮挡或路径不可跟踪时如何处理？ |

建议采用固定测试集和可复现实验：地图/场景版本、起终点分布、机器人 footprint/模型、代价地图参数、软件版本、规划超时、成功率、路径长度、平滑度、最小障碍间隙、计算时间和失败类型均需记录。论文/文档的规划时间或示例路径长度不应外推为目标产品性能。

## 9. 本轮定向复核与未关闭事项（2026-11-03）

本轮纠正：

- 移除 A* 通用“10–100 倍”、JPS“10–30 倍”、Weighted A* 固定权重范围等无条件速度/性能陈述。
- 区分 BFS/DFS、Dijkstra、A*、D* Lite、Theta*、JPS 的图结构与适用前提。
- 对 RRT/RRT* 的可行性、渐近最优等理论性质增加假设边界；不把有限时间结果等同于全局最优。
- 按 Nav2 Smac 官方文档区分 2D A*、Hybrid-A*、State Lattice，并移除“99% 室内 AMR 用一个工程默认”的无依据说法。
- 区分路径和轨迹，纠正将 nav_msgs/Path 描述为完整可执行轨迹的风险。
- 移除全覆盖固定 10% 重叠和 95% 覆盖率阈值，改为按工具有效宽度、跟踪误差、边界与产品验收要求定义。
- 明确 OMPL 是采样规划算法库，不会自动提供机器人碰撞模型、有效状态检查器、运动验证器和完整应用集成。

### 9.1 Nav2 Smac参数与机器人模型一致性复核（2026-11-05）

依据Nav2 Jazzy插件选型文档及Rolling版Smac Hybrid/Lattice参数文档（来源#1101–#1103），需要把“选对算法”进一步落实为模型、地图离散化和搜索预算的一致性检查：

- **Smac 2D不是通用非圆形足迹规划器**：Nav2将2D A*定位于圆形差速/全向等可原地转向平台；若机器人足迹明显非圆、不能原地转向或受最小转弯半径约束，不能只因地图是2D栅格就选2D插件。应比较Hybrid-A*或State Lattice。
- **Hybrid-A*模型输入**：Dubins/Reeds-Shepp运动模型、最小转弯半径、角度离散化和完整footprint碰撞检查必须与实机几何/运动学一致。最小转弯半径填错会让搜索结果在数学上可行、在实机上却不可跟踪。
- **State Lattice控制集是离线生成物**：控制集与生成时的地图分辨率、运动学约束绑定；该插件没有costmap downsampler，最小转弯半径也体现在预生成控制集中而非运行时参数。更换地图分辨率、底盘几何或控制集后必须重新生成/验证，不能只改YAML参数。
- **搜索预算是失败边界，不是实时保证**：Rolling文档列出max_iterations、max_planning_time、terminal_checking_interval和max_on_approach_iterations等上限参数。文档默认值只是该文档版本的配置示例，不是产品deadline；项目需根据目标CPU、地图规模、规划频率和任务最坏工况设定超时，并验证超时后是否正确返回失败/可接受容差路径。
- **解析扩展与代价捷径**：Hybrid/Lattice的analytic_expansion_max_length影响解析扩展；官方建议不要小于当前使用最小转弯半径的约4–5倍，否则规划时间可能显著上升。该建议不是对所有地图/车型的保证，仍需验证解析连接是否穿越高代价区、障碍膨胀区或不可行区域。
- **平滑器可能改变安全间隙**：平滑和refinement会改变离散路径点及其与障碍物的距离；必须对平滑前后分别执行footprint碰撞检查、曲率/曲率变化、最小障碍间隙和下游控制器可跟踪性验证，不能仅以路径更短或更光滑判定更优。

**Smac专项验收用例：** 圆形与非圆形footprint；最小转弯半径边界；倒车启用/禁用；窄通道与未知空间；不同costmap分辨率；不可达目标和目标容差；max_iterations/max_planning_time超时；analytic expansion在高代价区的拒绝；平滑前后碰撞/曲率检查；规划器输出与Controller实际跟踪偏差。记录发行版、nav2_smac_planner包版本、插件ID、参数文件哈希、地图/footprint版本、目标硬件、原始路径和规划耗时分布。该清单是待执行的验证设计，不代表本轮运行过Nav2测试。
