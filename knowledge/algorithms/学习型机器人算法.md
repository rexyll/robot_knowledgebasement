# 学习型机器人算法（Robot Learning / RL / IL / VLA）

> 学习型机器人算法不是一种单一算法，而是从数据中学习感知、状态估计、任务决策或动作策略的一组方法。它们可替代或增强传统模块，但不能自动提供可解释性、实时性、安全保证或跨机器人泛化。工程设计必须明确：输入观测、动作接口、训练数据、机器人形态、部署时序、评价任务与失效处置。

## 1. 先区分任务层级

| 层级 | 学习对象 | 典型输出 | 是否直接控制执行器 |
|---|---|---|---|
| 感知/状态表征 | 图像、点云、触觉、关节状态等 | 检测框、分割、特征、状态估计、物体/场景表示 | 通常否 |
| 运动/操作策略 | 传感器观测与机器人状态到动作的映射 | 关节位置/速度/力矩、末端位姿增量、动作序列 | 可能；必须经过控制接口与安全约束 |
| 任务/行为策略 | 子任务选择、技能调用、长时序动作 | 目标、技能 ID、参数化动作、行为树/状态机输入 | 通常不应直接绕过低层控制和安全层 |
| 语言/视觉-语言-动作模型（VLA） | 图像、语言、机器人状态到动作或动作 token | 语言条件动作、动作块、技能/子目标 | 取决于模型输出定义与部署系统 |
| 世界模型/预测模型 | 当前状态与动作到未来观测/状态预测 | 未来状态、奖励/代价、潜在状态转移 | 通常作为规划/策略学习的一部分 |

不要把“模型可以输出动作”理解成“模型可以安全控制整台机器人”。模型输出的动作坐标系、单位、控制模式、范围、更新周期、时延和失败语义必须定义清楚。

## 2. 强化学习（RL）

强化学习通过与环境交互，根据奖励或回报优化策略。机器人场景可在仿真中训练，也可在受控条件下使用真机数据；但仿真训练、离线学习和真机在线学习的风险及数据要求不同。

### 2.1 基本组成

- **观测** (o_t)：相机/深度/点云、IMU、关节状态、接触状态、任务指令等可用信息。
- **状态** (s_t)：环境/机器人内部完整状态的理论描述；现实系统中往往不能直接完整观测。
- **动作** (a_t)：关节位置/速度/力矩、末端增量、底盘速度或更高层技能命令。训练与部署必须使用一致的动作语义。
- **策略** (pi_	heta(a_tmid o_t))：根据观测选择动作的参数化模型。
- **奖励** (r_t)：对任务进展、稳定性、能耗、碰撞/约束违反等进行量化的学习信号。
- **环境转移**：机器人动力学、接触、执行器、传感器和场景共同决定下一时刻观测。

常见分法：
- **On-policy**：使用当前策略采样的数据更新策略；数据新鲜但样本成本可能较高。
- **Off-policy**：可使用历史回放数据更新；提高数据复用，但需要处理数据分布与当前策略之间的差异。
- **Model-free**：直接学习价值函数/策略；不显式建立可用于规划的环境动力学模型。
- **Model-based**：学习或利用动力学/世界模型来进行预测、规划或策略优化。

### 2.2 机器人 RL 的训练与 Sim2Real

典型流程是：定义任务与动作/观测空间 → 建立仿真模型 → 训练与验证策略 → 识别仿真/实机差异 → 分阶段上机测试。常见技术包括：

1. **域随机化（Domain Randomization）**：在训练中改变质量、摩擦、执行器增益、观测噪声、延迟、光照或物体参数，扩大训练分布。随机化区间应来自系统辨识、器件规格与不确定性分析，不应跨机器人照抄固定百分比。
2. **系统辨识与参数校准**：测量关节惯量/摩擦、执行器响应、延迟、接触和传感器特性，减少模拟器与真实系统之间的模型差异。
3. **教师-学生蒸馏**：训练阶段教师可利用部署时不可获得的特权状态，学生只使用真实部署能够获得的观测；需要验证学生在部分观测与噪声条件下的性能。
4. **历史观测/在线适应**：通过历史状态、负载或接触反馈推断动态变化；在线适应的更新范围必须受约束，并评估异常数据诱发策略漂移的风险。
5. **渐进式部署**：离线仿真、回放、硬件在环、限速/限力测试、受控真机、逐步扩大场景；每个阶段有停止条件和回滚方案。

**训练步数、并行环境数量、GPU 时间和奖励权重都不是通用配方。** Isaac Lab 支持 GPU 并行环境与多种 RL/IL 工作流，但实际吞吐量受物理后端、渲染、机器人模型、传感器模拟、网络结构、GPU 显存和训练算法限制。

### 2.3 奖励与约束

奖励函数是训练目标，不是安全证明。一个移动/足式控制任务可能考虑速度跟踪、姿态稳定、能耗、关节限位、滑移、接触冲击和动作平滑；具体项取决于任务、机器人和单位定义。

常见问题：
- **奖励投机（Reward Hacking）**：策略找到奖励函数漏洞，却没有完成真实任务。
- **尺度失衡**：不同奖励项的量级使某一项主导优化。
- **稀疏奖励**：成功信号太少，训练难以发现可行行为。
- **分布外状态**：训练环境未覆盖的载荷、摩擦、碰撞和传感器异常可能造成不可预测动作。
- **安全约束不充分**：奖励中的碰撞惩罚不等于硬约束，也不等于功能安全验证。

对安全相关机器人，学习策略应置于独立的监督/安全架构中：硬件限位、速度/力/功率约束、碰撞检测、急停、故障监控和安全状态切换必须依据风险评估设计并验证。不能仅依赖策略网络输出“学会了不碰撞”。

## 3. 模仿学习（IL）

模仿学习通过专家演示数据学习策略。数据可来自遥操作、专家操控、脚本/传统控制器、仿真或其他带有动作监督的来源。

### 3.1 常见方法

| 方法 | 核心思路 | 典型优势 | 主要局限 |
|---|---|---|---|
| Behavior Cloning（BC） | 将演示观测-动作作为监督学习样本 | 简单、基线清晰、训练稳定性较容易诊断 | 训练/部署状态分布不一致时会发生误差累积；演示未覆盖的情况缺乏纠错能力 |
| DAgger 类方法 | 在当前策略访问到的状态上继续收集专家纠正 | 缓解行为克隆分布漂移 | 需要专家或可靠标注器介入，在线采集成本较高 |
| Action Chunking（如 ACT） | 一次预测未来一段动作序列，减少逐步预测误差的累积 | 对连续操作/多峰演示轨迹有帮助 | 动作块长度、重叠/时间融合、推理延迟和动作边界平滑需要评测 |
| Diffusion Policy | 将视觉/状态条件下的动作序列建模为条件去噪扩散过程 | 可以表示多峰动作分布，并结合 receding-horizon 控制 | 多步去噪会带来推理开销；性能依赖数据、动作空间和采样配置 |
| Offline RL / 序列建模 | 从固定日志/离线轨迹学习策略或价值函数 | 可利用已有数据，减少在线探索 | 数据覆盖、行为分布外动作和价值外推风险需要处理 |

ACT、Diffusion Policy 等是具体算法家族，不代表整个 IL 领域的统一最优方案。扩散动作生成也不等于 VLA：它可以只接收图像/机器人状态，不必接收自然语言。

### 3.2 演示数据采集

| 数据来源 | 适用情况 | 关键限制 |
|---|---|---|
| 主从臂/手柄/VR 遥操作 | 精细操作、双臂协调、接触任务 | 控制映射、主从延迟、操作者差异、碰撞与数据质量控制 |
| 键盘/脚本/示教器 | 离散技能、重复流程、规则明确的任务 | 覆盖多样性有限，演示未必达到专家质量 |
| 仿真专家/传统控制器 | 可重复、规模化采集及边界场景 | 仿真模型偏差、奖励/控制器偏差可能进入数据 |
| 动捕/人体视频 | 学习动作先验或提供重定向目标 | 人体与机器人运动学/接触/动力学不同；必须处理姿态重定向、接触约束和缺失的机器人动作监督 |

**人类视频不等于机器人演示数据。** 若视频没有同步机器人状态、动作标签或可验证的重定向过程，不能直接视为可用于 BC 的机器人 ((o_t,a_t)) 轨迹。

### 3.3 数据集必须记录什么

至少记录：
- 机器人型号、关节顺序、关节限位、末端/夹爪定义、控制模式；
- 相机型号、安装位姿、分辨率、时间戳、曝光/深度参数；
- 关节位置/速度/力矩、末端位姿、力/触觉（若有）及单位；
- 观测与动作的时间同步、控制周期、延迟、插值/重采样方式；
- 任务指令、物体/场景条件、成功/失败/中断和人工干预标签；
- 数据集版本、训练/验证/测试切分、隐私/授权、使用许可与来源。

数据量不能用单一“每分钟多少 MB”估算。视频压缩格式/码率、相机数量、图像分辨率/帧率、深度数据、状态/动作字段和保存时长都会改变存储规模。应按具体数据采集配置计算流量与存储预算。

## 4. 视觉-语言-动作模型（VLA）

VLA 将视觉观测与自然语言指令等条件映射为机器人动作或动作序列。不同模型输入、机器人 embodiment、动作表示、数据来源和推理架构并不相同。

### 4.1 代表模型与研究系统

| 模型/系统 | 公开资料描述 | 重要边界 |
|---|---|---|
| RT-2（Google DeepMind, 2023） | 将预训练视觉语言模型与机器人数据共同微调，输入相机图像和语言指令，预测机器人动作 token | 研究工作展示了 Web 知识与机器人数据结合的潜力；不能由论文/演示推断公开可部署权重、任意机器人兼容或普遍成功率 |
| OpenVLA | 7B VLA；公开模型卡描述其使用 Open X-Embodiment 中约 970K 条机器人操作轨迹训练，输入语言与相机图像并输出动作 | 具体 checkpoint、动作归一化与机器人数据分布需匹配；GitHub README 对底层 Llama-2 派生模型有许可证提醒，与仅看代码 MIT 许可不同 |
| π₀ / π₀-FAST / π₀.₅（openpi） | openpi 代码库包含 flow-based VLA、基于 FAST action tokenizer 的自回归 VLA，以及增强开放环境泛化的 π₀.₅；提供基础 checkpoint 与微调示例 | 官方 README 明确说明模型先为 Physical Intelligence 自有机器人开发，迁移到其他平台需要适配且不保证成功；仓库给出的 GPU/OS 要求是当前实现的环境估计，不是所有 VLA 的通用要求 |
| GR00T N1.7（NVIDIA） | 官方仓库将 N1.7 标为 GA；架构由视觉语言基础模型与 diffusion transformer 动作头构成，支持多模态输入、机器人数据后训练和评估/部署流程 | 官方仓库区分代码 Apache-2.0 与模型权重 NVIDIA Open Model License；benchmark 中的推理速率必须绑定特定 GPU、TensorRT、batch 和配置 |
| Helix / Helix 02（Figure） | Figure 公布的 Helix 使用慢速语义系统与高速视觉运动策略；后续 Helix 02 增加 System 0 作为全身运动/接触基础层，形成分层架构 | 这是 Figure 的具体设计，不是全行业统一标准；其公开频率/成功演示不代表其他平台或任意任务性能 |

### 4.2 VLA 与传统架构的关系

VLA 可承担视觉条件的动作生成或技能执行，但通常仍需要：
- 机器人适配层：相机/状态预处理、关节映射、坐标系、动作单位/归一化、夹爪和控制模式转换；
- 控制层：低层伺服、力/速度/位置环、插补、关节限位和轨迹跟踪；
- 任务层：任务分解、技能选择、完成条件和失败恢复；
- 运行监督：输入有效性、模型健康度、超时、动作范围、异常检测和操作者接管；
- 独立安全机制：与模型网络分离的安全控制器/硬件链、急停和风险评估。

某个 VLA 的动作频率不能直接当作电机控制环频率。若模型异步或低频地产生动作块，需要定义缓存、时间戳、插值、重叠融合、超时处理和旧动作清除规则。

### 4.3 分层架构并非统一“共识”

分层控制是常见工程设计选择，但不同项目的层数、接口和频率不同。Figure Helix 的 System 1/2 与 Helix 02 的 System 0/1/2 是公司公布的具体架构；NVIDIA GR00T N1.7 公开描述的是 VLM backbone + diffusion transformer head。不能将某一家公司的系统划分、频率和任务成功率概括成行业通用标准。

## 5. LLM 在机器人系统中的非 VLA 用法

LLM 可用于自然语言交互、任务意图解析、故障知识检索或受限工具调用。但它通常不应直接生成未验证的电机指令或绕过安全控制。

较稳妥的集成方式：

1. 用户自然语言进入解析层；
2. 模型生成受约束的任务/技能调用结构（例如带 schema 的 JSON 或已登记 API 名称）；
3. 系统验证用户权限、参数范围、机器人状态、场景前置条件和工具返回；
4. 经任务执行器/行为树调用已验证技能；
5. 低层控制器执行并监控，独立安全系统可随时限制/停止；
6. 记录模型输入、工具调用、实际执行结果和人工接管事件。

常见应用包括工单/日志检索、自然语言任务编排、设备状态摘要、手册问答和操作员辅助。LLM 生成的解释或计划应标记不确定性，并通过机器人状态和工具结果验证。

## 6. 学习系统与传统算法栈的集成

| 系统模块 | 可使用学习方法 | 常见保留的传统/工程机制 |
|---|---|---|
| 感知 | 检测、分割、关键点、深度估计、语义特征 | 相机标定、时序同步、跟踪质量监控、几何约束 |
| 定位/建图 | 学习特征、学习深度、学习型回环/场景表征 | VIO/SLAM 几何优化、坐标系/TF、传感器标定与地图管理 |
| 预测/规划 | 行人轨迹、交互预测、学习型代价或策略 | 运动学/动力学约束、碰撞检查、可达性、规划失败处理 |
| 运动控制 | 足式/灵巧操作策略、残差策略、策略蒸馏 | 低层伺服、安全限位、独立制动/急停、实时 watchdog |
| 任务执行 | LLM/VLA 任务建议、技能选择、动作块 | 行为树/状态机、权限、前置条件、超时和恢复 |

“某层可以使用深度学习”不意味着该层必须完全由深度网络取代。混合式架构通常允许对学习模型进行监控、限制输出并在失效时切换到已验证行为。

## 7. 数据闭环与训练流程

推荐的工程闭环：

1. **任务规格**：定义成功/失败、可接受时间、精度、作用力/速度边界、环境范围与禁止行为。
2. **数据采集**：采用遥操作、专家控制、仿真或合规数据集；记录机器人/传感器/动作语义与数据许可。
3. **质量审查**：检查同步、缺失、重复、异常动作、错误标签、失败分布和数据泄漏。
4. **训练/微调**：锁定模型结构、代码 commit、数据集版本、超参数、随机种子和训练环境。
5. **离线评估**：按任务/环境/物体/演示者拆分数据，评估成功率、动作误差、校准和分布外行为。
6. **仿真评测**：对接触、摩擦、遮挡、载荷、延迟、传感器噪声等扰动做测试；明确仿真模型差异。
7. **硬件在环/受限实机**：在限速、限力、隔离区域和可接管条件下评估；不允许模型直接绕过安全联锁。
8. **部署监控与回流**：记录失败、人工接管、异常输出、环境变化和版本信息；经标注与审查后才加入下一轮数据集。

训练、验证与测试集要避免同一轨迹的相邻窗口泄漏到不同集合。跨物体、场地、光照、负载、机器人个体和操作者的泛化测试必须单独报告。

## 8. 评测指标

| 维度 | 指标示例 | 说明 |
|---|---|---|
| 任务能力 | 完成率、子任务完成率、失败类型 | 注明任务定义、物体/环境分布、试验次数和统计区间 |
| 数据效率 | 达到指定性能所需演示数、采样步数/交互成本 | 明确数据质量、训练预算和比较基线 |
| 泛化 | 新物体/场地/操作者/机器人配置的完成率 | 区分零样本、少样本微调和大量微调 |
| 动作质量 | 轨迹误差、抖动/jerk、速度/力约束违反、接触稳定性 | 绑定动作空间、单位、采样和控制器 |
| 实时性 | 观测到动作的端到端延迟、频率、超时/丢帧 | 在目标 GPU/CPU、图像尺寸和软件版本测量 |
| 安全性 | 碰撞/限位/力限制事件、危险动作率、接管次数、故障恢复 | 说明场景风险、检测器和独立保护机制 |
| 可靠性 | 长时间运行、重置/断连恢复、温升、内存泄漏 | 重复试验并记录软硬件版本 |

**不要用单一 success rate 宣称模型已具备通用能力。** 论文 benchmark、厂家演示、用户自测和产品验收是不同等级的证据，必须明确数据集、场景、试验次数和模型/软件版本。

## 11. 本轮定向复核与未关闭事项（2026-11-03）

本轮纠正：

- 删除“2023–2026 主叙事已从规则转向数据学习”“三条已落地路线”等概括性趋势判断，改为按 RL、IL、VLA 和工具链逐项描述。
- 删除固定 4096 并行环境、1 亿交互步、数小时 GPU、参数 ±20–30% 等通用训练配方；要求按任务、仿真模型、GPU、策略和实机系统确定。
- 删除未经可靠证据支持的 Unitree Go2/H2 全 RL 化、统一足式性能优于传统 ZMP 等结论；说明 RL 是可选控制方法，不能由单个案例外推产品路线。
- 纠正 Diffusion Policy、ACT、VQ-BeT 与 VLA 的类别边界；说明动作块/扩散生成是 IL 策略路线，不自动等同语言条件 VLA。
- 删除 ACT 单台每日数百条、轨迹 1 分钟 100–500MB、10 万条 10–50TB 等无采集配置依据的数字。
- 纠正 VLA 双系统“行业共识”和统一 50–200Hz/任务成功率 80–95% 说法；更新 Figure Helix/Helix 02 与 GR00T N1.7 的具体公开架构。
- 纠正 OpenVLA 代码与预训练模型许可证边界；记录 openpi 代码许可与 checkpoint/底层模型条款分离；记录 GR00T N1.7 代码与权重使用不同许可。
- 纠正 LeRobot/Isaac Lab“全部宽松、商用门槛低”的过度结论，补充 Isaac Sim、cuRobo、第三方资产以及数据集/权重许可证边界。
- 明确 LLM/VLA 不应绕过任务执行器、低层控制和独立安全保护；删除将模型输出等同可安全执行的暗示。
