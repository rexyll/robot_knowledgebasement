# 视觉 SLAM（VSLAM）与视觉惯性估计（VIO）

> 视觉 SLAM 使用相机观测估计运动轨迹并构建/维护地图；VIO（Visual-Inertial Odometry）将相机与 IMU 结合估计运动状态。二者有关联，但不是同义词：纯视觉单目、双目、RGB-D SLAM 都存在，不能说实际系统“都是 VIO”。

## 1. 任务与尺度：先明确系统要输出什么

| 任务/配置 | 观测来源 | 尺度与地图边界 | 典型输出 |
|---|---|---|---|
| 单目视觉里程计/SLAM | 一台单目相机 | 纯单目几何通常只能恢复到未知全局尺度（存在尺度规范自由度）；没有外部尺度来源时，轨迹不能直接解释为米制距离 | 相对/任意尺度轨迹、稀疏地图或系统内部地图 |
| 双目视觉 SLAM | 已标定双目相机 | 已知基线和双目几何可提供米制尺度；尺度精度受基线、标定、同步、视差和图像质量影响 | 米制相对位姿、地图 |
| RGB-D SLAM | RGB 图像 + 深度图 | 深度传感器提供带单位的距离观测；尺度准确性受深度标定、量程、材质、环境和无效深度影响 | 米制位姿、点云/稠密或半稠密地图 |
| 单目视觉惯性（VIO / VI-SLAM） | 单目相机 + IMU | IMU 可在充分运动激励、时间同步、内外参和噪声模型正确等条件下帮助恢复米制尺度；初始化条件不足时可能退化或失败 | 米制状态估计；是否产生持久地图/回环取决于具体系统 |
| 双目/多目视觉惯性 | 双目/多目相机 + IMU | 相机基线提供尺度约束，IMU 增加高频运动信息；多传感器仍需准确标定与同步 | 轨迹、局部地图或多会话地图，视实现而定 |

**不要把“VIO 一定能解决尺度”理解为无条件保证。** 单目视觉本身没有绝对尺度；视觉惯性初始化需要运动和观测提供足够约束。缺乏有效平移加速度激励、相机/IMU 时间偏移、外参错误或 IMU 饱和等情况都可能导致尺度与偏置估计不稳定。纯旋转或近似恒定速度等退化运动不能依靠“加上 IMU”自动消除。

还要区分：
- **odometry**：输出连续的局部运动估计，长期漂移可累积。
- **SLAM**：还包括地图管理、回环/全局约束或地图复用等能力；不同系统实现的范围不同。
- **localization**：在已有地图中定位，不一定重新建图。
- **semantic perception**：图像可作为目标检测/分割输入，但 VSLAM 的几何估计不会自动生成语义标签；语义地图需要单独的感知/融合设计。

## 2. 视觉算法路线

| 路线 | 核心观测/方法 | 适用特点 | 主要限制 |
|---|---|---|---|
| 间接法/特征法 | 检测、描述和匹配关键点，再做几何估计与优化；如 ORB 系列 | 有较成熟的几何验证、重定位和回环设计；可支持不同相机配置 | 依赖可重复检测/匹配的图像结构；重复纹理、运动模糊和低纹理区域可能失配 |
| 直接法/光度法 | 直接利用像素灰度/光度一致性估计运动或结构；如 DSO、LSD-SLAM | 不必完全依赖离散关键点描述子，可使用图像中有梯度的像素信息 | 仍需要足够的图像梯度和光度一致性；曝光变化、自动增益、运动模糊、滚动快门和光照变化都会影响结果；“直接法”不等于可以在无纹理墙面稳定工作 |
| 半稠密/稠密方法 | 在较多像素/深度观测上估计结构与位姿 | 可形成更丰富的表面/深度表达 | 数据量、显存/内存和计算成本较高；深度有效性与地图表达需要定义 |
| 视觉惯性估计（VIO） | 相机观测与 IMU 预积分/运动模型联合估计；可采用滤波或滑窗优化 | IMU 提供高频角速度/加速度信息，视觉提供外部几何约束 | 初始化、时间同步、外参、噪声模型和运动激励高度重要；VIO 不必然包含完整持久地图或回环 |
| 学习型视觉 SLAM | 学习得到的特征、光流、深度/位姿更新，与几何优化结合；如 DROID-SLAM | 可利用训练数据学习外观/运动先验，支持多种测试输入配置 | 泛化依赖训练数据和域差异；算力、显存、驱动/框架版本及失效可解释性需验证 |

ORB、SuperPoint 等特征不能仅凭“传统/学习”标签判断稳定性；应在目标相机、图像分辨率、曝光、场景和运动条件下比较检测/跟踪质量。SuperPoint 等学习特征的计算负载、模型许可和部署框架也要核验。

## 3. 视觉 SLAM / VIO 的通用数据流

以下是概念流程，不是所有算法都实现全部步骤，也不代表固定关键帧数量、固定输出频率或固定优化变量：

1. **图像采集与预处理**：检查曝光、时间戳、图像编码、畸变参数、滚动/全局快门和相机模型。
2. **视觉前端**：特征检测与跟踪、光度残差构建或学习型匹配/光流，估计帧间几何约束。
3. **初始化**：建立初始位姿、深度/尺度、重力方向和 IMU 偏置（若适用）；若观测几何或运动激励不足，应延后初始化或明确失败状态。
4. **状态估计/优化**：根据系统架构使用滤波、滑动窗口非线性优化或其他方法；视觉残差与 IMU 预积分残差的定义随实现变化。
5. **边缘化/地图管理**：部分系统将旧状态边缘化以控制计算量；SLAM 系统还需维护关键帧、地图点、局部地图或多地图数据结构。
6. **重定位与回环**：地点识别生成候选，随后使用几何一致性验证；错误回环可能破坏全局地图，不能只靠外观相似度接受约束。
7. **输出与评测**：发布位姿、速度、协方差/状态质量和地图（如实现支持）；记录追踪失败、重定位、延迟和资源占用。

### 3.1 视觉惯性初始化与标定

相机与 IMU 的融合至少涉及：

- 相机内参与畸变模型（pinhole、fisheye 等），以及图像分辨率/裁剪变化后的参数映射；
- 相机与 IMU 的空间外参（旋转和平移）、坐标轴方向和安装刚度；
- 相机与 IMU 时间偏移、时钟来源、时间戳语义和抖动；
- IMU 角速度/加速度单位、噪声密度、随机游走、偏置、量程、采样频率和饱和状态；
- 相机曝光、滚动快门读出时间、帧率变化和图像丢帧；
- 初始化阶段的有效平移/旋转激励与场景纹理/视差。

部分实现支持在线空间/时间标定，但“有在线标定功能”不代表可跳过初始标定、同步检查或质量验证；在线标定的收敛范围、激励需求和运行风险要按版本和参数验证。

### 3.2 双目与 RGB-D 的额外要求

- **双目**：左右相机内参/畸变、基线、相对姿态、同步、硬件触发、极线校正和有效视差范围。远距离或低纹理区域的视差可能不足；不能仅凭“已知基线”假设所有深度点都有可靠精度。
- **RGB-D**：确认深度单位、尺度因子、无效值编码、深度到彩色相机的配准、帧同步、工作量程和环境限制。透明/反光/吸光材质可能产生缺失或异常深度，具体取决于深度成像技术和设备。
- **鱼眼/全景相机**：使用与镜头相匹配的投影/畸变模型；不能直接套用普通针孔相机参数。

## 4. 失败模式与处理思路

| 现象 | 可能原因 | 检查方向 |
|---|---|---|
| 跟踪频繁丢失 | 弱纹理、重复纹理、强运动模糊、快速视角变化、动态物体遮挡 | 图像梯度/特征分布、曝光、帧率、运动速度、动态区域处理 |
| 尺度漂移或初始化失败 | 单目尺度未约束、IMU 激励不足、IMU 参数/外参/时间偏移错误 | 运动轨迹、初始化状态、重力方向、偏置、同步与尺度可观性 |
| 画面跟踪正常但地图弯曲 | 累积漂移、错误回环、局部几何约束不足 | APE/RPE、回环候选和几何验证、地图/轨迹图一致性 |
| 光照变化后估计恶化 | 自动曝光/增益、阴影、反光、光度模型不满足 | 曝光控制、图像预处理、光度参数、特征重检测 |
| 深度图出现洞/飞点 | 量程、材质、环境光、深度对齐或设备模式 | 查看原始深度有效率、深度单位/标定与设备模式 |
| 相机与 IMU 融合抖动 | 时间偏移、外参、IMU 饱和、驱动时间戳不一致 | 采集原始时间戳，做时延/外参标定与运动数据验证 |
| 回环后位姿突然变化 | 真实全局修正或错误回环/数据关联 | 查候选检索、重投影/几何一致性、优化前后残差和地图证据 |

没有目标传感器、实际数据和真值系统时，只能列出可能原因及测试方法，不能宣称已达到定位精度、抗退化能力或安全性能。

## 5. 视觉 SLAM 与 LiDAR SLAM 的比较

| 维度 | 视觉方法 | LiDAR 方法 |
|---|---|---|
| 主要测量信息 | 图像亮度/特征/深度或视觉惯性约束 | 激光测距几何点/扫描 |
| 尺度 | 单目纯视觉存在尺度自由度；双目/RGB-D 有标定尺度；VIO 依赖初始化与运动约束 | 测距通常提供米制尺度，系统误差仍受标定和传感器精度影响 |
| 环境敏感性 | 对纹理、光照、曝光、运动模糊敏感；不同镜头模型会影响几何 | 对可见光照相对不敏感，但受反射率、透明/吸收材料、雨雾/尘埃、视场和几何退化影响 |
| 地图表达 | 特征点、关键帧、稠密/半稠密深度、点云或学习型表示 | 2D 占据栅格、3D 点云/体素或距离场 |
| 语义能力 | 图像可接入检测/分割模型；VSLAM 本身不自动产生语义标签 | 可与相机融合生成语义信息；LiDAR 几何本身也不自动等于语义理解 |
| 系统成本 | 取决于相机/IMU、算力、同步与标定；不能给出跨产品通用价格 | 取决于扫描器类型、计算平台、安装与安全要求；不能给出跨产品通用价格 |

选择依据应是任务要求、环境、距离/视场、精度预算、功耗、安装空间、软件许可、维护能力和目标硬件验证，而不是“相机一定便宜”或“激光一定更准”。

## 6. 代表软件与部署边界

| 系统 | 官方公开能力 | 官方仓库/包装环境边界 | 需核验事项 |

| RTAB-Map / rtabmap_ros | 图优化 SLAM；可接 RGB-D、双目、LiDAR，进行外观/近邻回环；按配置输出 OccupancyGrid、点云或 OctoMap | 官方 ROS 2 wrapper README 声明最低 Humble；当前支持发行版表需在部署时核对；其 RGB-only 模式可以只做外观回环而不提供里程计、图优化或米制地图 | 必须选择适当传感器输入与同步节点；核对 ROS 发行版、包版本、地图模式、内存策略和依赖许可 |
| stella_vslam | 单目、双目、RGB-D；针孔、鱼眼、等距矩形等相机模型；支持地图存储/加载和新图像定位 | ROS wrapper 为独立仓库；上游 README 将 IMU integration 列在开发事项中，不应当作已验证 VIO 系统 | 版本需区分 0.3 前后；核心 BSD-2-Clause 许可不代表所有依赖均为相同许可，需审查 g2o/第三方组件及动态链接要求 |
| DROID-SLAM | 学习型视觉 SLAM；循环迭代更新位姿和像素深度，并使用 Dense Bundle Adjustment layer；可处理单目，并在测试阶段利用双目或 RGB-D | 官方仓库 demo 说明推理至少需要 11GB GPU 显存，训练至少 24GB（为该仓库给出的测试配置，不是所有实现的普适算法门槛） | 核对 CUDA/PyTorch、子模块、预训练权重、训练数据域差异、部署延迟和第三方许可 |

- ORB-SLAM3 官方 LICENSE/README 标注 GPL-3.0；README 另要求审查 Thirdparty/Dependencies 目录。

- stella_vslam 的 LICENSE.original 与 LICENSE.fork 均为 BSD 2-Clause，但 README 特别说明 0.3 以前版本按 ORB-SLAM2 派生 GPL 版本处理；同时指出 g2o 的 csparse_extension 为 LGPLv3+，并给出动态链接建议。
- DROID-SLAM 仓库 LICENSE 为 BSD 3-Clause；PyTorch/CUDA、子模块、预训练权重与数据集的条件需另行核验。

以上是仓库文件层面的公开声明记录，不构成法律意见，也不意味着“BSD = 自动适合闭源商用”。再分发、修改、静态/动态链接和依赖集成需要按实际 commit、依赖树和发行方式作许可审查。

## 7. 评测与工程验收

至少建立可复现的测试基线：

1. **输入与环境**：相机准确型号、镜头、分辨率、帧率、曝光/增益、快门类型、IMU 型号/固件、深度设备模式、安装位置、外参和软件版本。
2. **数据质量**：图像丢帧、同步偏差、时间戳抖动、IMU 饱和、深度有效率、曝光变化和数据包完整性。
3. **精度指标**：ATE/RPE、尺度误差、姿态误差、真值来源、轨迹对齐方法、统计量与置信区间/分位数。
4. **鲁棒性指标**：跟踪丢失率、重定位成功率/时间、错误回环率、不同纹理/光照/动态物体场景表现。
5. **资源与实时性**：端到端延迟、图像处理频率、CPU/GPU/内存/显存、功耗与热稳态；注明线程、分辨率和负载。
6. **失效与恢复**：相机遮挡、镜头污染、照明突变、IMU 断连、同步偏移、深度丢失、重定位和地图切换。

论文数据集的 ATE、视频演示帧率和单次成功轨迹不是目标产品验收证据。实机验收要在最终安装、温度、振动、照明、运算平台和目标场景下重复执行。

## 9. 本轮定向复核与未关闭事项（2026-11-03）

本轮纠正：

- 删除“纯视觉有尺度不确定性，所以实际都是 VIO”的错误概括；明确单目、双目、RGB-D 与视觉惯性均为不同配置。
- 把单目尺度、双目基线、RGB-D 深度尺度和单目-IMU 条件可观性分开说明；添加运动激励、同步和外参条件。
- 修正“直接法弱纹理可用”的绝对化说法：直接法仍需要足够图像梯度和可用光度模型。
- 纠正 VINS-Fusion 的输入类型和官方软件环境边界；移除未被该实现资料支撑的固定关键帧数、输出频率和四自由度回环流程细节。
- 纠正 MSCKF 类滤波式 VIO 与完整持久地图/回环 SLAM 的概念边界，不再混作同一能力。
- 纠正 RTAB-Map 为“直接输出稠密地图”的概括；按输入模式区分 RGB-D/双目/LiDAR 的图优化能力与 RGB-only 外观回环模式。
- 纠正 stella_vslam 的 VIO 归类：当前 README 仍将 IMU integration 列为开发事项；版本 0.3 前后许可边界也需区分。
- 删除视觉/激光方案通用价格和“图像天然语义”“家用扫地机路线转变”等无统一来源的市场或功能结论。
- 逐项核对 ORB-SLAM3、VINS-Fusion、RTAB-Map、stella_vslam、DROID-SLAM 的公开许可文件；明确核心许可证不覆盖所有依赖、权重和打包方式。
