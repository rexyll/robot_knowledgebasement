# 视觉感知算法（Vision / 3D Perception）

> 机器人感知将相机、深度、LiDAR、IMU、触觉和其他传感器观测转成可供定位、规划、交互和操作使用的状态与语义信息。深度学习是重要方法，但并不替代几何、标定、跟踪、点云处理、状态估计与不确定性管理。**检测分数高不等于机器人能安全避障**：输出必须考虑坐标系、时间戳、目标运动、误检/漏检、传感器盲区与下游保护策略。

## 1. 先区分感知任务

| 任务 | 典型输出 | 机器人用途 | 代表方法/工具 |
|---|---|---|---|
| 图像分类 | 图像级类别/概率 | 场景/工件粗分类 | CNN、ViT 等分类器 |
| 2D 目标检测 | bbox、类别、置信度 | 人、托盘、货物、门/按钮等目标定位 | Ultralytics YOLO 系列、RT-DETR |
| 旋转框/关键点 | oriented bbox、人体/物体关键点 | 斜放托盘、抓取姿态、人体姿态 | OBB detector、pose estimator |
| 语义分割 | 每像素类别 | 地面、墙面、可通行区域、动态区域 | DeepLab、SegFormer 等分割模型 |
| 实例/视频分割 | 每个实例的 mask，或跨帧 mask track | 动态目标轮廓、物体跟踪、视频标注 | Mask R-CNN、SAM 2、视频分割器 |
| 2D 多目标跟踪（MOT） | 带 ID 的时序检测框/轨迹 | 行人速度估计、目标持续身份、交互预测 | SORT、DeepSORT、ByteTrack |
| LiDAR 3D 检测 | 3D bbox、类别、置信度 | 车辆/货架/障碍物三维位置 | PointPillars、CenterPoint、PV-RCNN 等；OpenPCDet 为研究/开发工具箱 |
| 点云地面/语义/实例分割 | 地面标签、点级类别/实例 ID | 地面去除、障碍聚类、可行驶区域 | Patchwork++、RANSAC、Open3D-ML 等 |
| 深度/距离估计 | depth/disparity map、带单位的距离（若模型/标定支持） | 避障、抓取、场景重建 | RGB-D/双目几何、Depth Anything V2 等 |
| 视觉定位/光流 | 关键点匹配、光流、相对运动/位姿 | 视觉里程计、VIO、运动补偿 | 特征跟踪、光流、VSLAM/VIO 系统 |
| 语言/开放词汇感知 | 文本条件 bbox、区域匹配或图文相似度 | 长尾目标检索、语义任务交互 | Grounding DINO、YOLO-World、CLIP 等 |

边界提醒：

- **CLIP** 主要提供图文嵌入/相似度，并非直接输出检测框的通用检测器；如需框定位，通常要结合 grounding/detection 模型。
- **SAM 2** 是可提示的图像/视频分割模型，本身不自动给出开放词汇类别；类别语义需由检测/文本 grounding 等模块提供。
- **Depth Anything V2 基础相对深度 checkpoint** 输出相对深度/逆深度，不等同于具有标定米制尺度的深度相机；若需 metric depth，应使用明确以米制数据训练/校准的 metric checkpoint，并验证域适配。
- **DROID-SLAM** 属于视觉 SLAM，而非普通深度估计或检测器；见 [[视觉SLAM]]。
- 传统几何方法仍重要：地面拟合、点云聚类、几何一致性检查和 KF 数据关联可作为无学习或混合方案，不应因“深度学习主流”而全部移除。

## 2. 2D 检测、分割与关键点

### 2.1 检测模型

模型选型不能只比较 COCO mAP 或论文 FPS。需先定义机器人任务中的类别、目标尺寸、距离、遮挡比例、运动模糊、背景干扰、相机高度/视角以及漏检代价。

- **Ultralytics YOLO 系列**：官方框架覆盖 detection、instance/semantic segmentation、pose、OBB、分类和 tracking 等任务；具体版本与模型结构随仓库更新，应锁定 tag/commit 和 checkpoint。
- **RT-DETR**：端到端 Transformer 检测路线，可通过不同 decoder depth 在速度/精度间调整；官方公开 benchmark 需绑定模型变体、输入分辨率、数据集、GPU、TensorRT/FP16 设置。
- **小目标/细粒度目标**：不仅依赖换大 backbone，还需评估相机像素密度、拍摄距离、镜头焦距、输入 resize、标注框质量、目标占比和采样策略。

### 2.2 分割与关键点

- **语义分割**：每个像素分配类别，适合地面/墙面/货架面等区域理解；多个同类实例通常不会自动分开。
- **实例分割**：在语义类别之上区分独立物体，适合重叠物体与抓取对象轮廓。
- **视频/提示式分割**：可用点、框或已有 mask 提示模型跟踪/传播区域，但需检测遮挡恢复、ID 交换和长视频漂移。
- **关键点/姿态估计**：输出人体骨架或物体关键点；要将图像坐标转为机器人可用坐标，需相机标定、深度/几何约束和坐标变换。

## 3. 多目标跟踪与运动状态

检测器每帧输出的是候选观测；跟踪器负责跨帧关联并维护目标轨迹。常见模块包括：

1. **运动预测**：用 Kalman Filter 等根据历史状态预测下一时刻位置/速度。
2. **数据关联**：使用 IoU、外观 ReID、距离/马氏距离或组合代价矩阵进行匹配。
3. **轨迹管理**：新建、确认、丢失、重新激活和删除轨迹；配置 track buffer、确认帧数和置信度分层。
4. **不确定性与遮挡**：记录协方差/置信度、可见性和丢失时长；不要把短时预测位置当成当前准确检测。
5. **运动预测下游接口**：输出坐标系、时间戳、速度、目标尺寸、类别、ID 与状态质量，供 [[局部规划与避障]] 等模块使用。

典型区别：
- SORT：简单的 Kalman 预测 + IoU 匹配基线；
- DeepSORT：在 SORT 风格关联中加入外观 ReID 特征；
- ByteTrack：利用高、低置信度检测分层关联以挽回部分被遮挡/低分目标。

跟踪指标不只看目标 ID 是否连续；需评估遮挡、交叉、相似外观、快速转向、出入视野和相机运动场景。

## 4. LiDAR 与 3D 点云感知

### 4.1 几何处理链

```
原始 PointCloud2 / packet
    ↓ 解包、坐标变换、时间戳/逐点时间检查
畸变补偿（若扫描期间有明显运动）
    ↓
ROI / 高度 / 体素 / 距离过滤
    ↓
地面分割（Patchwork++ / RANSAC 等，按场景选择）
    ↓
非地面点云 → 欧式聚类 / DBSCAN / 学习型点级分割
    ↓
障碍簇、3D box、类别和置信度
    ↓
多帧跟踪/数据关联 → 速度和状态不确定性
    ↓
障碍物/可通行区域 → 定位、局部规划与安全监控
```

上述不是固定流水线。对不同扫描模式、雷达线数、点时间字段、视场、场景地面和机器人运动状态，预处理/地面分割/聚类顺序可能不同。

### 4.2 代表算法和工具

- **Patchwork++**：点云地面分割方法，采用区域自适应和多种鲁棒性处理；官方仓库当前提供 C++、Python 和 ROS 2 示例。它输出的是地面分割结果，不是完整物体检测/跟踪栈。
- **PointPillars**：将点云垂直柱状编码后用于 BEV 3D 检测的一种网络架构；速度和精度依赖点云预处理、pillar 尺寸、backbone、数据集和部署后端。
- **CenterPoint**：常见 BEV/voxel 系 3D 检测与跟踪方法之一；模型变体、数据集和代码实现需单独核验。
- **OpenPCDet**：LiDAR 3D 检测开发工具箱，官方 README 列出 PointRCNN、PV-RCNN、Voxel R-CNN、PV-RCNN++、MPPNet 等代码实现。README 中列出的 release/支持范围不能替代对最近 commit、依赖和特定模型配置的检查。
- **Open3D-ML**：Open3D 的 3D 机器学习扩展，提供点云语义分割数据集/模型与训练管线；实际框架和版本兼容需按当前 release 核验。

## 5. 深度估计、相机几何与标定

单目深度网络输出的相对深度通常不具备稳定的全局米制尺度。双目、RGB-D 和 metric depth 模型能提供尺度信息，但仍需正确标定、对齐、量程和误差模型。

工程检查至少包括：

- 相机内参、畸变模型、分辨率/裁剪/缩放变换；
- 相机与机器人 base frame 的空间外参；
- 双目左右相机同步、基线、极线校正和视差有效范围；
- RGB-D depth scale、无效值、深度到彩色图像对齐和有效量程；
- rolling shutter、曝光/自动增益、运动模糊和帧率变化；
- 相机—IMU—LiDAR 的时钟源、时间戳语义和时间偏移。

Depth Anything V2 的官方 checkpoint 并非统一许可：Small 模型卡列 Apache-2.0，Base 和 Large 模型卡列 CC-BY-NC-4.0；仓库代码许可证不能覆盖不同 checkpoint 的独立条款。metric-depth 子目录另提供室内/室外训练配置与米制模型，不能将基础相对深度权重直接当作 metric depth。

## 6. 多传感器融合感知

多传感器融合不止“前融合 vs 后融合”，还可以按中间特征/BEV 表达融合：

| 方式 | 输入/融合点 | 优势 | 风险与要求 |
|---|---|---|---|
| Early Fusion（数据级） | 原始图像/点云/深度在输入层对齐后联合处理 | 可保留丰富原始信息 | 对标定、同步、数据结构和计算资源要求高 |
| Feature/BEV Fusion（特征级） | 各模态先提特征，再在 BEV/共享空间融合 | 能结合异构模态的中间表示 | 特征空间、几何变换、采样与跨模态误差需仔细验证 |
| Late Fusion（目标/轨迹级） | 各传感器先独立检测/跟踪，再统一坐标系做数据关联 | 模块化、便于故障隔离和渐进集成 | 误检/漏检与关联误差可能在融合后固化；置信度标定和目标 ID 管理重要 |

同步误差对空间定位的近似影响可用：
`e_t \approx v\,\Delta t + r\,\omega\,\Delta t`
其中 v 为传感器/目标相对线速度量级，r 为观测距离，omega 为相对角速度量级，Δt 为时间偏差；这是小角度/短时间近似，实际还受物体运动、扫描内时间、外参和去畸变影响。单独写“10 ms 等于 1.5 cm”只适用于约 1.5 m/s 纯平移且忽略旋转等特定条件，不是统一同步标准。

融合策略需包括：坐标系、外参、时间同步、运动补偿、观测协方差/置信度、数据关联、传感器失效标志和退化模式。多传感器冗余不能仅按数量定义；要评估其视场/故障模式是否真正互补，并保持独立安全保护链。

## 7. 数据、训练与数据集

### 7.1 标注和切分

机器人数据集应覆盖目标现场，而不仅是公开数据集。标注规范至少定义：
- 类别字典、ignore/crowd、遮挡/截断、困难样本和属性标签；
- bbox/旋转框/掩码/关键点/3D box 的坐标定义与可见性规则；
- 多帧跟踪的 ID 连续性、遮挡恢复、出入场景和目标重识别；
- 传感器时间戳、标定版本、坐标系和数据同步状态；
- 训练/验证/测试按场景、时间、机器人、地点和轨迹分组，避免同一段视频相邻帧泄漏到不同集合。

### 7.2 常见评测数据集

| 数据集 | 任务/模态示例 | 主要用途与注意 |
|---|---|---|
| COCO | 2D detection / segmentation / keypoints | 通用图像 benchmark；目标类别/尺度不代表机器人目标分布 |
| KITTI | 相机、LiDAR、3D 检测/跟踪/里程计 | 经典自动驾驶场景，传感器与道路场景有特定边界 |
| nuScenes | 多相机、LiDAR、雷达、3D detection/tracking | 多传感器自动驾驶基准；与室内 AMR 的安装/场景不同 |
| Waymo Open Dataset | 多相机/LiDAR 3D perception | 大规模自动驾驶感知基准；数据使用条款另查 |
| SemanticKITTI | LiDAR semantic segmentation | 点云逐点语义分割；数据集许可和 benchmark 协议须按官方页面核对 |
| 自采机器人数据 | 室内货架、托盘、人机共融、玻璃/反光、低矮障碍、门/电梯 | 最能覆盖目标产品域；需管理隐私、授权、标注一致性和版本 |

## 8. 端侧部署与性能测量

典型部署路径：

1. 固定训练框架、模型 checkpoint、预处理方式和数据标签映射；
2. 导出 ONNX 或目标后端格式，检查动态输入、算子支持、数值一致性；
3. 选择 FP32/FP16/INT8 等精度，进行校准和准确率回归；
4. 在目标硬件上验证图像解码、resize/letterbox、颜色空间转换、归一化、推理、NMS/后处理和消息发布；
5. 测量多路相机并发、队列长度、丢帧、时延分布、CPU/GPU/NPU 占用、内存/显存与热稳态；
6. 在量化、驱动、模型或硬件版本升级后执行回归。

**FPS 必须带条件**：准确硬件型号/功耗模式、软件/驱动/CUDA/TensorRT/RKNN 版本、模型 commit/checkpoint、输入分辨率、batch、精度、预处理/后处理是否计时、多路并发情况。不能用“Orin YOLOv8n 30–60 FPS”或“RK3588 15–30 FPS”作为产品承诺；服务器 T4 上 RT-DETR 的 TensorRT benchmark 也不能外推到 Jetson、RK3588 或实际多传感器整栈。

## 9. 机器人感知的专门要求

- **近场和低矮障碍**：桌腿、线缆、托盘叉孔、地面凸起和透明/反光材料；需结合传感器安装高度、视场/盲区和地面结构验证。
- **目标尺寸与距离**：小目标像素占比和远距离检测性能由镜头、分辨率、曝光、运动模糊与模型共同决定；不能直接照搬 COCO mAP。
- **动态人/动物**：检测之外还需要跟踪、速度/运动估计、遮挡处理与不确定性；保护功能须按风险评估设计，不应把单一视觉模型称为安全冗余。
- **机械臂交互**：目标关键点、抓取姿态和深度必须转换到机器人/末端坐标，并验证标定误差、可达性、夹爪接触与力控。
- **玻璃门/镜面/黑色物体**：不同深度技术、LiDAR 波长/材料和成像条件表现不同，需要在目标场景采样验证。
- **算力受限**：模型蒸馏、剪枝、量化、ROI/关键帧策略可优化成本，但要监控召回率和长时间漏检风险。

## 10. 验收指标与风险测试

| 任务 | 指标示例 | 必须明确的评测条件 |
|---|---|---|
| 2D/3D 检测 | mAP/AP50、按类别召回率、漏检率、误报率、小目标/距离分桶 | IoU 阈值、类别、距离、遮挡、场景、真值和样本数 |
| 分割 | mIoU、per-class IoU、mask AP、边界质量 | 类别/实例定义、忽略区域、目标尺度、分辨率 |
| 跟踪 | HOTA、IDF1、MOTA、ID switch、轨迹碎片 | 目标定义、遮挡时间、检测器阈值、匹配准则 |
| 深度 | Abs Rel、RMSE、δ 阈值、有效像素率 | 传感器真值、量程、单位、对齐与裁剪区域 |
| 点云地面/语义 | precision/recall、IoU、地面误分率 | 点云密度、雷达型号、地形/坡度、运动速度 |
| 实时性 | 端到端时延 P50/P95/P99、吞吐、丢帧/超时 | 硬件/模型/精度/分辨率/并发、预后处理计时范围 |
| 现场可靠性 | 误报/漏报按运行小时或任务数统计、重识别、故障恢复、人工接管 | 目标现场分布、试验时长、负载、照明、污损与传感器故障 |

安全相关感知要单独分析失效模式：漏检、误检、目标 ID 丢失、时间戳错位、坐标外参漂移、传感器遮挡/污损、模型超时和分布外输入。测试结果应进入风险分析和保护策略，不能只以平均 mAP 或 FPS 决定产品放行。

## 13. 本轮定向复核与未关闭事项（2026-11-03）

本轮纠正：

- 移除“现在感知主流就是深度学习”的单线叙事，保留几何点云处理、标定、跟踪和学习模型的互补关系。
- 纠正 CLIP、Grounding DINO、SAM 2、Depth Anything V2、DROID-SLAM 的任务边界；不再将 CLIP 当作直接检测框模型、SAM2 当作自带开放词汇类别的检测器、DAv2 基础 checkpoint 当作直接米制深度、DROID-SLAM 当作普通深度估计。
- 将 Ultralytics YOLO 示例更新为版本可变的模型家族，不将 YOLOv8/11 固定为长期最新版本；删除无测试条件的 Jetson Orin/RK3588 FPS。
- 删除“10ms 错位=1.5cm”作为通用同步标准，改为带速度/角速度/距离前提的小时间偏差近似式。
- 删除“后融合是 AMR 工程主流”“动态人漏检致命”“整栈<15W”“近场0.05–0.5m”“窄场景±5cm”等缺少产品/场景条件的数字或普遍断言。
- 纠正 PointPillars、OpenPCDet、Patchwork++ 的项目边界；Patchwork++ 只负责地面分割，OpenPCDet 是开发工具箱，不能将模型家族和库名混为一谈。
- 补充 detection/segmentation/tracking/depth/3D perception 各自的评估指标；避免只用 COCO mAP/FPS 做产品判断。
- 复核许可：Ultralytics 官方说明 AGPL-3.0/Enterprise 两种方案；Depth Anything V2 的代码许可与各 checkpoint 许可不同；SAM2 的代码/权重许可与数据集许可必须分开；Patchwork++、ByteTrack、GroundingDINO、OpenPCDet 和 PaddleDetection 按各自仓库 LICENSE 记录。
