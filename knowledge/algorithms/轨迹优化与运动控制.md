# 轨迹优化与运动控制（Trajectory Optimization & Motion Control）

> 本页覆盖从几何路径到可执行运动的中间层：轨迹生成/时间参数化、路径跟踪、模型预测控制（MPC）和底层执行接口。**路径、轨迹、控制命令不是同一个对象**：路径是几何位姿序列；轨迹还描述时间、速度、加速度等；控制器根据状态误差和约束生成下一步命令。不同机器人（差速底盘、阿克曼、全向底盘、机械臂、足式机器人）的模型和控制接口差异很大，没有通用的固定控制频率、加速度上限或求解器周期。

## 1. 控制对象、层级与数据接口

### 1.1 先区分四种数据

| 对象 | 含义 | 示例 |
|---|---|---|
| 几何路径（path） | 机器人应该经过的空间位姿/关节构型序列，不必包含时间信息 | nav_msgs/Path、SE(2) 位姿点、机械臂关节 waypoint |
| 时间参数化轨迹（trajectory） | 给路径/状态序列分配时间，并给出速度、加速度，必要时给 jerk/接触状态 | q(t)、q̇(t)、q̈(t)；x(t)、v(t)、a(t) |
| 参考（reference） | 当前控制周期或预测窗口内希望跟踪的目标状态/输出 | 目标线速度、角速度、关节位置/速度、末端位姿 |
| 控制命令（command） | 控制器实际输出给下游接口的指令 | Twist、关节位置/速度/力矩、驱动器电流/力矩目标 |

规划器返回一条路径，不表示其曲率、速度和加速度已满足底盘/执行器限制。轨迹平滑或时间参数化后也需要重新做碰撞、可跟踪性和制动能力检查。

### 1.2 常见控制栈

~~~text
任务/导航/操作目标
        ↓
几何路径与局部路径跟踪（例如 Nav2 Controller）
        ↓
轨迹生成/速度约束/时间参数化（视系统而定）
        ↓
底盘控制器或机械臂轨迹控制器
        ↓
ros2_control Controller Manager / 硬件接口（或厂商驱动）
        ↓
MCU / 电机驱动器 / 伺服器内部控制
        ↓
电机、电磁制动器、传动与机械本体
~~~

这是一种概念分层，不是每个产品都具有完全独立的所有层。某些底盘把速度闭环放在驱动器内，某些系统由 MCU 做轮速闭环；机械臂控制器可能直接接收关节轨迹，厂商伺服器内部再运行电流/速度/位置环。必须按实际硬件、驱动和软件接口绘制真实的数据流。

## 2. 机器人运动学与动力学模型

控制器使用的模型必须匹配机器人构型、坐标约定、驱动方式和运行范围。模型简单不代表错误；模型复杂也不自动代表更好。根据任务误差预算、速度/加速度、接触和计算资源选择。

### 2.1 差速/独轮车模型（unicycle）

平面状态可写为 (x,y,θ)，控制输入为线速度 v 和角速度 ω：

~~~text
ẋ = v cos(θ)
ẏ = v sin(θ)
θ̇ = ω
~~~

该模型适合描述差速底盘的低速平面运动学，不直接表达轮胎侧偏、轮速动态、地面打滑、制动和电机带宽。实际轮速指令需再根据轮半径、轮距、驱动方向及速度/加速度限制做逆运动学转换。

### 2.2 阿克曼/汽车式模型

简化运动学自行车模型常写为：

~~~text
ẋ = v cos(θ)
ẏ = v sin(θ)
θ̇ = (v / L) tan(δ)
~~~

其中 L 为轴距、δ 为前轮等效转角。由此可得曲率 κ=tanδ/L，最小转弯半径受最大转角、轴距、转向机构限位及轮胎/机械结构约束。

该模型不允许像差速底盘一样原地旋转；倒车时速度符号及转向/曲率方向约定需要在控制器实现中明确。若轮胎侧偏和横向动力学不可忽略，应考虑动力学自行车模型或更完整的车辆动力学模型，不能将某一简单公式直接用于所有速度/路面/载荷条件。

### 2.3 舵轮、全向与 Mecanum 底盘

全向底盘可以产生不同方向的平面速度，但其可控性由轮组布局、转向角、滚子方向、轮速范围和接触条件决定。运动学逆解将车体速度映射为各轮速度/转角；若个别轮达到限速、轮胎打滑或转向器饱和，车体速度目标就未必可实现。

不要只用状态变量 (x,y,θ,vx,vy) 就断言机器人一定能全向移动；应检查具体轮组约束、逆运动学矩阵秩、速度/加速度/转向速率限值和故障模式。

### 2.4 机械臂与关节空间

机械臂控制常使用关节状态 q、q̇，以及关节加速度、力矩和末端位姿/速度。常见层次包括：

- 关节空间位置/速度/力矩控制；
- 末端空间（Cartesian / operational-space）控制；
- 逆运动学、雅可比映射和奇异位形处理；
- 阻抗/导纳控制与接触力控制；
- 轨迹时间参数化和碰撞/关节限位检查。

机械臂的控制器、伺服器和安全功能接口因厂商差异较大。移动底盘的 cmd_vel 与机械臂的 joint trajectory/torque 命令不是可以互换的通用接口。

## 3. 路径跟踪算法

路径跟踪器根据当前状态与路径参考生成命令。其目标通常是控制横向误差、航向误差、速度误差和输入变化，同时满足机器人运动学与执行器约束。

### 3.1 Pure Pursuit（纯跟踪）

Pure Pursuit 在路径前方选择预瞄点（lookahead point），根据机器人当前位置与该点的几何关系计算需要跟踪的曲率。若路径点在机器人坐标系中坐标为 (xL,yL)，预瞄距离为 Ld=√(xL²+yL²)，一种常用曲率表达为：

~~~text
κ = 2 y_L / L_d²
~~~

差速底盘可用 ω=vκ 形成角速度命令；阿克曼模型可用 δ=arctan(Lκ) 转换为等效前轮转角。符号和坐标约定应与实现一致。

- 预瞄距离较短：跟踪更积极，但对定位噪声和路径离散化更敏感，可能产生摆动。
- 预瞄距离较长：动作通常更平滑，但可能切弯或偏离狭窄路径。
- 速度缩放预瞄：可将预瞄距离与速度关联，但需要设置上下限并结合底盘响应/控制更新率验证。

预瞄距离不是跨平台通用常数；要依据轴距/轮距、速度、路径曲率、定位噪声、控制延迟和 footprint 测试。Nav2 Regulated Pure Pursuit（RPP）在 Pure Pursuit 上增加曲率/障碍距离速度调节、可选速度缩放预瞄和前向碰撞投影检查；它仍是 Nav2 的路径跟踪控制器，不应取代安全额定防护功能。官方文档的参数默认值只是插件默认配置，必须按目标平台调优。

### 3.2 Stanley 控制器

Stanley 类控制器使用航向误差与前轴横向误差构造转向反馈。简化表达常写成：

~~~text
δ = θ_e + atan(k · e_y / (v + ε))
~~~

其中 ey 为横向误差、θe 为航向误差、v 为车辆速度，k 和 ε 为实现中的增益/数值保护项。公式符号取决于误差和转向正方向约定。

Stanley 是一种几何/反馈路径跟踪思路，不意味着只要“高速”就一定优于 Pure Pursuit。其表现仍受路径曲率、定位噪声、速度、转向速率、车辆模型和参数影响。

### 3.3 LQR 跟踪

线性二次调节器（LQR）通常从局部线性化的误差状态模型出发：

~~~text
xₖ₊₁ = Aₖ xₖ + Bₖ uₖ
~~~

并最小化二次代价：

~~~text
J = Σₖ (xₖᵀ Q xₖ + uₖᵀ R uₖ)
~~~

求得状态反馈 u_k=-K_kx_k。它适合在模型可信、误差范围有限、线性化模型有效的工作点附近进行跟踪控制。约束处理、非线性大范围运动、饱和和障碍避让需要额外设计；LQR 的“最优”只针对所定义线性模型与二次代价。

### 3.4 PID 与级联控制

PID 可用于轮速/电机速度、关节位置或其他闭环变量，但不能把一个 PID 环路当成完整的机器人运动控制器。常见工程要点：

- 先明确测量值、设定值、单位、采样时间和执行器输出；
- 分别处理比例、积分、微分项与噪声滤波，检查积分饱和（anti-windup）；
- 速度前馈、加速度前馈和摩擦补偿可能比单纯增加反馈增益更有效；
- 级联控制（例如位置外环、速度内环）需要确定带宽分离、限幅和接口时序；
- 当执行器、驱动器内部已经有闭环时，外部再叠一层相同控制环可能引入耦合或振荡。

不能用“P 大啸叫就降 P 加 D”代替诊断；机械共振、编码器噪声、采样/通信延迟、电流限幅、传动间隙和驱动器内环都可能导致类似症状。

## 4. 轨迹生成、平滑与时间参数化

### 4.1 从路径到轨迹

设几何路径由弧长参数 s 表示，s(t) 是沿路径的位置进度。时间参数化要为其分配速度、加速度和必要的 jerk：

~~~text
v = ṡ      a = s̈      j = s⃛
~~~

对于曲率为 κ(s) 的平面路径，横向/向心加速度约束常写作：

~~~text
|a_lat| = v² |κ| ≤ a_lat,max
~~~

因此在曲率较大处通常需要降低速度。实际还需考虑纵向加速度、制动能力、坡度、载荷、摩擦、轮胎/轮地接触、转向器速度限制和驱动器饱和。

### 4.2 常见轨迹处理

- **曲线平滑**：B-spline、Bezier、圆弧/Clothoid 等可用于减小离散路径的方向/曲率不连续；平滑后必须重新检查碰撞和通道边界，因为拟合曲线可能切入障碍或未知区域。
- **速度剖面**：梯形速度、三角速度或 S-curve 速度剖面用于在速度/加速度/jerk 约束内规划运动时间。
- **时间最优参数化**：在路径形状固定时，根据速度、加速度、动力学/执行器限制为路径分配时间；是否能保证全局时间最优取决于模型和求解方法。
- **轨迹优化**：可同时优化路径形状、时间、障碍间距、能耗或平滑度；代价项与约束必须有明确单位/尺度，不能把软惩罚当成硬安全约束。

平滑后的路径仍需经过真实机器人 footprint 的碰撞检查、定位不确定性裕度、曲率/转向限值和下游控制可跟踪性验证。

## 5. 模型预测控制（MPC）

### 5.1 工作机制

MPC 在每个控制时刻基于状态估计、动力学模型和未来参考，求解有限预测时域内的控制序列；只执行最前面的控制量，随后读取新状态并再次优化（receding horizon）。

典型目标由状态误差、控制量、控制增量、终端代价等组成：

~~~text
minimize over x[0:N], u[0:N-1]:
  Σ(k=0..N-1) [
    (x[k]-x_ref[k])ᵀ Q (x[k]-x_ref[k])
  + (u[k]-u_ref[k])ᵀ R (u[k]-u_ref[k])
  + (u[k]-u[k-1])ᵀ S (u[k]-u[k-1])
  ]
  + (x[N]-x_ref[N])ᵀ Q_f (x[N]-x_ref[N])
~~~

常见约束包括状态/关节边界、速度/加速度、转向/力矩限制、动力学方程、障碍物距离和终端条件。具体模型、状态和控制量由移动底盘、机械臂或足式机器人的任务决定。

MPC 的效果和计算量依赖预测时域、离散步长、变量维数、动力学模型、障碍约束、求解器、warm start、初值和目标硬件。MPC 并不自动“最强”或“适合所有动态避障”；求解超时、模型不匹配或约束不可行时必须定义可验证的退化/停止策略。

### 5.2 QP 求解器和非线性 OCP 求解器不是一回事

| 工具 | 问题类型/特征 | 适用边界 |
|---|---|---|
| OSQP | 求解凸二次规划（convex QP），形式为二次目标 + 线性约束；采用 ADMM 类方法 | 适合线性 MPC、凸化后的局部 QP 等；不能直接把一般非线性最优控制问题原样交给 OSQP 求解 |
| acados | 面向最优控制结构的数值优化软件，支持非线性 OCP/NLP、SQP 类方法、multiple shooting 和嵌入式求解流程 | 可用于 NMPC/MHE，但需要模型/导数/离散化/约束与目标平台配置；“为实时应用设计”不是所有问题都能达到指定周期的保证 |

OSQP 官方定义的目标是凸二次规划 1/2 xᵀPx+qᵀx，其中 P 半正定；acados 官方 README 则将其定位为用于非线性最优控制问题的求解框架。两者不能被简化成“OSQP 100Hz、acados 1kHz 都绰绰有余”。

## 6. ROS 2 与底层控制接口

ROS 2 中 ros2_control 的 Controller Manager 管理控制器生命周期、硬件接口和控制更新循环；update_rate 由配置决定。官方文档说明其主线程会尝试配置 SCHED_FIFO 实时调度策略，但实际确定性仍取决于内核、权限、CPU/IRQ 亲和性、内存锁定、线程负载、硬件驱动和测量验证。

接口检查清单：

1. **命令定义**：Twist 的 frame、单位、线/角速度含义，或者机械臂 joint trajectory/effort 的关节顺序和控制模式。
2. **更新频率**：由 Controller Manager、控制器、驱动器和硬件各自配置；不要把某个机器人上的电流环/速度环频率写成所有产品的标准。
3. **命令限幅**：URDF/控制器/硬件接口中的速度、加速度、effort/position 限值是否一致；命令是否会被平滑器、控制器或驱动器再次限幅。
4. **时序与 watchdog**：记录状态采样、控制计算、通信、驱动接收和制动响应的端到端延迟分布；超时阈值根据最坏/高分位时延、机器人速度和风险分析确定。
5. **执行器反馈**：监测编码器/电流/温度/故障标志、跟踪误差、饱和和控制器退出；命令发布成功不等于执行器按期完成运动。
6. **安全接口**：急停、保护停止、STO/制动器和安全扫描仪由独立安全架构处理；普通 ROS 控制循环和 watchdog 不构成安全认证。

ros2_control 官方文档特别建议在仿真中验证 fallback controllers，因为 fallback 激活仍取决于状态/命令接口是否可用。实际项目需要在目标硬件和故障场景中验证。

## 7. 足式/人形机器人运动控制

足式与人形机器人包含浮动基座、多接触状态切换、质心动力学、摩擦锥、关节限位和全身任务优先级，不能直接套用差速底盘的 Pure Pursuit 或速度 PID。

### 7.1 经典分层控制

- **步态/接触规划**：定义支撑脚、摆动脚、接触序列、落脚点或足端轨迹。
- **质心/动量规划**：基于简化质心模型或 centroidal dynamics 预测质心、角动量和接触力。
- **ZMP 方法**：在适用的平面接触/支撑多边形假设下使用零力矩点作为稳定性相关量；不能把它当成所有动态跑跳/多接触任务的完整模型。
- **WBC（Whole-Body Control）**：在全身动力学、接触约束和任务优先级下求解关节加速度/接触力等控制量；常见实现可用 QP，但具体变量和约束随机器人及控制架构而变。
- **关节伺服/驱动器**：把控制量转换为关节位置、速度或力矩命令，并处理电机/减速器限制。

### 7.2 学习型策略与模型控制

RL 策略可以用于步态、地形适应或残差控制；模型预测控制、WBC 与 RL 也可以组合。不能笼统说“2024–2026 RL 已成足式控制主流”，也不能认为仿真训练的关节目标就能直接作为安全的执行器命令。需考虑状态估计、接触检测、关节/力矩限制、域随机化、仿真差异、训练数据覆盖和独立安全保护。见 [[学习型机器人算法]]。

## 8. 常见问题与诊断

| 现象 | 可能原因 | 检查方向 |
|---|---|---|
| 路径跟踪摆动 | 预瞄参数不匹配、定位噪声、路径曲率突变、延迟或速度环响应不足 | 记录横向/航向误差、曲率、命令/实际速度、时间戳与频率 |
| 切弯/偏离窄道 | 预瞄过长、足迹没有纳入跟踪约束、路径与速度剖面不一致 | 检查 footprint、lookahead、路径离散与碰撞预测 |
| 控制器过冲 | 积分饱和、制动/加速度模型错误、命令延迟、速度限制位置不一致 | 检查 PID 输出、限幅、anti-windup、驱动器反馈和实际制动 |
| MPC 超时/不可行 | 预测模型误差、初值差、约束冲突、问题规模过大、求解器数值问题 | 记录求解状态、迭代数、残差、warm start、求解耗时和 infeasible 状态 |
| 机械臂振动/力控不稳 | 刚度/阻尼设置、接触估计、力传感器噪声、雅可比奇异、伺服器内外环耦合 | 检查力/位姿反馈、坐标变换、滤波、关节限位和驱动器模式 |
| 足式接触切换失败 | 接触时序/估计不准、摩擦模型不匹配、力限幅、状态估计漂移 | 检查足端接触状态、质心/动量预测、接触力和地面条件 |

## 12. 求解器状态、异步控制与时间参数化的验收边界（2026-11-05）

### 12.1 OSQP 求解状态必须进入控制状态机

OSQP求解的是凸二次规划（QP），其模型形式为半正定二次目标与线性约束。控制应用不能把“调用成功”或“返回了数值”当作“得到可直接执行的最优控制量”。至少区分：

- `solved` 与 `solved inaccurate`：后者按更宽松容差判定，是否可接受必须由控制误差预算和约束余量决定。
- `primal infeasible` / `dual infeasible`：问题不可行或目标无界，需要回溯约束、边界和模型构造。
- `maximum iterations reached` / `run time limit reached` / `unsolved`：没有正常求解完成；控制器必须定义丢弃本次结果、使用经过验证的备用策略或进入受控安全状态的条件。
- `non convex`：模型不满足求解器凸性要求；OSQP提示轻微非凸可能无法可靠检测，建模方仍需独立检查矩阵性质。

建议将求解器状态、迭代数、原始/对偶残差、求解耗时、约束违反量、上次有效解时间戳和fallback状态写入诊断记录。Warm start、固定稀疏结构、代码生成或设置time limit可能改善特定工作负载表现，但不自动证明最坏执行时间或控制安全性。<Cite refs={["turn838075search3","turn963615view2","turn838075search7"]}/>

### 12.2 ros2_control 异步更新会改变数据新鲜度与调度语义

Controller Manager的`update_rate`定义其主控制循环频率；不意味着每个控制器必然以相同频率同步执行。ros2_control支持控制器异步更新，并可单独设置`update_rate`、线程优先级和CPU affinity。Jazzy官方文档明确说明：若异步控制器上一轮`update()`尚未完成，下一次触发会复用上一结果并报告missed update cycles；异常仍可能导致控制器被deactivate。<Cite refs={["turn963615view0","turn963615view1"]}/>

工程设计需显式检查：
- 控制器输出是否带状态采样时间、计算完成时间和有效期；复用上一结果时命令是否过期。
- 异步线程优先级/CPU affinity是否与Controller Manager、硬件read/write、IRQ及其他实时线程形成可分析的资源分配。
- 控制器更新频率低于主循环时，保持上一命令是否符合系统动态和安全需求；位置、速度、力矩和接触控制不能一概而论。
- missed-cycle计数、执行时间分布、抖动、异常退出和fallback激活条件是否可观测；fallback接口故障时是否仍可用。
- 异步硬件组件read/write与控制器线程之间是否存在数据竞争、缓冲积压或时序错配。

异步执行是隔离较长计算对主循环的直接阻塞，不是让超时计算自动满足实时期限，也不等于安全fallback已通过验证。版本差异必须按目标ROS发行版文档核对。

### 12.3 时间参数化的“最优”受约束模型限定

固定几何路径上的时间最优路径参数化（TOPP）需要明确输入路径、边界条件和约束集合。TOPP-RA等方法可在其建模约束范围内求取路径速度参数；不能仅凭算法名称推断它自动覆盖所有关节/电机力矩、热限制、接触摩擦、jerk、制动器能力、载荷变化或整机安全约束。ROS Index当前快照将toppra列为维护中并提供0.6.10包版本，同时提示Python支持将被移除、建议考虑C++版本；实际部署需核对发行版、源码版本和语言绑定。<Cite refs={["turn963615view4","turn838075search2"]}/>

每个时间参数化方案应记录：
1. 几何路径及其坐标系、单位、连续性和碰撞/可达性验证结果；
2. 起止速度/加速度及中间waypoint是否要求停车；
3. 速度、加速度、jerk、力矩/功率、关节限位、接触/摩擦等实际纳入和未纳入的约束；
4. 约束来源是制造商额定值、辨识模型、在线估计还是经验值，并记录载荷、温度、电压和磨损等适用条件；
5. 离散化、网格、求解容差、数值失败处理、输出轨迹重新碰撞检查与下游可跟踪性验证。

“时间最优”只对所给路径、边界条件、约束模型和数值求解设定成立；约束不完整或参数不可信时，结果不代表真实机器人最快可行运动。

### 12.4 RPP前向碰撞投影不是动态环境预测或安全额定保护

Nav2 Regulated Pure Pursuit可沿当前命令的运动方向投影机器人footprint，并使用costmap进行前向碰撞检查；投影受时间上限和lookahead carrot距离等参数限制。该功能依赖传感器输入、costmap更新、footprint、TF、机器人模型和控制器执行链。它不是对动态障碍未来轨迹的完整预测，也不能覆盖传感器盲区、数据过期、CPU失效或独立制动链故障；不能替代安全额定扫描仪、安全控制器、保护停止或STO。参数默认值不是产品验收阈值。<Cite refs={["turn963615view3"]}/>

## 13. PID 闭环的离散实现、饱和处理与验收方法（2026-11-06）

本节给出可用于轮速、关节位置/速度等单输入单输出闭环的工程化检查框架。它不规定通用增益或控制频率；具体控制对象、驱动器内部环路、传感器分辨率、采样周期和执行器能力必须由目标系统确定。

### 13.1 先固定信号方向、单位和离散时间

定义设定值 (r_k)、测量值 (y_k)、误差 (e_k=r_k-y_k)、控制输出 (u_k)，采样间隔 (T_s)。开始调参前必须记录：

- 变量物理意义和单位，例如 rad、rad/s、m/s、N·m；位置/速度/电流量不能混用。
- 正方向、编码器计数方向、电机相序/驱动器方向和反馈符号；小幅正向命令应得到预期方向的测量变化。
- 控制器实际执行时间戳、采样周期分布、数据年龄和输出有效期，而不只是配置中的目标频率。
- 控制输出的物理含义、上下限、变化率限制，以及驱动器内部是否已经闭合电流/速度/位置环。

若反馈符号错误，增大比例增益会形成正反馈；这不是通过重新调参可以修复的问题。

### 13.2 位置式 PID 的一种离散表达

一种常见的离散实现可写为：

```text
e[k] = r[k] - y[k]
P[k] = Kp * e[k]
I*[k+1] = I[k] + Ki * Ts * e[k]
D[k] = -Kd * (y[k] - y[k-1]) / Ts
u*[k] = P[k] + I[k] + D[k] + uff[k]
u[k] = limit(u*[k], u_min, u_max)
```

这里对测量值求微分（derivative on measurement），可避免设定值阶跃直接在微分项产生 derivative kick。上式是说明结构的基础形式，不包含微分滤波、抗积分饱和、输出变化率限制和离散实现细节；不能直接作为所有驱动器的生产代码。

参数量纲必须与误差和输出单位匹配。例如当误差单位为 rad、输出为 N·m 时，(K_p) 的量纲为 N·m/rad；积分和微分增益的量纲还分别包含时间因子。禁止脱离单位和采样周期比较不同项目的数值增益。

### 13.3 微分滤波与噪声

数值微分会放大高频测量噪声。工程实现通常需要对微分通道低通滤波，或使用带滤波的微分状态；滤波参数必须结合采样周期、传感器噪声和闭环带宽确定。滤波太弱可能放大编码器量化/噪声，滤波太强则增加相位滞后。

验收时应同时记录原始测量、滤波后测量、微分项和输出，避免仅看最终位置曲线而无法定位噪声来源。对低分辨率编码器，速度估计方法和更新窗口本身也会引入延迟。

### 13.4 输出饱和与 anti-windup

执行器存在电流、速度、力矩、驱动器内部限幅和供电限制。若积分器持续按未受限误差累积，而实际输出已经饱和，解除饱和后可能产生长时间过冲。至少应选用并验证一种 anti-windup 策略：

- **条件积分（conditional integration）**：输出已饱和且误差继续推动输出向饱和方向时，暂停该方向的积分；当误差有助于退出饱和时允许积分恢复。
- **反算回馈（back-calculation）**：将受限输出与未受限输出之差反馈至积分状态，例如
  ```text
  I[k+1] = I[k] + Ki*Ts*e[k] + Kaw*Ts*(u[k] - u*[k])
  ```
  其中 (K_{aw}) 的取值和离散实现需与控制器结构匹配，不能套用未经验证的固定值。

必须区分控制器软件限幅与驱动器内部实际限幅；若驱动器内部限幅不可观测，软件 anti-windup 可能仍无法准确反映真实执行输出。若同时存在幅值限制和 slew-rate 限制，应定义 anti-windup 使用哪个实际受限信号，并测试两种限制共同作用时的状态行为。

### 13.5 前馈、级联与模式切换

- **前馈**：速度/加速度前馈、重力补偿或摩擦补偿可减轻反馈误差，但依赖模型和标定；模型误差可能导致稳态偏差或反向扰动。
- **级联控制**：例如位置外环输出速度参考、速度内环输出力矩/电流参考。每层都要定义单位、限幅、更新周期、数据时间戳和失效行为；内环通常需要比外环更快，但带宽间隔必须根据对象动态和采样/延迟分析，不能使用固定倍数作为通用规则。
- **无扰切换（bumpless transfer）**：手动/自动、不同控制器或控制模式切换时，应使积分状态与当前实际输出协调。一个可能的初始化思路是令积分项补足当前输出与 P/D/前馈项之间的差额；具体计算必须考虑输出限幅和内部驱动器状态。
- **复位与重启**：明确积分状态何时清零、何时保持、何时按当前输出重建；编码器重置、驱动器重新使能、控制器 deactivate/activate 和故障恢复不能共享一个未经分析的默认策略。

### 13.6 调试与验收顺序

建议按以下顺序执行并归档原始数据：

1. **静态方向/单位检查**：断开危险运动或使用受控台架，验证反馈符号、单位、零点、编码器方向和输出极性。
2. **开环/低能量检查**：在批准的安全工况下确认执行器响应、死区、摩擦、饱和、延迟和传感器噪声。
3. **P 项基线**：从受控小幅输入开始，观察稳态误差、振荡、结构共振和限幅；不以单一阶跃响应替代完整工况。
4. **I 项与抗饱和**：测试负载扰动、持续偏差、长时间饱和及解除饱和后的恢复。
5. **D 项/滤波**：测试测量噪声、量化、速度估计延迟和设定值变化，确认微分冲击和噪声放大受控。
6. **前馈/级联**：逐层启用并检查环路交互、带宽、限幅传播和更新时序。
7. **故障与边界**：注入传感器超时/跳变、命令过期、执行器饱和、控制周期抖动、驱动器故障、模式切换和控制器重启，验证输出是否被拒绝、保持、降级或进入经设计的安全状态。
8. **工况矩阵**：覆盖空载/额定及允许载荷、速度范围、方向变化、温度/电压范围、不同地面/摩擦状态和重复运行；只测试经过风险评估批准的范围。

至少记录设定值/测量值/误差/控制输出/饱和标志/积分状态/时间戳/周期抖动/驱动器反馈/故障码，并报告超调、稳态误差、上升/调节时间、跟踪误差、饱和持续时间、恢复时间和异常次数。指标定义、滤波、统计窗口和工况必须固定，不能只挑选成功曲线。

### 13.7 控制器失败语义与安全边界

- 测量值 NaN/Inf、时间戳倒退、数据超时、输出越界或计算异常时，必须定义明确的拒绝/降级路径；不能静默地把无效值送入驱动器。
- 控制器计算失败时保持上一命令是否安全，取决于被控对象和命令类型；对速度、力矩、位置保持和接触控制不能一概而论。
- 软件 PID 的输出归零不必然等于机械停止；制动器、驱动器使能、STO、安全 PLC 和机械保持装置属于不同层级。
