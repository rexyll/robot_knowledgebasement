# 轨迹优化与运动控制（Trajectory Optimization & Motion Control）

> 本页覆盖从几何路径到可执行运动的中间层：轨迹生成/时间参数化、路径跟踪、模型预测控制（MPC）和底层执行接口。**路径、轨迹、控制命令不是同一个对象**：路径是几何位姿序列；轨迹还描述时间、速度、加速度等；控制器根据状态误差和约束生成下一步命令。不同机器人（差速底盘、阿克曼、全向底盘、机械臂、足式机器人）的模型和控制接口差异很大，没有通用的固定控制频率、加速度上限或求解器周期。

## 1. 控制对象、层级与数据接口

### 1.1 先区分四种数据

| 对象 | 含义 | 示例 |
|---|---|---|
| 几何路径（path） | 机器人应该经过的空间位姿/关节构型序列，不必包含时间信息 | nav_msgs/Path、SE(2) 位姿点、机械臂关节 waypoint |
| 时间参数化轨迹（trajectory） | 给路径/状态序列分配时间，并给出速度、加速度，必要时给 jerk/接触状态 | q(t)、q̇(t)、q̈(t)；x(t)、v(t)、a(t) |
| 参考（reference） | 当前控制周期或预测窗口内希望跟踪的目标状态/输出 | 目标线速度、角速度、关节位置/速度、末端位姿 |
| 控制命令（command） | 控制器实际输出给下游接口的指令 | Twist、关节位置/速度/力矩、驱动器电流/力矩目标 |

规划器返回一条路径，不表示其曲率、速度和加速度已满足底盘/执行器限制。轨迹平滑或时间参数化后也需要重新做碰撞、可跟踪性和制动能力检查。

### 1.2 常见控制栈

~~~text
任务/导航/操作目标
        ↓
几何路径与局部路径跟踪（例如 Nav2 Controller）
        ↓
轨迹生成/速度约束/时间参数化（视系统而定）
        ↓
底盘控制器或机械臂轨迹控制器
        ↓
ros2_control Controller Manager / 硬件接口（或厂商驱动）
        ↓
MCU / 电机驱动器 / 伺服器内部控制
        ↓
电机、电磁制动器、传动与机械本体
~~~

这是一种概念分层，不是每个产品都具有完全独立的所有层。某些底盘把速度闭环放在驱动器内，某些系统由 MCU 做轮速闭环；机械臂控制器可能直接接收关节轨迹，厂商伺服器内部再运行电流/速度/位置环。必须按实际硬件、驱动和软件接口绘制真实的数据流。

## 2. 机器人运动学与动力学模型

控制器使用的模型必须匹配机器人构型、坐标约定、驱动方式和运行范围。模型简单不代表错误；模型复杂也不自动代表更好。根据任务误差预算、速度/加速度、接触和计算资源选择。

### 2.1 差速/独轮车模型（unicycle）

平面状态可写为 (x,y,θ)，控制输入为线速度 v 和角速度 ω：

~~~text
ẋ = v cos(θ)
ẏ = v sin(θ)
θ̇ = ω
~~~

该模型适合描述差速底盘的低速平面运动学，不直接表达轮胎侧偏、轮速动态、地面打滑、制动和电机带宽。实际轮速指令需再根据轮半径、轮距、驱动方向及速度/加速度限制做逆运动学转换。

### 2.2 阿克曼/汽车式模型

简化运动学自行车模型常写为：

~~~text
ẋ = v cos(θ)
ẏ = v sin(θ)
θ̇ = (v / L) tan(δ)
~~~

其中 L 为轴距、δ 为前轮等效转角。由此可得曲率 κ=tanδ/L，最小转弯半径受最大转角、轴距、转向机构限位及轮胎/机械结构约束。

该模型不允许像差速底盘一样原地旋转；倒车时速度符号及转向/曲率方向约定需要在控制器实现中明确。若轮胎侧偏和横向动力学不可忽略，应考虑动力学自行车模型或更完整的车辆动力学模型，不能将某一简单公式直接用于所有速度/路面/载荷条件。

### 2.3 舵轮、全向与 Mecanum 底盘

全向底盘可以产生不同方向的平面速度，但其可控性由轮组布局、转向角、滚子方向、轮速范围和接触条件决定。运动学逆解将车体速度映射为各轮速度/转角；若个别轮达到限速、轮胎打滑或转向器饱和，车体速度目标就未必可实现。

不要只用状态变量 (x,y,θ,vx,vy) 就断言机器人一定能全向移动；应检查具体轮组约束、逆运动学矩阵秩、速度/加速度/转向速率限值和故障模式。

### 2.4 机械臂与关节空间

机械臂控制常使用关节状态 q、q̇，以及关节加速度、力矩和末端位姿/速度。常见层次包括：

- 关节空间位置/速度/力矩控制；
- 末端空间（Cartesian / operational-space）控制；
- 逆运动学、雅可比映射和奇异位形处理；
- 阻抗/导纳控制与接触力控制；
- 轨迹时间参数化和碰撞/关节限位检查。

机械臂的控制器、伺服器和安全功能接口因厂商差异较大。移动底盘的 cmd_vel 与机械臂的 joint trajectory/torque 命令不是可以互换的通用接口。

## 3. 路径跟踪算法

路径跟踪器根据当前状态与路径参考生成命令。其目标通常是控制横向误差、航向误差、速度误差和输入变化，同时满足机器人运动学与执行器约束。

### 3.1 Pure Pursuit（纯跟踪）

Pure Pursuit 在路径前方选择预瞄点（lookahead point），根据机器人当前位置与该点的几何关系计算需要跟踪的曲率。若路径点在机器人坐标系中坐标为 (xL,yL)，预瞄距离为 Ld=√(xL²+yL²)，一种常用曲率表达为：

~~~text
κ = 2 y_L / L_d²
~~~

差速底盘可用 ω=vκ 形成角速度命令；阿克曼模型可用 δ=arctan(Lκ) 转换为等效前轮转角。符号和坐标约定应与实现一致。

- 预瞄距离较短：跟踪更积极，但对定位噪声和路径离散化更敏感，可能产生摆动。
- 预瞄距离较长：动作通常更平滑，但可能切弯或偏离狭窄路径。
- 速度缩放预瞄：可将预瞄距离与速度关联，但需要设置上下限并结合底盘响应/控制更新率验证。

预瞄距离不是跨平台通用常数；要依据轴距/轮距、速度、路径曲率、定位噪声、控制延迟和 footprint 测试。Nav2 Regulated Pure Pursuit（RPP）在 Pure Pursuit 上增加曲率/障碍距离速度调节、可选速度缩放预瞄和前向碰撞投影检查；它仍是 Nav2 的路径跟踪控制器，不应取代安全额定防护功能。官方文档的参数默认值只是插件默认配置，必须按目标平台调优。

### 3.2 Stanley 控制器

Stanley 类控制器使用航向误差与前轴横向误差构造转向反馈。简化表达常写成：

~~~text
δ = θ_e + atan(k · e_y / (v + ε))
~~~

其中 ey 为横向误差、θe 为航向误差、v 为车辆速度，k 和 ε 为实现中的增益/数值保护项。公式符号取决于误差和转向正方向约定。

Stanley 是一种几何/反馈路径跟踪思路，不意味着只要“高速”就一定优于 Pure Pursuit。其表现仍受路径曲率、定位噪声、速度、转向速率、车辆模型和参数影响。

### 3.3 LQR 跟踪

线性二次调节器（LQR）通常从局部线性化的误差状态模型出发：

~~~text
xₖ₊₁ = Aₖ xₖ + Bₖ uₖ
~~~

并最小化二次代价：

~~~text
J = Σₖ (xₖᵀ Q xₖ + uₖᵀ R uₖ)
~~~

求得状态反馈 u_k=-K_kx_k。它适合在模型可信、误差范围有限、线性化模型有效的工作点附近进行跟踪控制。约束处理、非线性大范围运动、饱和和障碍避让需要额外设计；LQR 的“最优”只针对所定义线性模型与二次代价。

### 3.4 PID 与级联控制

PID 可用于轮速/电机速度、关节位置或其他闭环变量，但不能把一个 PID 环路当成完整的机器人运动控制器。常见工程要点：

- 先明确测量值、设定值、单位、采样时间和执行器输出；
- 分别处理比例、积分、微分项与噪声滤波，检查积分饱和（anti-windup）；
- 速度前馈、加速度前馈和摩擦补偿可能比单纯增加反馈增益更有效；
- 级联控制（例如位置外环、速度内环）需要确定带宽分离、限幅和接口时序；
- 当执行器、驱动器内部已经有闭环时，外部再叠一层相同控制环可能引入耦合或振荡。

不能用“P 大啸叫就降 P 加 D”代替诊断；机械共振、编码器噪声、采样/通信延迟、电流限幅、传动间隙和驱动器内环都可能导致类似症状。

## 4. 轨迹生成、平滑与时间参数化

### 4.1 从路径到轨迹

设几何路径由弧长参数 s 表示，s(t) 是沿路径的位置进度。时间参数化要为其分配速度、加速度和必要的 jerk：

~~~text
v = ṡ      a = s̈      j = s⃛
~~~

对于曲率为 κ(s) 的平面路径，横向/向心加速度约束常写作：

~~~text
|a_lat| = v² |κ| ≤ a_lat,max
~~~

因此在曲率较大处通常需要降低速度。实际还需考虑纵向加速度、制动能力、坡度、载荷、摩擦、轮胎/轮地接触、转向器速度限制和驱动器饱和。

### 4.2 常见轨迹处理

- **曲线平滑**：B-spline、Bezier、圆弧/Clothoid 等可用于减小离散路径的方向/曲率不连续；平滑后必须重新检查碰撞和通道边界，因为拟合曲线可能切入障碍或未知区域。
- **速度剖面**：梯形速度、三角速度或 S-curve 速度剖面用于在速度/加速度/jerk 约束内规划运动时间。
- **时间最优参数化**：在路径形状固定时，根据速度、加速度、动力学/执行器限制为路径分配时间；是否能保证全局时间最优取决于模型和求解方法。
- **轨迹优化**：可同时优化路径形状、时间、障碍间距、能耗或平滑度；代价项与约束必须有明确单位/尺度，不能把软惩罚当成硬安全约束。

平滑后的路径仍需经过真实机器人 footprint 的碰撞检查、定位不确定性裕度、曲率/转向限值和下游控制可跟踪性验证。

## 5. 模型预测控制（MPC）

### 5.1 工作机制

MPC 在每个控制时刻基于状态估计、动力学模型和未来参考，求解有限预测时域内的控制序列；只执行最前面的控制量，随后读取新状态并再次优化（receding horizon）。

典型目标由状态误差、控制量、控制增量、终端代价等组成：

~~~text
minimize over x[0:N], u[0:N-1]:
  Σ(k=0..N-1) [
    (x[k]-x_ref[k])ᵀ Q (x[k]-x_ref[k])
  + (u[k]-u_ref[k])ᵀ R (u[k]-u_ref[k])
  + (u[k]-u[k-1])ᵀ S (u[k]-u[k-1])
  ]
  + (x[N]-x_ref[N])ᵀ Q_f (x[N]-x_ref[N])
~~~

常见约束包括状态/关节边界、速度/加速度、转向/力矩限制、动力学方程、障碍物距离和终端条件。具体模型、状态和控制量由移动底盘、机械臂或足式机器人的任务决定。

MPC 的效果和计算量依赖预测时域、离散步长、变量维数、动力学模型、障碍约束、求解器、warm start、初值和目标硬件。MPC 并不自动“最强”或“适合所有动态避障”；求解超时、模型不匹配或约束不可行时必须定义可验证的退化/停止策略。

### 5.2 QP 求解器和非线性 OCP 求解器不是一回事

| 工具 | 问题类型/特征 | 适用边界 |
|---|---|---|
| OSQP | 求解凸二次规划（convex QP），形式为二次目标 + 线性约束；采用 ADMM 类方法 | 适合线性 MPC、凸化后的局部 QP 等；不能直接把一般非线性最优控制问题原样交给 OSQP 求解 |
| acados | 面向最优控制结构的数值优化软件，支持非线性 OCP/NLP、SQP 类方法、multiple shooting 和嵌入式求解流程 | 可用于 NMPC/MHE，但需要模型/导数/离散化/约束与目标平台配置；“为实时应用设计”不是所有问题都能达到指定周期的保证 |

OSQP 官方定义的目标是凸二次规划 1/2 xᵀPx+qᵀx，其中 P 半正定；acados 官方 README 则将其定位为用于非线性最优控制问题的求解框架。两者不能被简化成“OSQP 100Hz、acados 1kHz 都绰绰有余”。

## 6. ROS 2 与底层控制接口

ROS 2 中 ros2_control 的 Controller Manager 管理控制器生命周期、硬件接口和控制更新循环；update_rate 由配置决定。官方文档说明其主线程会尝试配置 SCHED_FIFO 实时调度策略，但实际确定性仍取决于内核、权限、CPU/IRQ 亲和性、内存锁定、线程负载、硬件驱动和测量验证。

接口检查清单：

1. **命令定义**：Twist 的 frame、单位、线/角速度含义，或者机械臂 joint trajectory/effort 的关节顺序和控制模式。
2. **更新频率**：由 Controller Manager、控制器、驱动器和硬件各自配置；不要把某个机器人上的电流环/速度环频率写成所有产品的标准。
3. **命令限幅**：URDF/控制器/硬件接口中的速度、加速度、effort/position 限值是否一致；命令是否会被平滑器、控制器或驱动器再次限幅。
4. **时序与 watchdog**：记录状态采样、控制计算、通信、驱动接收和制动响应的端到端延迟分布；超时阈值根据最坏/高分位时延、机器人速度和风险分析确定。
5. **执行器反馈**：监测编码器/电流/温度/故障标志、跟踪误差、饱和和控制器退出；命令发布成功不等于执行器按期完成运动。
6. **安全接口**：急停、保护停止、STO/制动器和安全扫描仪由独立安全架构处理；普通 ROS 控制循环和 watchdog 不构成安全认证。

ros2_control 官方文档特别建议在仿真中验证 fallback controllers，因为 fallback 激活仍取决于状态/命令接口是否可用。实际项目需要在目标硬件和故障场景中验证。

## 7. 足式/人形机器人运动控制

足式与人形机器人包含浮动基座、多接触状态切换、质心动力学、摩擦锥、关节限位和全身任务优先级，不能直接套用差速底盘的 Pure Pursuit 或速度 PID。

### 7.1 经典分层控制

- **步态/接触规划**：定义支撑脚、摆动脚、接触序列、落脚点或足端轨迹。
- **质心/动量规划**：基于简化质心模型或 centroidal dynamics 预测质心、角动量和接触力。
- **ZMP 方法**：在适用的平面接触/支撑多边形假设下使用零力矩点作为稳定性相关量；不能把它当成所有动态跑跳/多接触任务的完整模型。
- **WBC（Whole-Body Control）**：在全身动力学、接触约束和任务优先级下求解关节加速度/接触力等控制量；常见实现可用 QP，但具体变量和约束随机器人及控制架构而变。
- **关节伺服/驱动器**：把控制量转换为关节位置、速度或力矩命令，并处理电机/减速器限制。

### 7.2 学习型策略与模型控制

RL 策略可以用于步态、地形适应或残差控制；模型预测控制、WBC 与 RL 也可以组合。不能笼统说“2024–2026 RL 已成足式控制主流”，也不能认为仿真训练的关节目标就能直接作为安全的执行器命令。需考虑状态估计、接触检测、关节/力矩限制、域随机化、仿真差异、训练数据覆盖和独立安全保护。见 [[学习型机器人算法]]。

## 8. 常见问题与诊断

| 现象 | 可能原因 | 检查方向 |
|---|---|---|
| 路径跟踪摆动 | 预瞄参数不匹配、定位噪声、路径曲率突变、延迟或速度环响应不足 | 记录横向/航向误差、曲率、命令/实际速度、时间戳与频率 |
| 切弯/偏离窄道 | 预瞄过长、足迹没有纳入跟踪约束、路径与速度剖面不一致 | 检查 footprint、lookahead、路径离散与碰撞预测 |
| 控制器过冲 | 积分饱和、制动/加速度模型错误、命令延迟、速度限制位置不一致 | 检查 PID 输出、限幅、anti-windup、驱动器反馈和实际制动 |
| MPC 超时/不可行 | 预测模型误差、初值差、约束冲突、问题规模过大、求解器数值问题 | 记录求解状态、迭代数、残差、warm start、求解耗时和 infeasible 状态 |
| 机械臂振动/力控不稳 | 刚度/阻尼设置、接触估计、力传感器噪声、雅可比奇异、伺服器内外环耦合 | 检查力/位姿反馈、坐标变换、滤波、关节限位和驱动器模式 |
| 足式接触切换失败 | 接触时序/估计不准、摩擦模型不匹配、力限幅、状态估计漂移 | 检查足端接触状态、质心/动量预测、接触力和地面条件 |

## 12. 求解器状态、异步控制与时间参数化的验收边界（2026-11-05）

### 12.1 OSQP 求解状态必须进入控制状态机

OSQP求解的是凸二次规划（QP），其模型形式为半正定二次目标与线性约束。控制应用不能把“调用成功”或“返回了数值”当作“得到可直接执行的最优控制量”。至少区分：

- `solved` 与 `solved inaccurate`：后者按更宽松容差判定，是否可接受必须由控制误差预算和约束余量决定。
- `primal infeasible` / `dual infeasible`：问题不可行或目标无界，需要回溯约束、边界和模型构造。
- `maximum iterations reached` / `run time limit reached` / `unsolved`：没有正常求解完成；控制器必须定义丢弃本次结果、使用经过验证的备用策略或进入受控安全状态的条件。
- `non convex`：模型不满足求解器凸性要求；OSQP提示轻微非凸可能无法可靠检测，建模方仍需独立检查矩阵性质。

建议将求解器状态、迭代数、原始/对偶残差、求解耗时、约束违反量、上次有效解时间戳和fallback状态写入诊断记录。Warm start、固定稀疏结构、代码生成或设置time limit可能改善特定工作负载表现，但不自动证明最坏执行时间或控制安全性。<Cite refs={["turn838075search3","turn963615view2","turn838075search7"]}/>

### 12.2 ros2_control 异步更新会改变数据新鲜度与调度语义

Controller Manager的`update_rate`定义其主控制循环频率；不意味着每个控制器必然以相同频率同步执行。ros2_control支持控制器异步更新，并可单独设置`update_rate`、线程优先级和CPU affinity。Jazzy官方文档明确说明：若异步控制器上一轮`update()`尚未完成，下一次触发会复用上一结果并报告missed update cycles；异常仍可能导致控制器被deactivate。<Cite refs={["turn963615view0","turn963615view1"]}/>

工程设计需显式检查：
- 控制器输出是否带状态采样时间、计算完成时间和有效期；复用上一结果时命令是否过期。
- 异步线程优先级/CPU affinity是否与Controller Manager、硬件read/write、IRQ及其他实时线程形成可分析的资源分配。
- 控制器更新频率低于主循环时，保持上一命令是否符合系统动态和安全需求；位置、速度、力矩和接触控制不能一概而论。
- missed-cycle计数、执行时间分布、抖动、异常退出和fallback激活条件是否可观测；fallback接口故障时是否仍可用。
- 异步硬件组件read/write与控制器线程之间是否存在数据竞争、缓冲积压或时序错配。

异步执行是隔离较长计算对主循环的直接阻塞，不是让超时计算自动满足实时期限，也不等于安全fallback已通过验证。版本差异必须按目标ROS发行版文档核对。

### 12.3 时间参数化的“最优”受约束模型限定

固定几何路径上的时间最优路径参数化（TOPP）需要明确输入路径、边界条件和约束集合。TOPP-RA等方法可在其建模约束范围内求取路径速度参数；不能仅凭算法名称推断它自动覆盖所有关节/电机力矩、热限制、接触摩擦、jerk、制动器能力、载荷变化或整机安全约束。ROS Index当前快照将toppra列为维护中并提供0.6.10包版本，同时提示Python支持将被移除、建议考虑C++版本；实际部署需核对发行版、源码版本和语言绑定。<Cite refs={["turn963615view4","turn838075search2"]}/>

每个时间参数化方案应记录：
1. 几何路径及其坐标系、单位、连续性和碰撞/可达性验证结果；
2. 起止速度/加速度及中间waypoint是否要求停车；
3. 速度、加速度、jerk、力矩/功率、关节限位、接触/摩擦等实际纳入和未纳入的约束；
4. 约束来源是制造商额定值、辨识模型、在线估计还是经验值，并记录载荷、温度、电压和磨损等适用条件；
5. 离散化、网格、求解容差、数值失败处理、输出轨迹重新碰撞检查与下游可跟踪性验证。

“时间最优”只对所给路径、边界条件、约束模型和数值求解设定成立；约束不完整或参数不可信时，结果不代表真实机器人最快可行运动。

### 12.4 RPP前向碰撞投影不是动态环境预测或安全额定保护

Nav2 Regulated Pure Pursuit可沿当前命令的运动方向投影机器人footprint，并使用costmap进行前向碰撞检查；投影受时间上限和lookahead carrot距离等参数限制。该功能依赖传感器输入、costmap更新、footprint、TF、机器人模型和控制器执行链。它不是对动态障碍未来轨迹的完整预测，也不能覆盖传感器盲区、数据过期、CPU失效或独立制动链故障；不能替代安全额定扫描仪、安全控制器、保护停止或STO。参数默认值不是产品验收阈值。<Cite refs={["turn963615view3"]}/>

## 13. PID 闭环的离散实现、饱和处理与验收方法（2026-11-06）

本节给出可用于轮速、关节位置/速度等单输入单输出闭环的工程化检查框架。它不规定通用增益或控制频率；具体控制对象、驱动器内部环路、传感器分辨率、采样周期和执行器能力必须由目标系统确定。

### 13.1 先固定信号方向、单位和离散时间

定义设定值 (r_k)、测量值 (y_k)、误差 (e_k=r_k-y_k)、控制输出 (u_k)，采样间隔 (T_s)。开始调参前必须记录：

- 变量物理意义和单位，例如 rad、rad/s、m/s、N·m；位置/速度/电流量不能混用。
- 正方向、编码器计数方向、电机相序/驱动器方向和反馈符号；小幅正向命令应得到预期方向的测量变化。
- 控制器实际执行时间戳、采样周期分布、数据年龄和输出有效期，而不只是配置中的目标频率。
- 控制输出的物理含义、上下限、变化率限制，以及驱动器内部是否已经闭合电流/速度/位置环。

若反馈符号错误，增大比例增益会形成正反馈；这不是通过重新调参可以修复的问题。

### 13.2 位置式 PID 的一种离散表达

一种常见的离散实现可写为：

```text
e[k] = r[k] - y[k]
P[k] = Kp * e[k]
I*[k+1] = I[k] + Ki * Ts * e[k]
D[k] = -Kd * (y[k] - y[k-1]) / Ts
u*[k] = P[k] + I[k] + D[k] + uff[k]
u[k] = limit(u*[k], u_min, u_max)
```

这里对测量值求微分（derivative on measurement），可避免设定值阶跃直接在微分项产生 derivative kick。上式是说明结构的基础形式，不包含微分滤波、抗积分饱和、输出变化率限制和离散实现细节；不能直接作为所有驱动器的生产代码。

参数量纲必须与误差和输出单位匹配。例如当误差单位为 rad、输出为 N·m 时，(K_p) 的量纲为 N·m/rad；积分和微分增益的量纲还分别包含时间因子。禁止脱离单位和采样周期比较不同项目的数值增益。

### 13.3 微分滤波与噪声

数值微分会放大高频测量噪声。工程实现通常需要对微分通道低通滤波，或使用带滤波的微分状态；滤波参数必须结合采样周期、传感器噪声和闭环带宽确定。滤波太弱可能放大编码器量化/噪声，滤波太强则增加相位滞后。

验收时应同时记录原始测量、滤波后测量、微分项和输出，避免仅看最终位置曲线而无法定位噪声来源。对低分辨率编码器，速度估计方法和更新窗口本身也会引入延迟。

### 13.4 输出饱和与 anti-windup

执行器存在电流、速度、力矩、驱动器内部限幅和供电限制。若积分器持续按未受限误差累积，而实际输出已经饱和，解除饱和后可能产生长时间过冲。至少应选用并验证一种 anti-windup 策略：

- **条件积分（conditional integration）**：输出已饱和且误差继续推动输出向饱和方向时，暂停该方向的积分；当误差有助于退出饱和时允许积分恢复。
- **反算回馈（back-calculation）**：将受限输出与未受限输出之差反馈至积分状态，例如
  ```text
  I[k+1] = I[k] + Ki*Ts*e[k] + Kaw*Ts*(u[k] - u*[k])
  ```
  其中 (K_{aw}) 的取值和离散实现需与控制器结构匹配，不能套用未经验证的固定值。

必须区分控制器软件限幅与驱动器内部实际限幅；若驱动器内部限幅不可观测，软件 anti-windup 可能仍无法准确反映真实执行输出。若同时存在幅值限制和 slew-rate 限制，应定义 anti-windup 使用哪个实际受限信号，并测试两种限制共同作用时的状态行为。

### 13.5 前馈、级联与模式切换

- **前馈**：速度/加速度前馈、重力补偿或摩擦补偿可减轻反馈误差，但依赖模型和标定；模型误差可能导致稳态偏差或反向扰动。
- **级联控制**：例如位置外环输出速度参考、速度内环输出力矩/电流参考。每层都要定义单位、限幅、更新周期、数据时间戳和失效行为；内环通常需要比外环更快，但带宽间隔必须根据对象动态和采样/延迟分析，不能使用固定倍数作为通用规则。
- **无扰切换（bumpless transfer）**：手动/自动、不同控制器或控制模式切换时，应使积分状态与当前实际输出协调。一个可能的初始化思路是令积分项补足当前输出与 P/D/前馈项之间的差额；具体计算必须考虑输出限幅和内部驱动器状态。
- **复位与重启**：明确积分状态何时清零、何时保持、何时按当前输出重建；编码器重置、驱动器重新使能、控制器 deactivate/activate 和故障恢复不能共享一个未经分析的默认策略。

### 13.6 调试与验收顺序

建议按以下顺序执行并归档原始数据：

1. **静态方向/单位检查**：断开危险运动或使用受控台架，验证反馈符号、单位、零点、编码器方向和输出极性。
2. **开环/低能量检查**：在批准的安全工况下确认执行器响应、死区、摩擦、饱和、延迟和传感器噪声。
3. **P 项基线**：从受控小幅输入开始，观察稳态误差、振荡、结构共振和限幅；不以单一阶跃响应替代完整工况。
4. **I 项与抗饱和**：测试负载扰动、持续偏差、长时间饱和及解除饱和后的恢复。
5. **D 项/滤波**：测试测量噪声、量化、速度估计延迟和设定值变化，确认微分冲击和噪声放大受控。
6. **前馈/级联**：逐层启用并检查环路交互、带宽、限幅传播和更新时序。
7. **故障与边界**：注入传感器超时/跳变、命令过期、执行器饱和、控制周期抖动、驱动器故障、模式切换和控制器重启，验证输出是否被拒绝、保持、降级或进入经设计的安全状态。
8. **工况矩阵**：覆盖空载/额定及允许载荷、速度范围、方向变化、温度/电压范围、不同地面/摩擦状态和重复运行；只测试经过风险评估批准的范围。

至少记录设定值/测量值/误差/控制输出/饱和标志/积分状态/时间戳/周期抖动/驱动器反馈/故障码，并报告超调、稳态误差、上升/调节时间、跟踪误差、饱和持续时间、恢复时间和异常次数。指标定义、滤波、统计窗口和工况必须固定，不能只挑选成功曲线。

### 13.7 控制器失败语义与安全边界

- 测量值 NaN/Inf、时间戳倒退、数据超时、输出越界或计算异常时，必须定义明确的拒绝/降级路径；不能静默地把无效值送入驱动器。

- 软件 PID 的输出归零不必然等于机械停止；制动器、驱动器使能、STO、安全 PLC 和机械保持装置属于不同层级。

## 14. Jerk 约束、多轴同步与在线轨迹重定时（2026-11-06）

### 14.1 路径、时间参数化与在线轨迹生成是三个不同层次

- **几何路径（path）**：描述机器人在配置空间或任务空间中经过哪些位置，通常不包含时间。
- **路径时间参数化（time parameterization）**：给定几何路径 (q(s))，求路径进度 (s(t))，从而得到 (q(t))、速度和加速度；其目标是在约束下安排沿既定路径的运动时间。
- **状态到状态轨迹生成（state-to-state OTG）**：给定当前 (q,dot q,ddot q) 和目标状态，以及速度/加速度/jerk 限制，直接生成满足约束的时间轨迹；它不必先有一条完整的几何路径。
- **在线轨迹生成/重定时**：在控制周期内根据新的当前状态、目标或约束重新计算后续轨迹，适合目标变化、视觉伺服或受控减速等场景。

这几层不能互相替代。对有障碍物的机械臂任务，OTG 生成的平滑关节运动仍需由上游规划保证路径/碰撞约束；对固定路径的高速运动，仅用单轴 state-to-state 轨迹也不能自动满足路径曲率、接触或整机动力学约束。

### 14.2 jerk 与 S 曲线的意义

jerk 定义为加速度对时间的导数：

[
j(t)=rac{d a(t)}{dt}=rac{d^3 q(t)}{dt^3}
]

梯形速度曲线通常具有近似阶跃的加速度切换；理想阶跃意味着 jerk 出现冲击。S 曲线通过限制 jerk，使加速度以有限斜率上升/下降，从而减少加速度突变。对称的七段 S 曲线可概念化为：

1. 正 jerk：加速度从初值上升；
2. 零 jerk：保持正加速度；
3. 负 jerk：将正加速度降至零；
4. 零加速度：保持恒速（若该运动距离足够）；
5. 负 jerk：建立负加速度；
6. 零 jerk：保持负加速度；
7. 正 jerk：将负加速度平滑恢复至终值。

并非每次运动都会出现完整七段：短距离、低速或非零起止速度/加速度可能使某些阶段消失。不能只根据“七段式”名称假设每个段都存在。

限制 jerk 的工程意义包括降低结构激励、减少传动间隙冲击和改善末端负载平稳性；但 jerk 受限不等于振动必然消失。结构模态、柔性、共振、齿隙、摩擦、负载变化和控制器带宽仍可能产生振动。 jerk 上限应来自机械/工艺要求、驱动器能力或经过验证的辨识模型，而不是从通用示例照抄。

### 14.3 多轴同步策略与代价

多轴运动常见三类同步目标：

- **时间同步（time synchronization）**：各轴各自满足运动学限制，并调整持续时间，使所有轴尽可能在同一时刻到达目标。适合需要末端同时到位的协调运动，但各轴的相位轨迹不一定是直线比例关系。
- **相位同步（phase synchronization）**：在可行时使各轴沿共同的相位比例运动，形成配置空间中的直线运动；若约束/边界状态不允许，则算法可能退回其他同步策略。它并不等同于任务空间直线运动。
- **不同步（no synchronization）**：每轴独立生成，计算和到达时间不强制一致。只有当机构允许各轴独立到达、且下游任务不要求同步时才适用。

同步策略必须结合机构耦合、末端路径要求、碰撞余量和工艺约束选择。关节空间直线不保证末端笛卡尔直线；多轴同时到位也不代表途中满足碰撞、奇异性、力矩或接触约束。

### 14.4 约束输入应从设备能力逐层收敛

至少分开管理以下限制：

| 约束 | 常见来源 | 需要额外核验的内容 |
|---|---|---|
| 位置/行程 | 机械限位、编码器范围、软件限位 | 零点偏置、软限位余量、制动距离、回零状态 |
| 速度 | 电机/驱动器/减速器/机器人型号数据 | 载荷、姿态、温度、电压、外部轴和控制模式 |
| 加速度 | 驱动器能力、机械刚度、工艺要求 | 峰值/连续定义、负载惯量、结构振动和冲击 |
| jerk | 工艺平稳性、机械/传动响应、辨识模型 | 测量带宽、滤波影响、结构模态及末端负载 |
| 力矩/电流/功率 | 电机、驱动器、减速器及供电规格 | 峰值持续时间、热降额、再生制动和母线电压 |
| 接触/摩擦 | 末端工具、工件、地面或夹持条件 | 法向力、摩擦系数不确定性、接触切换与滑移 |

URDF 或 `joint_limits.yaml` 中的限制是软件模型输入，不自动证明它们等于真实设备可持续能力。应记录数值来源、单位、型号/固件、负载、温度和有效条件；对没有可靠来源的限制标为待确认，不用“典型值”冒充设备额定值。

### 14.5 MoveIt TOTG 与 jerk-limited smoothing 的职责边界

MoveIt 的规划器通常先生成关节/末端位置路径，再通过时间参数化补充时间戳、速度和加速度。其官方教程指出，TOTG 对原始轨迹段进行拟合并重新采样，生成点可能在给定路径容差内偏离原轨迹，因此后续可能需要重新进行碰撞检查；该教程还明确说明，TOTG 时间参数化本身不处理 jerk 限制，可在后处理阶段增加 Ruckig jerk-limited smoothing。具体适配器顺序应按目标 MoveIt 发行版的文档与配置核对，不能混用旧版教程中的参数或顺序。来源：[MoveIt 2 Time Parameterization](https://github.com/moveit/moveit2_tutorials/blob/main/doc/examples/time_parameterization/time_parameterization_tutorial.rst)、[MoveIt TOTG API](https://moveit.picknik.ai/main/api/html/classTimeOptimalTrajectoryGeneration.html)。

由此得到的工程检查链：

1. 规划器输出几何路径；
2. 检查路径连续性、关节限位、碰撞与可达性；
3. 根据每个关节的速度/加速度限制进行时间参数化；
4. 若需要 jerk 限制，再执行 jerk-limited smoothing；
5. 对后处理结果重新检查碰撞、位置/速度/加速度/jerk 约束；
6. 评估离散采样与控制器插补之间的偏差；
7. 将最终轨迹下发到控制器，并通过跟踪误差和驱动器状态验证执行结果。

“平滑后更顺”不是充分验收条件：平滑可能改变轨迹几何、拉长时间、降低间隙余量，或因采样/插补造成实际路径偏离。

### 14.6 在线 OTG 的输入、循环和状态连续性

在线生成器通常需要每个自由度的当前状态 ((q,dot q,ddot q))、目标状态和运动学限制，并以固定控制周期迭代输出下一时刻状态。Ruckig 官方教程给出了该接口结构、同步选项、输入验证和结果状态；也特别说明，下一周期若实际当前状态与预先计算轨迹不一致，算法会基于新的状态重新计算。来源：[Ruckig Tutorial](https://docs.ruckig.com/tutorial.html)。

在线重定时的关键工程要求：

- **使用真实当前状态**：当前位置、速度和加速度应来自有时间戳的状态估计/驱动器反馈；不能在每次重规划时假设机器人已到达上一次期望状态。
- **保持状态连续性**：新轨迹初始状态应与当前实际运动状态相容。只替换目标位置而忽略当前速度/加速度，可能产生速度或加速度不连续。
- **区分目标更新与约束更新**：目标跳变、限速变化、负载变化、坐标系变化和控制模式切换应分别定义触发条件与边界。
- **确定输出时序**：生成器控制周期、硬件读写周期、控制器插补周期和总线周期需要对齐或有明确的时间戳/缓冲策略；不能仅靠相同的名义频率推断同步。
- **明确停止策略**：停止不是简单地把目标位置设为当前位置。应根据当前速度/加速度、可用制动能力和停止空间生成受约束减速轨迹；急停/保护停止仍由独立安全链承担。
- **限制重规划抖动**：传感器噪声或目标微小抖动可能触发频繁重算。应设计死区、目标滤波、滞回或更新节流，但这些处理不能引入不可接受的响应延迟。

Ruckig 文档列出了输入验证和错误状态（如输入无效、轨迹持续时间/位置限制/同步计算错误）。工程集成必须逐项处理错误结果，不能在错误时继续发送未定义或过期输出。文档还指出，位置限制能力及中间 waypoint 的本地实时计算存在版本/许可差异；选型时必须核对实际采用的版本、社区版/Pro 功能边界和部署方式，不能从 API 名称推断功能都可用。

| 验证项 | 输入/工况 | 核验内容 |
|---|---|---|

2. **边界条件多项式**：`CubicTrajectory` 在两端匹配位置/速度；`QuinticTrajectory` 在两端匹配位置/速度/加速度。构造时给定固定时长，采样返回位置、速度和加速度。
3. **单轴七段 S 曲线**：`SCurveTrajectory` 根据位移、最大速度、最大加速度和最大 jerk 构造对称 rest-to-rest 轨迹；短行程可省略恒速段或恒加速度段，支持反向位移，并提供 `valid()` 和 `duration()`。
4. **多轴命令桥接**：`CspTrajectoryCommandPublisher` 在同一采样时刻对固定数量的标量轨迹采样，先完整检查样本和命令形状，再发布一个固定容量 CSP 批次；检查采样时间非负且不回退、序列号递增、deadline 和 clock domain。队列满时不提交序列号/采样时间状态。
5. **执行边界分层**：桥接器注释明确其运行于规划/worker 线程，而非硬实时 cyclic callback；驱动能力、驱动状态、校准和目标限值由下游 cyclic owner 再次验证。

### 16.3 现有测试覆盖

- 标量轨迹测试覆盖阶跃、斜坡端点/斜率、非正时长、正弦解析导数、偏置/相位、负频率和有限样本。
- 多项式测试覆盖三次/五次边界条件、内部解析采样、rest-to-rest 五次轨迹、时域外采样和非正时长。
- S 曲线测试覆盖 rest-to-rest 端点、离散采样速度/加速度/jerk 限制、反向运动、短行程/长行程，以及非法限值和零位移。
- CSP bridge 测试覆盖双轴完整批次、deadline/clock metadata、空指针/非有限样本拒绝、队列满、采样时间回退和序列号回退。
- CMake 将以上四个测试源文件纳入核心测试目标。CI Run #2827 的 Linux/Windows Test 步骤均成功。

### 16.4 发现的能力边界与风险

1. **不是通用路径时间参数化**：当前三个生成器均为单轴标量轨迹。没有看到基于几何路径 q(s) 的 TOPP/TOPP-RA 类路径参数化实现，也没有按关节速度/加速度/力矩约束求解整条路径时间分配的模块。
2. **多轴批次不等于多轴同步规划**：CSP bridge 保证同一采样时刻、完整批次发布，但不会自动调整各轴时长以保证同时到达，也不计算末端路径偏差或多轴相位同步误差。
3. **S 曲线边界条件有限**：当前实现是对称 rest-to-rest；未提供非零起止速度/加速度、非对称加减速限制、在线目标变更/重定时或 jerk 采样输出接口。
4. **多项式不自动满足运动约束**：Cubic/Quintic 只满足给定端点条件和时长，不保证内部峰值速度、加速度或 jerk 不超过设备限制，也不是时间最优求解器。
5. **输入与数值边界尚不统一**：Scalar/Ramp/Sine/Cubic/Quintic 构造接口没有统一的有限值/范围校验；极小正时长下多项式系数的 T^2 至 T^5 分母可能造成数值溢出。S 曲线检查构造参数有限且限值为正，但没有对位移差、派生相位时长和总时长的所有中间结果统一做有限值校验；两个有限端点相减也可能溢出。
6. **无效 S 曲线可能被桥接器误认为有效样本**：无效 `SCurveTrajectory` 的 `sample()` 返回有限的起点保持值；`ISampledScalarTrajectory` 接口没有暴露有效状态，CSP bridge 仅检查采样结果是否有限。因此，仅把无效 S 曲线传给 bridge 时，当前接口不能可靠地将“轨迹无效”与“合法保持轨迹”区分开。
7. **非有限采样时间语义不一致**：CSP bridge 会拒绝 NaN/Inf 采样时间；但底层各轨迹的 `sample()` 没有统一约定。特别是 S 曲线的 NaN 时间可能通过比较分支落到整段积分路径，得到类似终点的有限样本。建议将有限时间校验纳入轨迹接口自身，而不只依赖下游 bridge。
8. **单位契约需明确**：标量轨迹注释允许调用方自定义位置单位，而 CSP bridge 输出字段命名为 rad、rad/s、rad/s²；调用方必须保证输入确实是关节弧度单位，或在适配层显式转换。当前接口没有单位类型系统。
9. **约束检查职责在下游**：bridge 将速度/加速度写入命令，但自身不检查每轴位置/速度/加速度限制；依赖下游 cyclic owner 的限制检查。必须保持该二次验证，不得把 bridge 的有限值检查理解为设备约束验证。

### 16.5 后续改进优先级

- **P0｜样本有效性与数值防护**：统一轨迹构造和采样的有限值语义；为采样结果提供明确状态/错误通道；检查 S 曲线派生中间值和总时长；拒绝 NaN/Inf 时间；增加极小/极大位移、极小正时长、溢出、非法 S 曲线经 CSP bridge 发布等回归测试。
- **P1｜多轴同步和单位/约束契约**：增加显式多轴同步策略（共同完成时间、各轴限值差异、同步误差）；明确 rad 与调用方单位的转换边界；测试批次中任一轴不可行时的全批次拒绝。
- **P1｜完整运动规划能力**：将 state-to-state OTG、固定路径时间参数化、waypoint 拼接/连续性、在线重定时分开建模；按需求评估 Ruckig、MoveIt TOTG/Ruckig smoothing 或 TOPP-RA，而不是将单轴 S 曲线包装为完整路径规划。
- **P2｜性能与目标平台验收**：基于实际目标 CPU/OS/控制周期测量分位数与最坏执行时间；完成控制器插补、驱动限值、碰撞复核和 SIL/HIL/实机分级验证。benchmark smoke 不能替代 WCET 或硬实时验收。

### 16.6 审查结论

当前模块提供了可复用的单轴参考轨迹、边界条件多项式、对称 rest-to-rest S 曲线和固定容量 CSP 批次发布接口；其基础构建/单元测试有 Linux、Windows CI 证据。它适合作为**基础轨迹生成组件**，但不能据此认定已具备通用多轴同步、路径时间参数化、在线 OTG 或完整机器人轨迹规划能力。上述结论是源码/测试静态审查；本轮未在本地重建上游项目、未连接真实驱动器、未执行 HIL/实机或目标平台 WCET 测量，也未复制上游源码。

### 17.4 发现的能力边界与风险

1. **模型输入范围较窄**：URDF adapter 明确拒绝 branch，且当前仅覆盖 fixed/revolute/continuous/prismatic 串联链；未覆盖 planar/floating joint、mimic、transmission、完整 URDF XML 语义和多分支树。DH 仅声明 Standard convention。
2. **URDF 解析器不是完整 XML parser**：实现通过字符串扫描识别 tag/attribute，测试只覆盖简化的常见 XML 片段；XML comments、namespace、entity/转义属性、复杂格式和 malformed document 的一致性尚未证明。若作为通用 URDF 输入层，应改用成熟 XML parser 或明确限制输入子集。
3. **Joint limits 校验不完整**：`RobotModel::valid()` 主要检查串联拓扑和几何有限值，不完整验证 limits；DH/URDF 入口未统一强制 effort/velocity 非负，URDF 对 revolute/prismatic 未强制 lower/upper 必须存在。IK 的限位投影依赖这些字段，因此错误/缺失限制可能变成无界运动范围。
4. **手工构造模型的轴向量契约不明确**：模型校验要求 movable joint axis 非零，但没有统一要求单位化；URDF parser 会归一化轴，手工构造的 prismatic axis 若非单位向量，FK 位移尺度会随轴向量模长变化。应在模型入口统一归一化或拒绝非单位轴。
5. **FK 不执行关节限位检查**：FK 接受有限但超出 joint limits 的 q。作为纯运动学函数可以是合理设计，但 IK、控制器和上层应用必须明确承担限位约束，不能将 FK 成功解释为机器人可执行。
6. **IK 初始状态限位未被验证**：Numerical IK 和 DLS 在迭代更新时可投影到 joint limits，但进入求解前没有检查/裁剪 initial。若初始 q 已超限且目标恰好对应该状态，可能直接返回 Converged。应在入口拒绝或按显式策略投影初始状态，并补回归测试。
7. **IK 误差尺度混合**：位置误差以米、姿态误差以弧度组成同一六维向量参与平方代价；没有 task-space weighting/characteristic length。相同数值量级的米和弧度不代表相同工程重要性，可能改变求解方向和代价下降判断。Numerical IK 还采用固定前向差分步长/固定阻尼且没有候选代价下降线搜索；DLS 有阻尼调整和代价下降试探，但差分步长与 max_joint_step 仍对 revolute/prismatic 采用同一数值尺度。
8. **冗余/碰撞约束未覆盖**：当前 IK 未提供 null-space posture objective、任务优先级、碰撞距离约束、速度/加速度约束或连续轨迹 IK；单次 Pose IK 成功不代表路径连续、无碰撞或可执行。
9. **奇异性求解缺少不收敛状态**：Jacobi eigensolver 有 max_eigen_iterations，但达到迭代上限后没有显式返回“不收敛”或误差界；调用者可能把未充分对角化的对角元素当作最终 singular values。当前测试没有强制触发迭代上限。
10. **惯性张量物理合法性检查不足**：`valid_state()` 检查质量非负、COM/矩阵元素有限及惯性对角项非负，但没有检查矩阵对称性、正半定性和主惯量三角不等式。非物理惯性参数可能进入 M(q) 并影响动力学/控制结果。
11. **Coriolis 是有限差分参考实现**：质量矩阵对 q 使用固定绝对步长 1e-5 做中心差分，再计算 Christoffel 项；混合 rad/m 坐标和不同连杆尺度下该步长未必合适，计算成本也不适合未经目标平台测量就宣称高频实时。测试仅验证单自由度零速度 Coriolis，没有覆盖多自由度非零耦合项或与可信参考库的数值对照。
12. **动力学输出还有数值边界**：`bias_forces()` 在 c+g 相加后没有再次检查 allFinite；大数值输入可能在组合时溢出。质量矩阵虽做对称化和有限值检查，但未显式检查正定性/条件数。
13. **ComputedTorque 的限幅是静默裁剪**：输出力矩按绝对限值 clamp，但结果不附带饱和状态/裁剪量；没有位置/速度/加速度约束、摩擦/柔性/执行器动态补偿和模型不确定性处理。它是 stateless control law，不是安全控制器或完整驱动闭环。

2. **线性离散 Kalman predict/update**：`kalman_predict` 实现 x⁻=Ax+Bu、P⁻=APAᵀ+Q；`kalman_update` 用创新协方差 LLT 求解 Kalman gain，并使用 Joseph form 更新协方差。实现检查维度、有限值、协方差对称性及 PSD/PD 条件，并采用候选状态事务性提交。
3. **LQG certainty-equivalent 控制**：`lqg_control` 接受 Kalman estimate 和给定反馈矩阵 K，计算 u=-K*x_hat。它只实现估计状态反馈映射，不负责系统辨识、LQR 权重设计或 Kalman 参数整定。
4. **单轴扰动观测器**：`DisturbanceObserver` 用 J*a - tau_command + B*omega 估计模型残差，基于速度差分估算加速度，再用一阶低通滤波和上下限裁剪输出扰动估计及补偿力矩。
5. **平面里程计积分**：`PlanarOdometry` 对 body-frame planar twist 做 SE(2) constant-twist 积分；非零角速度时使用圆弧解析更新，零/极小角速度时使用直线近似，并在输出非有限时拒绝提交。

### 18.3 现有测试覆盖

- StateObserver：非法配置/输入、未配置调用、从位置测量估计速度、较大初始误差收敛、reset、惯量/阻尼/刚度模型项影响加速度。
- DiscreteKalman：标量解析测量更新、控制输入和过程噪声预测、LQG 使用估计状态、非法更新保持输出、维度和非有限输入拒绝。
- DisturbanceObserver：非法配置/输入、恒定模型残差估计、补偿方向、估计限幅、reset。
- PlanarOdometry：直线运动、初始航向、恒定 twist 精确圆弧、body lateral velocity、非法输入时状态不变。
- 测试以单轴合成对象、标量 Kalman 和理想平面 twist 为主；没有覆盖多传感器融合、真实 IMU/编码器噪声、轮胎打滑、时间戳错位或真实机器人状态估计误差。

### 18.4 发现的能力边界与风险

1. **StateObserver 的 Euler 稳定性依赖 dt**：实现只要求 dt 有限且大于零，没有最大步长或离散稳定性检查。观测增益较大或采样周期突增时，forward Euler 可能放大误差甚至数值发散；目前没有大 dt、dt 抖动或长时间运行边界测试。
2. **StateObserver 缺少运算后有限值检查**：输入和配置有限不保证乘加结果有限；更新先修改内部估计状态，再写输出，没有候选状态 all-finite 检查。极端值可能使状态变为 Inf/NaN 但仍返回成功，缺少事务性保护。
3. **DisturbanceObserver 对速度差分噪声敏感**：扰动估计通过相邻速度样本差分得到加速度，之后才做一阶低通；编码器量化、速度估计噪声和时间戳抖动可能被放大。需要噪声、量化、延迟和变采样周期测试。
4. **扰动残差使用命令力矩而非实测执行器力矩**：估计值会混合外部负载扰动、驱动器电流/力矩跟踪误差、饱和、摩擦模型误差和惯量误差；不能把 estimated_disturbance 直接解释为纯外部扰动力矩。必须明确补偿正负号、信号来源和闭环使用边界。
5. **DisturbanceObserver 缺少运算后有限值/事务性检查**：有限输入仍可能在速度差分、惯量乘法或补偿力矩计算中溢出；当前更新会先写内部估计和历史速度，再返回成功，没有对所有候选中间值做完整 finite 检查。
6. **Kalman 只覆盖线性离散模型**：当前接口需要调用方提供 A/B/C/Q/R，没有 EKF/UKF、非线性状态模型、传感器时间同步、缺测/离群值门控、创新统计或自动噪声辨识。LQG helper 也只是 u=-K*x_hat，不等于完整 LQG 设计工作流。
7. **Kalman 输出协方差的后验合法性检查有限**：输入协方差会做对称/半正定检查，更新使用 Joseph form 并对称化，最后检查有限值；但输出后验协方差没有再次做 PSD 检查或报告最小特征值，仍建议增加数值回归。
8. **PlanarOdometry 是运动学积分，不是融合定位**：输入是已知 body twist；没有轮编码器模型、IMU 融合、偏置估计、协方差传播、打滑检测、时间戳/同步管理或地图定位，因此不能把它称为完整移动机器人状态估计系统。
9. **小角速度分支阈值只看角速度绝对值**：分支条件使用 abs(wz)>1e-12，而真实转角是 wz*dt；若 wz 极小但 dt 极大，代码会走直线近似，即使累计转角已不可忽略。建议按 theta=wz*dt 使用稳定的 sinc/cosc 形式或小角度级数，并增加极端 dt 测试。
10. **缺少估计器之间的一致性与故障降级验证**：当前各模块独立测试，没有覆盖传感器丢包/跳变、时间戳回退、估计协方差膨胀、观测器重置、估计失效后控制器切换或安全停止策略。

### 18.5 后续改进优先级

- **P0｜估计状态数值与时间边界**：StateObserver/DisturbanceObserver 对候选状态、导数、滤波输出和补偿力矩做有限值检查并事务性提交；明确 dt 上下界和异常采样策略；PlanarOdometry 按累计转角选择稳定小角度公式。
- **P1｜估计质量与传感器模型**：为扰动观测器补充速度噪声/量化/延迟测试，明确 command torque 与 measured torque 的模型差异；为 Kalman 增加后验协方差 PSD 检查、创新/残差统计、缺测和异常测量处理。
- **P1｜机器人状态估计能力**：补充轮编码器/IMU 融合、偏置估计、协方差传播、时间戳对齐、滑移检测和故障降级；根据机器人形态评估 EKF/UKF/error-state Kalman filter，而不是把 twist 积分等同于定位。
- **P2｜目标平台验证**：使用目标传感器日志和辨识模型进行离线回放、噪声/延迟注入、SIL/HIL；报告位置/速度误差、协方差一致性、漂移、恢复时间、CPU/内存和最坏执行时间。

### 18.6 审查结论

当前仓库有一个简化二阶机械轴 Luenberger observer、通用线性离散 Kalman predict/update、模型残差扰动观测器和 SE(2) twist 里程计积分器；Kalman 的 Joseph form、协方差输入检查和 PlanarOdometry 的事务性更新是有价值的稳健性设计。它们尚未构成完整的移动机器人/机械臂多传感器状态估计栈。主要缺口是 observer 数值/采样周期边界、扰动估计对噪声与执行器误差的敏感性、Kalman 的测量异常/后验一致性，以及缺少 IMU/编码器融合和真实日志验证。本节为源码/测试静态审查；未本地重建上游、未使用真实传感器日志、未进行 HIL/实机或目标平台 WCET 测试，也未复制上游源码。

### 19.4 发现的能力边界与风险

1. **差速/Mecanum 是理想运动学映射**：没有轮胎打滑、轮径误差、地面附着、负载转移、滚子角度误差、驱动器动态或在线标定模型。正逆映射 round-trip 只能验证代数一致性，不能证明实车里程计/控制精度。
2. **统一轮速缩放不等于可行运动分配**：公共比例因子能保留理想运动方向，但不考虑每轮加速度/jerk、驱动电流/力矩、热降额、摩擦锥、轮胎附着和电池功率约束；也没有对底盘期望 twist 的动态可达性进行反馈。
3. **Pure Pursuit 的 lookahead 距离基准存在偏差风险**：实现从最近路径顶点开始累计 lookahead，而不是先投影到最近路径段再沿路径累计，也不是严格求车辆位置处 lookahead 圆与路径的交点。路径点稀疏或车辆位于两个顶点之间时，实际目标点相对车辆的前视距离可能明显偏离配置值；自交/回环路径还可能因全局最近点选择跳段。
4. **路径跟踪器输出速度固定**：Pure Pursuit、Stanley、LQR 和 MPC 都以配置的固定 linear_speed 输出，没有统一的曲率降速、制动距离、加速度/jerk 限制、路径终点停车或障碍物约束。Pure Pursuit/Stanley 对 linear_speed 的符号允许范围也不完全一致，倒车语义需要明确。
5. **LQR/MPC 是局部运动学模型**：LQR 使用局部切线和固定速度的线性化自行车模型；MPC 使用小误差线性模型、固定 horizon/速度和固定次数投影梯度下降。当前没有曲率前馈、动态速度优化、障碍物/碰撞约束、转向变化率约束或优化未收敛状态。MPC 的 gradient_step 与 horizon/权重耦合，固定迭代次数并不证明每次求解都达到最优或稳定收敛。
6. **CartesianControl/Impedance 的姿态误差坐标系需核对**：两者先计算 q_error = q_desired * conjugate(q_current)，再对 log_so3(q_error) 额外乘当前姿态旋转；而 CartesianAdmittance 的实现注释和测试将同样的左乘姿态误差视为已经在 base frame，不再额外旋转。对非单位当前姿态，这三条路径存在坐标系处理不一致的风险。建议统一 spatial/body error 定义，并补充“当前姿态非单位旋转 + base-frame 目标增量”的回归测试。
7. **Cartesian task-space wrench 的单位/权重需要显式标定**：平移误差为米、旋转误差为弧度；线性/角向 stiffness、damping、wrench 的量纲不同。接口使用 6 维对角增益，未提供 characteristic length 或统一任务空间权重规范；参数不能直接跨机器人或末端工具复用。
8. **Cartesian impedance/control 没有奇异性阻尼或 null-space 任务整合**：直接使用 Jᵀ wrench；关节力矩可能在奇异/近奇异构型下出现任务空间能力退化或较大关节负载。虽然另有 NullSpaceControl 工具，但当前接口未将它们组合为有明确优先级的任务栈。
9. **CartesianAdmittance 显式 Euler 与 passivity 边界**：配置只要求 dt 正且有限，没有基于虚拟质量/阻尼/刚度的离散稳定性或 passivity 检查。高刚度、低虚拟质量或较大 dt 可能导致离散振荡；软件限幅不等于能量/接触安全保证。
10. **阻尼 Null-space projector 不再是精确投影**：damping>0 时采用 sigma/(sigma²+damping²)，所得 I−J#J 一般不严格幂等，也不保证 J*P=0；次级任务可能泄漏到主任务。现有近奇异测试只检查有限输出，没有量化 primary-task leakage 与阻尼权衡。
11. **Null-space 截断阈值是绝对值**：zero-damping 路径使用固定 absolute singular_tolerance；不同 Jacobian 单位、尺度和机械臂尺寸下，秩判定可能不具备尺度不变性。建议增加相对阈值和 characteristic-length 规范。
12. **CartesianControl/Impedance 的输入姿态校验不够显式**：q/dq 和向量输入有维度/有限值检查，但 desired/equilibrium pose 的 quaternion norm 和 position finite 应在接口入口统一验证，避免依赖后续矩阵运算间接发现异常。

1. **通用非线性 MPC**：调用方提供离散 dynamics、stage cost、terminal cost 和 box control bounds；实现通过有限差分 rollout 估算梯度、投影到控制边界、backtracking line search，并支持 warm-start、shift、projected-gradient 诊断、iteration/line-search 计数和明确 termination enum。
2. **Constrained QP**：求解凸二次目标，约束范围是线性等式和 box bounds；使用 ADMM、带等式约束的 KKT x-update 和 box projection，检查 Hessian 对称/半正定、等式矩阵行满秩及 primal/dual residual 收敛。
3. **Generic MPC adapter**：把求解器 callback 与问题/结果校验解耦，检查维度、有限值、预测状态矩阵形状和控制边界；它本身不实现预测模型或优化器。
4. **连续时间 CBF**：ControlBarrierFilter 提供单标量控制仿射系统的一阶 CBF 约束；MultiBarrierFilter 对单标量输入求多个一维半空间的交集。
5. **多输入 CBF**：MultiInputCbfFilter 将多条 affine barrier constraints 与 actuator box bounds 组成半空间集合，通过枚举小规模 active sets 投影 nominal control；另有 RelativeDegreeTwoCbfFilter 将相对阶二约束转换为多输入仿射约束。
6. **离散时间 CBF**：DiscreteTimeCbfFilter 强制一阶预测条件 h(x[k+1]) ≥ (1−gamma)h(x[k]) + margin；RobustDiscreteTimeCbfFilter 以用户提供的逐 barrier prediction error bound 收紧 drift。
7. **CBF + slew-rate 组合**：CbfSlewRateFilter 与 RobustCbfSlewRateFilter 将前一实际应用控制和每周期最大控制变化量转换成更窄的 actuator bounds，再执行 CBF 投影。
8. **参考调节器**：ReferenceGovernor 根据位置范围、速度上限、加速度上限和离散 stopping-speed 约束平滑目标位置，要求配置后 reset。
9. **鲁棒/自适应基础控制**：RobustAdaptiveController 使用参数投影、sigma leakage 和连续 boundary-layer robust term；SlidingModeController 使用 sat(s/phi) 代替理想 sign(s)，并报告输出饱和。

### 20.4 发现的能力边界与风险

1. **Relative-degree-two CBF 公式与标准级联定义不一致，列为 P0 数学复核项**：代码当前使用 `Lf2(h) + LgLf(h)u + alpha1*h_dot + alpha1*alpha2*h >= margin`。若按标准 exponential CBF 递归定义 `psi1 = h_dot + alpha1*h`，并要求 `psi1_dot + alpha2*psi1 >= 0`，展开应为 `h_ddot + (alpha1+alpha2)*h_dot + alpha1*alpha2*h >= 0`。当前 `h_dot` 系数缺少 `alpha2`；现有测试的非零 h_dot 场景不足以区分两种公式。需先确认设计定义，再添加非零 h_dot 解析测试；本轮未改上游源码。
2. **CBF 安全性依赖调用方提供的正确模型**：filter 只接收 barrier 值、drift、control derivative 或一步预测量，并不从真实系统动力学推导它们。离散 robust CBF 的保证还依赖 prediction_error_bounds 真正覆盖模型误差、扰动和采样误差；不满足假设时，filter 成功不等于真实系统安全。
3. **多输入 CBF active-set 枚举存在组合复杂度**：实现最多允许 20 条总约束，并枚举至多 n 个 active constraints；它明确面向 small-dimensional problems。约束数/控制维度增大时组合数量快速增长，尚无最坏执行时间或实时调度保证。
4. **CBF slew-rate 参数是每周期 delta，不是物理变化率**：`max_control_delta` 没有 dt 字段；调用方必须自行将 rate limit 乘以实际控制周期，并传入 last applied control 而非 last requested control。若采样周期变化或传入请求值，约束含义会偏离实际执行器变化率。
5. **MPC 成功返回不代表优化已收敛**：`solve_nonlinear_mpc()` 的 bool 表示求解流程生成了有效结果；`termination` 仍可能是 IterationLimitReached 或 NoImprovingStep。上层必须检查 termination、projected_gradient_norm 和工作量计数，不能仅凭 true 当作收敛。
6. **非线性 MPC 只约束控制 box bounds**：没有内建 state constraints、非线性路径约束、terminal set、碰撞约束、disturbance/tube robustness 或多阶段硬约束；这些需要通过外部 formulation/solver 扩展。梯度依赖有限差分完整 rollout，计算量随 horizon、控制维度和 line search 增长，未测目标平台 WCET。
7. **Constrained QP 不是通用高性能 QP 求解器**：当前只处理凸 Hessian、线性等式和 box bounds；使用 dense Eigen/ADMM，不含通用不等式矩阵、稀疏结构、warm start、rho 自适应或实时迭代预算证明。文档自身将其定位为 deterministic baseline，而非 production solver。
8. **Generic MPC wrapper 无法验证预测模型真实性**：它验证结果形状、有限值和控制边界，但无法验证 predicted_states 是否确由实际 dynamics rollout 得到，也无法验证 solver cost 是否与真实目标函数一致。
9. **ReferenceGovernor 没有 jerk 限制**：只管理位置、速度和加速度；dt 仅要求正且有限，没有上限。reset 检查位置/速度范围，但没有按停止距离判断当前速度是否能在位置边界内安全停车；极端边界状态可能在 update 时返回 ConstraintViolation。
10. **鲁棒自适应与滑模组件是标量控制原语**：参数投影、sigma leakage 和 boundary layer 可限制部分数值/抖振问题，但没有给出具体被控对象的匹配不确定性界、Lyapunov 证明或执行器约束证明；不能单独称为鲁棒安全控制器。
11. **CBF 输出指标需避免误读**：active_constraint_count 主要统计接近零的 barrier residual，不应默认解释为所有 actuator bounds 和 barrier constraints 的完整 active-set 计数；minimum_safety_margin 也只反映输入模型中的约束余量。

### 20.5 后续改进优先级

- **P0｜Relative-degree-two CBF 数学定义**：确认 exponential CBF 递归定义，复核 h_dot 系数是否应为 alpha1+alpha2；增加 h、h_dot、h_ddot、LgLf(h) 全部非零的解析测试和边界测试，再决定是否修复上游实现。
- **P0｜安全过滤器使用契约**：明确连续/离散 CBF 的模型假设、采样周期、prediction error bound 的来源与验证方法；将 max_control_delta 与 dt/实际 applied control 关联，并在接口文档中防止误用。
- **P1｜实时复杂度与 solver status**：为 active-set CBF 的最大控制维度/约束数做组合数预算和最坏耗时测试；MPC 上层强制检查 termination；为 QP/MPC 增加 warm-start、solver status 和迭代预算策略。
- **P1｜约束完整性**：按具体机器人加入 state/path/terminal constraints、障碍物与执行器动态约束；为 robust CBF 的 error bounds 提供离线验证或在线估计来源，而不是手工常量。
- **P1｜ReferenceGovernor 与鲁棒控制**：补 jerk 约束、采样周期异常处理和 reset 停止距离可行性检查；对 adaptive/sliding 控制补充对象假设、扰动界、饱和影响与 Lyapunov/数值仿真证据。
- **P2｜目标平台验证**：使用真实动力学模型和扰动日志开展 SIL/HIL；测量可行性率、约束违例率、最坏求解时间、控制抖动和异常降级行为。

### 20.6 审查结论

当前仓库包含较完整的优化/安全过滤基础构件：有限差分非线性 MPC、box/equality ADMM QP、连续/离散/鲁棒/多输入/相对阶二 CBF、slew-rate 组合、ReferenceGovernor、鲁棒自适应和滑模边界层。数值边界测试和 CBF 多步合成闭环测试较充分，但这并不等于已完成机器人级安全证明。最优先复核 RelativeDegreeTwoCbfFilter 的 h_dot 系数，以及 CBF 模型误差界/采样周期/实际 applied control 契约；其次是 active-set 最坏执行时间、MPC termination 检查和 QP 能力边界。本节为源码/测试静态审查；未本地重建或运行上游、未在真实系统验证 barrier model/误差界、未执行 HIL/WCET/安全认证，也未复制上游源码。

9. **WholeBodyQp/行走操作组合**：WholeBodyQp 将多任务、变量 box bounds 和参考姿态正则化组合成加权 least-squares 问题；WalkingManipulationController 通过不同权重组合 locomotion 与 manipulation 任务。
10. **接触力分配**：ContactWrenchOptimizer 使用投影梯度分配接触点力以逼近期望六维 wrench，施加法向力范围和方形摩擦金字塔；另提供最多 8 个接触点的 fixed-storage 版本。

### 21.4 发现的能力边界与风险

1. **QPTaskHierarchy 是加权优先级，不是严格 lexicographic hierarchy**：实现将所有 level 累加进一个 weighted least-squares Hessian/gradient；高权重只是软优先级，冲突任务仍可互相折中。注释已说明不是 exact lexicographic solver，不能把 level 顺序当作硬优先级或安全约束。
2. **QPTaskHierarchy/WholeBodyQp 的迭代收敛诊断不足**：使用固定步长 projected gradient 和固定 iteration count；显式 step_size 只检查正且有限，没有限制在稳定步长区间，也没有梯度范数/目标变化/收敛状态。迭代结束返回 true 不证明已收敛。
3. **TaskSpaceHierarchy 的阻尼 projector 是近似 null-space**：damping>0 时伪逆不是 Moore–Penrose 精确逆，P=I−J#J 通常不严格幂等，也不保证高优先级任务严格零泄漏；需量化每一级残差变化和任务干扰。
4. **WholeBodyQp 不是完整浮动基 whole-body dynamics QP**：当前只支持加权任务残差和变量 box bounds；实现注释明确 general contact inequalities 与 floating-base dynamics equalities 不在初始范围。没有显式浮动基动力学等式、接触力摩擦锥、关节力矩/加速度耦合约束或碰撞不等式。
5. **ContactWrenchOptimizer 的接触假设很强**：所有接触力都在 world frame，法向固定为 +Z；切向摩擦使用方形金字塔近似，法向力上下界固定，忽略接触力矩/CoP、任意地形法向、接触开关状态和接触点不确定性。固定实现最多 8 个接触点，固定迭代次数不等于 WCET 证明。
6. **ContactModel 可能在几何分离时产生阻尼法向力**：法向力公式为 max(0, k*max(0,−gap) − d*v_normal)。当 gap>0 但 v_normal<0（接触点正在接近平面）时，阻尼项可能使 normal_force>0，即尚未穿透就出现接触力。当前分离测试没有覆盖“分离且正在接近”的组合；需确认是否为有意的预接触阻尼模型，否则应仅在接触激活条件下施加阻尼。
7. **FootTrajectory clearance 固定沿 world Z**：不读取地形法向或局部高度场；在斜坡、台阶和非平地面上，摆动弧可能穿地或不必要抬高。轨迹只覆盖 swing 段，不包含 touchdown 速度匹配、冲击约束或在线避障。
8. **GaitScheduler 是开环相位时钟**：按 period/duty/offset 计算相位，没有接触传感器闭环、早触地/晚触地调整、相位重置、支撑状态估计或 gait transition 平滑；phase 输出不能替代真实接触状态。
9. **CentroidalDynamics 是外力聚合模型**：只做 Newton-Euler 总力/力矩求和，不含浮动基/关节耦合、质心惯量变化、centroidal momentum matrix、角动量状态演化或接触动力学求解。
10. **ZMP 使用简化 LIPM 和矩形支撑区域**：公式不处理角动量变化、质心垂向加速度、非平面地形、多个不连续支撑区域、真实接触力可行性或动态摩擦约束；inside_support 是几何矩形判定，不是完整稳定性证明。
11. **LocomotionMpc 是双积分器平面加速度优化**：没有接触力、质心角动量、摩擦锥、足端轨迹、障碍物、地形、终端稳定集或鲁棒不确定性；固定梯度步长/迭代次数无收敛诊断，不能视为完整 legged MPC。
12. **FloatingBaseState 接受非单位四元数**：验证仅要求有限且非零范数，测试明确允许非单位 quaternion；所有消费端必须统一决定何时归一化，并保证 body-to-world 约定不被误用。
13. **WalkingManipulation 是软权重折中**：locomotion_weight 大于 manipulation_weight 只表示加权目标更偏向 locomotion，不是严格任务优先级或安全约束；任务冲突时仍可能牺牲稳定性目标以降低总目标。
14. **WholeBodyControl/JointImpedance 是控制律组件而非完整 WBC**：前者只做 Jᵀ wrench 力矩合成，后者只做关节弹簧阻尼；均没有把浮动基动力学、接触约束、碰撞约束和驱动器/电流/热限制联合求解。

### 22.4 发现的能力边界与风险

1. **Distributed Clocks 尚未形成真实配置/同步链路，列为 P0**：layout/profile 中有 `distributed_clocks_enabled`、cycle/shift time 元数据，但审查的 `EthercatIghAdapter` 实现没有调用 `ecrt_slave_config_dc`、`ecrt_master_application_time`、`ecrt_master_sync_reference_clock`、`ecrt_master_sync_slave_clocks` 或 `ecrt_master_sync_monitor_queue`；`Cia402MotionInterlock` 也没有 DC lock/synchronization 条件。不能因 layout 标记 DC enabled 就宣称 CSP 已实现分布式时钟同步。
2. **CSP rearm latch 的运行健康判据存在边界缺口，列为 P0 复核**：首次健康要求 scan 完成且所有 slave operational；但进入已运行状态后，`master_path_healthy` 没有包含 `!scan_in_progress`、scan_slave_count/index 完整性，`slot_runtime_valid` 只检查 configured/state_valid，没有检查 online/operational/AL=OP。stage 会拒绝新 setpoint，但 receive_process 的 rearm latch 可能未被置位，旧 process image/controlword 仍可能被 queue_send 提交。需用 fake API 增加“WKC complete 但 slave SafeOp/offline”及“运行中 topology rescan”测试，验证 stale 0x6040 是否被强制 Disable Voltage。
3. **非 CSP 输出缺少统一安全态策略**：通信故障时 adapter 专门对已管理 CSP 轴的 0x6040 controlword 写 Disable Voltage；其他 output PDO 没有通用 safe-output policy。若应用通过 raw PDO 输出其他控制对象，必须由上层明确故障安全值和失联行为，不能假设 adapter 自动清空所有输出。
4. **MDP provenance token 不是密码学证明**：代码注释已说明 report_set_token 是审核报告集关联 token，不是签名。plan 的 evidence accepted 布尔值和非零 token 是流程门禁，不证明报告来源/内容真实性；需在受控构建/发布流程中保管报告与哈希。
5. **CSP profile token 未与当前已配置 plan token 做 adapter 内部等值绑定**：stage 侧主要检查 profile token 非零和设备/拓扑信息；adapter 未保存并核对 configure_mdp_plan 时使用的 report_set_token。因而 provenance 的最后一跳仍依赖调用方正确传递 profile，不能把非零 token 当作 adapter 已验证的配置来源。
6. **PDO/CiA 402 binding 的 revision 范围需明确**：通用 `resolve_cia402_pdo_bindings` 主要按 ring position、vendor/product 和对象/位宽匹配；firmware revision/serial 的强约束依赖更高层 MDP plan topology match。若绕过 MDP plan 直接使用基础 resolver，可能将同厂商/产品不同 revision 的 PDO layout 混用。
7. **每个 PDO domain 的 expected WKC 应有正值契约**：ProcessDataLayout 的 domain validation 没有明确拒绝 expected_working_counter=0；后续 domain status 会落入 Unknown/无法判定 Complete。应在配置阶段拒绝无效 expected WKC 或显式标记该 domain 不参与健康判定。
8. **EtherCAT cyclic 调度由调用方负责**：adapter 提供 receive/process 与 queue/send 原语，不创建实时周期线程，也不配置 CPU affinity、SCHED_FIFO、mlock、IRQ affinity 或 deadline watchdog。固定容量/无动态分配不等于硬实时证明；每周期还读取 master/scan/slave/domain 多组诊断，必须测目标拓扑下 WCET。
9. **CANopen bus-off 恢复没有清理节点会话**：CanopenVirtualNode::set_bus_off 只置 communication_faulted，set_bus_recovered 只清除标志；不会 reset 正在进行的 segmented SDO transfer，也不会把 NMT state 强制退回 PreOperational/Stopped 或要求显式 rearm。恢复后旧 SDO transfer/NMT Operational 状态可能继续生效，需定义安全恢复状态机。
10. **CANopen object 初值宽度校验不对称**：add_object 检查 size_bytes 为 1/2/4/8，但未像 set_object_value 一样验证初始 value 是否能装入 size_bytes；初始值过宽可能在 PDO/SDO 编码时被截断。
11. **CANopen 覆盖范围是经典 CAN 与单组虚拟 PDO**：CanopenCanFrame 是 8-byte classic CAN；虚拟节点集中覆盖 RPDO1/TPDO1 和一个对象字典模型，不等同完整 CANopen master/manager、多个 PDO、SYNC/EMCY/time-stamp、LSS 或设备配置栈。
12. **SocketCAN 传输不负责总线配置和重试策略**：bitrate、restart-ms、bus-off 自动恢复由操作系统/网卡配置；send 是非阻塞调用，队列满/EAGAIN 由调用方处理。接收路径没有 kernel timestamp 语义，heartbeat 时间由调用方提供。
13. **虚拟设备不是驱动器模型**：VirtualJointDevice 的运动/力矩模型是简化 SIL 行为；FaultInjectableVirtualJointDevice 适合故障路径测试，不代表真实 drive watchdog、功率级、制动器、编码器或安全回路。
14. **电机目录参数不是完整伺服配置**：VendorMotorProfile 提供电机目录级机械/电气参数，不包含具体 drive firmware、编码器计数、齿轮/传动链、热限制、PDO 映射、校准和安全限值；不可直接据此使能实机。

## 23. Relative-degree-two exponential CBF 数学复核（2026-11-14）

### 23.1 审查基线与源码位置

- 上游仓库：[`rexyll/MotionControlAlgorithms`](https://github.com/rexyll/MotionControlAlgorithms)
- 审查基线：main，`c11091bd2bb3ce001eb09f2664c1ff5076f8a73b`（2026-11-14）。
- 实现：`include/mca/control/relative_degree_two_cbf_filter.hpp`。
- 委托投影器：`include/mca/control/multi_input_cbf_filter.hpp`。
- 测试：`tests/control/multi_input_cbf_filter_test.cpp` 中的 RelativeDegreeTwoCbfFilter 测试。
- 本轮为源码与测试静态复核；未修改上游源码，未本地构建或运行上游测试。

### 23.2 标准级联推导

对控制仿射系统

\[
\dot x=f(x)+g(x)u,
\]

以及相对阶为 2 的安全函数 \(h(x)\)，假设 \(L_g h=0\)，且控制输入首次出现在 \(\ddot h\) 中。指数型 CBF 常定义

\[
\psi_0=h,\qquad \psi_1=\dot h+\alpha_1 h,
\]

\[
\psi_2=\dot\psi_1+\alpha_2\psi_1.
\]

展开可得

\[
\psi_2=\ddot h+(\alpha_1+\alpha_2)\dot h+\alpha_1\alpha_2h.
\]

若 \(\ddot h=L_f^2h+L_gL_fh\,u\)，则应施加

\[
L_f^2h+L_gL_fh\,u+(\alpha_1+\alpha_2)\dot h+\alpha_1\alpha_2h\geq0.
\]

该级联条件的安全解释还依赖初始集合条件（通常要求 \(h\geq0\) 且 \(\psi_1\geq0\)）以及模型/输入假设；单次过滤器不自动构成完整安全证明。

### 23.3 实现与测试对照

当前 `RelativeDegreeTwoCbfFilter::filter` 将每个 barrier 的漂移项构造为

\[
L_f^2h+\alpha_1\dot h+\alpha_1\alpha_2h-\text{safety\_margin}.
\]

与标准级联展开相比，缺少 \(\alpha_2\dot h\)。控制系数矩阵使用输入的 \(L_gL_fh\)，这一部分与上述模型形式一致；下游 `MultiInputCbfFilter` 将漂移项与控制项组成半空间约束并投影名义控制。

现有 `RelativeDegreeTwoCbfFilter.EnforcesCascadedBarrierCondition` 测试设置 \(\dot h=0\)，因此无论系数是否缺失都会得到相同结果；`LeavesSafeNominalUnchanged` 虽设置非零 \(\dot h\)，但名义控制在两种公式下均远离边界，不能检出差异。当前测试未覆盖非零 \(\dot h\) 且两种公式给出相反安全判定的情况。

### 23.4 可复核数值反例

取 \(\alpha_1=2\)、\(\alpha_2=3\)、\(h=0.1\)、\(\dot h=-0.2\)、\(L_f^2h=0\)、\(L_gL_fh=1\)，并令 safety margin 为 0。则当前实现的控制前漂移项为

\[
0+2(-0.2)+2\cdot3\cdot0.1=0.2,
\]

故名义控制 \(u=0\) 会被判断为满足约束。标准级联条件的控制前项则为

\[
0+(2+3)(-0.2)+2\cdot3\cdot0.1=-0.4,
\]

因此必须满足 \(-0.4+u\geq0\)，即 \(u\geq0.4\)。该反例证明当前实现可能在 \(\dot h\ne0\) 时低估约束严格程度；它不依赖数值求解器细节。

### 23.5 结论与修复验收建议

- **结论：P0 数学实现缺项已由源码公式和解析反例确认**，不再只是“可能不一致”。若 API 意图确实是标准二阶 exponential CBF，漂移项应使用 \((\alpha_1+\alpha_2)\dot h\)。若设计者意图采用另一种非标准定义，则必须重命名/明确数学契约并给出推导，不能继续称为标准级联条件。
- 最小回归：采用 §23.4 数值反例，确认 \(u=0\) 不可行、过滤器应选择满足 \(u\geq0.4\) 的控制；另加入正/负非零 \(\dot h\)、不同 \(\alpha_1,\alpha_2\)、多 barrier、控制上下界冲突、非零 safety_margin 和输出事务性保持测试。
- 需要验证 `minimum_safety_margin` 报告值仍对应未平移的物理残差，并检查多约束下最小残差的含义。
- 更新 API 注释、数学说明和测试命名；明确 \(h\geq0\)、\(\psi_1\geq0\)、相对阶、模型误差与采样/离散实现假设。
- **授权边界：** 本轮只完成知识库审查与修复验收设计。未修改 `MotionControlAlgorithms` 源码或 CI；如需上游修复，须先取得用户对目标分支和具体文件范围的明确授权。

**验证边界：** 本结论来自读取上游 main 源码和测试内容、手工展开公式及解析数值反例；未在本地运行 C++ 测试，未做闭环仿真、真实机器人、HIL、WCET 或安全认证。

### 24.2 通用数据模型与 IgH 适配器并不闭环

1. 通用 `EthercatProcessDataDomain` 定义 `cycle_time_ns`、`sync0_shift_ns` 和 `distributed_clocks_enabled`；`valid()` 只在 DC 被标记启用时检查 cycle time 非零。这是数据模型，不是主站配置动作。
2. 通用层还定义 `EthercatDcState` 与 `ethercat_dc_transition_allowed()`，可表达 Unsupported、NotConfigured、Synchronizing、Locked、Lost、Degraded 等状态迁移；但该状态机本身不会配置从站时钟、推进应用时间或读取同步偏差。
3. IgH adapter 的 `Config` 只有 `master_index`、`cycle_time_ns`、`send_interval_us`，没有 DC enable、Sync0 cycle/shift、reference clock 或同步监测策略字段。
4. `configure_impl()` 生成每个 domain 的 layout 时只写入 `id` 与 `cycle_time_ns`；没有设置 `distributed_clocks_enabled` 或 `sync0_shift_ns`，因此该 adapter 当前生成的 domain layout 保持 DC disabled/default 状态。
5. 对 `src/hardware/ethercat_igh_adapter.cpp` 全文检索，没有发现 `ecrt_slave_config_dc`、`ecrt_master_application_time`、`ecrt_master_sync_reference_clock`、`ecrt_master_sync_slave_clocks`、`ecrt_master_sync_monitor_queue` 等 IgH DC 配置/周期同步 API 调用。
6. 测试 fake 头文件 `tests/fakes/igh/ecrt.h` 未声明上述 DC API；现有 PDO mapping profile 测试也未建立 DC 配置、同步收敛或失锁回归。

### 24.3 激活、周期运行与 CSP interlock

- `activate()` 的准入条件是 master 已配置；它设置可选 send interval、调用 `ecrt_master_activate()` 并取得 domain image，没有 DC 配置或 Locked 状态门禁。
- `receive_process()` 的运行健康证据包括 master receive/state、link、scan progress、slave online/operational/AL 状态和各 domain WKC；没有 DC lock、reference-clock 状态或同步偏差采样。
- CSP runtime-ready/recovery 判据建立在上述通信/拓扑/AL/WKC 条件上；CSP stage/interlock 没有 DC 状态输入。因此，当前 CSP 通路不能声称已验证 DC 同步，也不会因 DC 失锁而触发专门的 DC fail-safe/rearm。
- 这不等于所有 EtherCAT CSP 设备都必须启用 DC，也不证明当前无 DC 配置必然产生危险。部分设备/应用可能使用 free-run 或其他同步方式；是否必须 DC，取决于驱动器同步模式、控制周期、跨轴同步精度和应用需求。当前可确认的是：该 IgH adapter 没有提供可请求、可观测、可联锁的 DC 能力。

### 24.4 结论与修复决策

**结论：P0 能力缺口已确认，但应准确标记为“当前 IgH adapter 不支持/未暴露 DC”，而不是“DC 已启用但锁定失败”。** 通用结构体和状态机只是预留抽象；当前 adapter 的配置入口、布局生成、IgH API 调用、runtime health 与 CSP interlock 均没有形成真实 DC 链路。

建议分两阶段处理：

1. **先建立显式能力边界（最小安全修复）**：为 adapter 提供明确 capability/diagnostic，报告 DC unsupported；在上层请求 DC 时以明确错误拒绝，不允许把通用 layout 中的 DC 标志默默当作已生效。当前 adapter 没有 DC 请求入口，后续若增加通用 layout/config 入口，必须在配置时拒绝 unsupported 请求。
2. **如产品需求确实要求 DC，再实现完整闭环**：配置从站 Sync0 cycle/shift；按 IgH 生命周期正确推进 application time；按目标拓扑选择并同步 reference/slave clocks；周期读取 sync monitor/偏差；定义 Locked/Degraded/Lost 阈值、debounce 和超时；将 DC 状态纳入要求 DC 的 motion profile/CSP interlock、故障 latch 和显式 rearm。参数必须来自设备 ESI/厂商手册和实测，不得使用猜测默认值。

### 24.5 最小回归与验收清单

- fake API 能记录 DC configure/application-time/reference-clock/slave-clock/sync-monitor 调用顺序及参数。
- 未启用 DC 的 profile 可以按明确 free-run 契约运行；请求 DC 但 adapter capability 不支持时，配置必须 fail closed。
- 启用 DC 时，配置失败、未锁定、偏差超限、monitor 读取失败、运行中 Lost/Degraded 均有确定状态和错误路径。
- 对要求 DC 的 CSP profile，只有 DC 达到配置规定的 Locked 条件才允许使能；运行中失锁应触发受定义的安全输出/latch，并要求显式 rearm。
- 覆盖多从站、不同 Sync0 shift、reference clock 变化、断链恢复、scan 变化和长时间周期偏差；用真实 IgH master + 代表性驱动器进行 HIL 验证，再测目标平台 jitter/WCET。
- 记录 DC 偏差分布、最大偏差、锁定时间、丢锁恢复时间和测量时钟域；CI/fake API 通过不能替代 HIL。
