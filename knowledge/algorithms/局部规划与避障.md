# 局部规划与避障（Local Planning and Control）

> 局部规划/控制器在当前状态、全局路径、局部环境观测与机器人运动约束下，计算短时域的可执行运动命令。它需要在路径跟踪、障碍规避、运动学/动力学约束和执行器响应之间权衡。不存在通用的固定控制频率、固定障碍预测时域或单一最佳控制器。控制器的碰撞预测也不能自动替代安全额定保护装置与风险评估。

## 1. 输入输出与概念边界

典型输入包括：
- 当前位姿/速度估计、运动学模型和机器人 footprint；
- 全局路径或目标位姿；
- 局部 costmap（静态地图、传感器障碍、膨胀代价和可选过滤器）；
- 速度/加速度/曲率/倒车等约束；
- 传感器时间戳、定位质量和控制器状态。

输出可能是速度命令、短时运动序列或控制量；具体接口由控制器和底盘驱动定义。局部控制器可能在有限时间窗内预测轨迹，但预测轨迹不是已执行轨迹，也不是独立安全认证。

需要区分：
- **局部规划器/控制器**：计算短时运动命令并跟踪路径；
- **动态障碍预测**：估计他人未来可能占据的位置/区域；
- **任务/交通协调**：处理多机优先级、窄道会车、交通规则与死锁；
- **安全功能**：由风险评估确定的安全相关停止/限速/保护功能，不能依靠普通导航控制器单独承担。

## 2. 常见控制器与局部规划方法

| 方法/插件 | 核心思路 | 典型用途 | 主要边界 |
|---|---|---|---|
| DWA / DWB | 在受速度/加速度约束的动态窗口中采样控制/轨迹，向前仿真并由多个 critic 评分 | Nav2 文档中的默认 controller plugin；支持可配置轨迹生成和评分 | 评分函数、采样密度、预测时域决定行为；局部最优、窄道和复杂动态障碍需专门测试 |
| TEB（Timed Elastic Band） | 优化带时间间隔的离散轨迹节点，考虑障碍距离、时间和运动学/动力学约束 | 需要显式时间/轨迹优化、倒车或类汽车约束的研究/系统 | 计算复杂度依赖优化问题和约束；rst-tu-dortmund/teb_local_planner 上游是 ROS 1 base_local_planner / catkin 插件，不是 Nav2 原生插件 |
| Regulated Pure Pursuit（RPP） | Pure Pursuit 跟踪路径，并按曲率/障碍距离等调节线速度；可进行前向 footprint 碰撞投影检查 | 需要几何路径跟踪、平顺速度调节和碰撞检查的移动平台 | 主要目标是沿给定路径精确跟踪；默认不会像可偏离全局路径的 DWB/MPPI 一样围绕动态障碍主动寻找大幅绕行路径 |
| MPPI | 采样控制序列扰动、按运动模型前向模拟轨迹、由 critic 评价并迭代更新控制序列的采样式 MPC | 需要灵活代价函数、预测运动模型和动态避障的系统；Nav2 实现支持差速/全向/阿克曼模型 | 性能受样本数、时域、模型、critic、CPU 和地图更新影响；Nav2 上游 README 描述其为高度优化的 CPU-only 实现，不应写成默认 GPU 加速 |
| VFH 等直方图方法 | 将障碍表示为方向/角度直方图，再选择可行运动方向 | 计算资源受限或简单移动平台 | 受栅格/扇区分辨率、目标方向和局部极小值影响；具体实现差异较大 |
| 人工势场（APF） | 目标吸引势与障碍排斥势组合产生运动方向 | 教学、启发式局部避障或其他方法的组成部分 | 可能出现局部极小值、振荡和狭窄通道失败；不宜将未经验证的 APF 作为唯一安全避障机制 |

Nav2 的 DWB、MPPI 和 RPP 都是 controller plugins；TEB 是独立上游 ROS 包，其 ROS 2 port/fork 需要逐个核验仓库、接口和维护状态，不能将 ROS 1 上游兼容性外推到 Nav2。

### 2.1 如何选择，而不是套用口诀

Nav2 官方调参指南区分了常见用途：
- RPP 更偏向较准确的全局路径跟踪，按曲率或靠近障碍等条件减速，并可启用前向碰撞检测；
- DWB 与 MPPI 可以在动态障碍条件下偏离全局路径，分别通过轨迹 critic 评分或采样式预测控制寻找局部可行命令。

这只是特定 Nav2 版本和插件能力的选择起点，不是“重载必选 RPP、动态人群必选 MPPI、倒车必选 TEB”的普遍规律。需结合机器人运动模型、路径可行性、局部环境、算力、控制延迟、障碍动态和实测数据选择。

## 3. 动态障碍处理

典型感知与预测链路：

1. **检测/跟踪**：从 LiDAR、深度相机、视觉或其他传感器获得障碍观测；区分静态结构、动态目标与噪声。
2. **状态估计**：估计目标位置、速度、尺寸/占据区域和不确定性；明确坐标系、时间戳和多传感器关联。
3. **运动预测**：可使用恒速/恒加速度等运动模型、交互模型或学习型预测；预测时域应与任务时延、目标运动和控制周期匹配，不能固定照搬统一的 0.5–2 s。
4. **冲突判定**：判断机器人候选轨迹与目标未来占据区域是否在空间和时间上冲突；预测置信度低时需采用保守策略。
5. **行为与控制**：由控制器、行为树/状态机和交通协调逻辑决定减速、等待、绕行、重规划或停止。

行人安全距离、通行礼让规则、机器人优先级和电梯/门口行为，取决于目标市场法规、现场流程、机器人尺寸/速度、任务场景和风险评估。不要将“右让左”“机让人”或单一米数作为跨国家/场景的通用规则。

## 4. Nav2 Costmap：障碍层与过滤器

Nav2 Costmap2D 是全局/局部规划的环境代价表达，不是完整安全系统。常见 plugin/layer 的职责包括：

| 层/过滤器 | 作用 | 使用注意 |
|---|---|---|
| Static Layer | 将静态 OccupancyGrid 地图加载到 costmap | 地图版本、坐标系、未知空间语义和地图更新策略需明确 |
| Obstacle Layer | 处理 LaserScan/PointCloud2 等观测，标记障碍并按配置 raytrace 清除 | observation source、marking/clearing、最小/最大量程、障碍高度和传感器时间戳必须匹配 |
| Voxel Layer | 维护 3D 体素障碍信息，可利用点云进行标记/清除 | 体素高度、分辨率、观测来源与内存开销需按任务测试 |
| Range Sensor Layer | 将声呐/红外等 Range 消息转为代价地图观测 | 传感器视锥、噪声和概率模型必须与器件数据匹配 |
| Inflation Layer | 在障碍周围增加指数衰减代价；在机器人内切半径内设置致命代价 | 参数受 footprint、定位/地图误差与规划偏好影响；不是速度相关膨胀的自动实现 |
| Keepout Filter | 指定禁止进入区域 | 区域地图/坐标系和失效默认行为需核验 |
| Speed Filter | 在指定区域施加最大速度限制 | 这是区域限速机制，不替代实际制动能力和安全速度监控 |

**Inflation radius 不是简单的“速度越快就越大”。** 它定义代价扩张的空间范围。若要按速度、载荷或制动状态改变运行边界，应在独立、可验证的速度/安全策略中实现，并验证其与 costmap、footprint、控制器的交互。仅增大 inflation radius 可能使窄道在规划中变为不可通行，却不等同于已经建立了安全保护区。

## 5. 时延、制动距离与安全边界

把任意传感器频率、处理时间、控制频率和底盘响应时间相加成一个“通用回路时延”，容易产生错误安全结论。应在最终设备上测量最坏/高分位时延，并明确统计口径、负载、网络和温度条件。

在恒定速度且制动减速度可近似为常数的简化模型中，可用以下关系估算反应距离与制动距离：

\[
d_{req} \ge v\,t_{latency} + \frac{v^2}{2a_{min}} + d_{margin}
\]

其中：
- (v)：测试工况下的运行速度；
- (t_{latency})：从目标/障碍实际出现到制动开始产生有效减速度的总时延；
- (a_{min})：经最坏工况测试确认的有效最小制动减速度；
- (d_{margin})：覆盖测量误差、定位/检测不确定性、坡度、制动变化、控制余量等的附加裕度。

该式只是简化运动学估算，不是保护距离标准或安全计算的替代品。真实停止距离受载荷、地面摩擦、坡度、轮胎、制动器、供电状态、执行器温度、控制器饱和和 jerk 约束影响；必须按产品和目标场地测量。安全相关保护装置（如安全激光扫描仪、触边、安全控制器、STO/制动链）需要按风险评估、适用标准和整机验证确定，普通 Nav2 costmap/控制器不能取代它们。

## 6. 局部控制常见故障与诊断

| 现象 | 可能原因 | 检查与处理方向 |
|---|---|---|
| 路径两侧反复摆动 | 多条轨迹评分接近、采样分辨率/critic 权重不合适、定位噪声、全局路径曲率不连续 | 先记录候选轨迹和 critic 分数；检查定位/路径，再调采样与代价，不要只加某个“滞后项” |
| 原地转圈或无法接近目标 | 目标姿态、footprint、costmap 膨胀、goal checker、运动学约束、路径末端朝向不匹配 | 检查目标位姿、footprint、costmap 和 goal checker 的完整配置；不要套用 xy_goal_tolerance 大于 inflation_radius 这种无依据规则 |
| 窄道无法通过 | footprint/定位误差/地图分辨率、inflation 和实际可行间隙不匹配；控制器没有可行运动原语 | 先用准确足迹与误差预算验证可通行性，再选择合适的全局规划器/控制器；不要简单降低安全边界 |
| 两台机器人相互等待 | 狭窄路段缺少资源预约、优先级、会车点或死锁恢复策略 | 由多机调度/交通管理规划会车与预约；局部控制器不应独自解决系统级交通冲突 |
| 机器人在障碍前反复停车/绕行 | 感知误报/清除不当、点云/扫描时间戳、障碍层 clearing、footprint 或路径/控制器预测模型不一致 | 检查原始观测、标记/清除、TF 和 costmap 可视化，再审查控制器预测轨迹 |

## 7. 工程验收与测试矩阵

局部规划/控制器验收至少覆盖：

1. **模型与接口**：机器人 footprint、运动模型、速度/加速度/曲率限制、命令接口、控制周期、坐标系和软件版本。
2. **环境/感知**：静态障碍、动态目标、遮挡、传感器盲区、误检/漏检、时间同步、地图更新和清除。
3. **路径跟踪**：直线、曲线、狭窄通道、倒车、掉头、目标姿态和重规划。
4. **动态交互**：行人横穿、迎面相遇、追随、两机/多机死锁、动态物体突然出现。
5. **性能**：观测至命令时延、控制器执行时间、CPU/GPU、丢帧/超时、速度变化和轨迹偏差。
6. **制动与保护**：最大载荷、地面/坡度、低电量/温度、传感器断连和安全保护触发；测量实际停止行为并核对安全需求。

记录试验场景、重复次数、真值/测量方式、软件/驱动 commit、controller 参数、地图和传感器配置。论文或官方文档中的例子不能替代目标机器人的验证数据。

## 9. 本轮定向复核与未关闭事项（2026-11-03）

本轮纠正：

- 删除局部控制器通用 20–50Hz、TEB 10–50ms 和端到端 200–500ms 等无目标平台测试支撑的时延/频率数字。
- 纠正“MPPI GPU 加速”：Nav2 上游 MPPI README 将其实现描述为高度优化的 CPU-only 路径，并通过采样扰动、运动模型前向模拟、critic 评分和 softmax 更新控制序列。
- 纠正 RPP “避障弱”：官方文档含曲率/障碍距离速度调节和可配置的前向 footprint 碰撞投影检查，但其主要设计目标仍是沿给定路径跟踪，不等同于 DWB/MPPI 对动态障碍大幅偏离路线。
- 纠正 DWB/MPPI/RPP/TEB 的插件和算法边界：TEB 上游 package.xml/CMake 使用 catkin、base_local_planner、nav_core，不能把原仓库写成 Nav2 原生插件；ROS 2 fork 需独立核验。
- 纠正 TEB 许可描述：上游 BSD 不涵盖所有第三方依赖；README 标注 Eigen MPL2、g2o csparse_extension LGPL3+ 等不同依赖许可。
- 删除恒速预测 0.5–2 秒、社会距离 0.8–1.2m、右让左等通用数字/规则，改为按现场法规、目标运动、时延、风险评估和验证设定。
- 纠正 costmap 结构：Voxel/Range 为不同观测类型的 layer，Keepout/Speed 是 filters；Inflation Layer 是空间代价扩张，不是自动速度相关保护距离。
- 用简化运动学关系说明反应距离与制动距离，明确这不是安全保护距离标准；实机最坏工况与独立安全功能仍须验证。
