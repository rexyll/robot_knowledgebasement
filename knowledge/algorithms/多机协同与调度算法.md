# 多机协同与调度算法

> N 台机器人在共享空间里完成 M 个任务且互不添堵。两层问题：**任务分配（谁干什么）** + **路径协调（路上不打架）**。上游系统见 [[调度系统RMS]] · [[多机调度流程]]。

## 任务分配（Task Allocation）

| 算法 | 思想 | 复杂度 | 适用 |
|---|---|---|---|
| 贪心最近邻 | 每任务派最近空闲车 | O(NM) | 快但次优，实时性好（工程默认起点） |
| **匈牙利算法** | 全局最优二部图匹配 | O(N³) | 批量分配（50-200 台规模） |
| **拍卖算法** | 车竞标出价（成本+激励） | 分布式友好 | 去中心化车队、通信受限 |
| 市场机制 CBBA | 一致性束算法 | 分布式 | 弱通信环境（野外/救灾） |
| MILP/CP | 精确规划 | 指数级 | 小规模基准/离线 |

- 成本函数：`cost = 行驶时间 + 到达等待 + 电量惩罚 + 负载类型匹配 + 优先级`
- 批处理：任务成批发（1-5s 窗口）再匹配，比逐个即时派效率高 10-30%
- 带时间窗（ pickup/delivery TW）→ VRP 类问题（车辆路径问题），NP-hard，用 OR-Tools/LKH 求解

## 多智能体路径规划（MAPF）

| 算法 | 类型 | 思想 |
|---|---|---|
| 优先级规划 | 解耦 | 排优先级依次规划，后者避让前者（快、不完备） |
| 冲突搜索 CBS | 最优 | 高层冲突树+底层单机 A*，最优但指数爆炸 |
| ECBS | 有界次优 | CBS+信封约束（w=1.2-1.5 实用） |
| LaCAM | 2023+ 新 SOTA | 大规模快求解 |
| **路网+时间窗（工程主流）** | 解耦 | 地图切成路网（走廊/节点），占用预约（Reservation Table），路口互斥 |

**工程现实**：百台以上车队几乎都用"路网化+预约表+规则"而非学术 MAPF：
```
1. 地图抽象: 走廊图(topology graph) + 单向道 + 缓冲区(机器人车身尺寸)
2. 资源预约: 段锁(segment lock) — 车申请 A→B 段, 冲突则等待/绕行
3. 死锁预防: 环检测(申请链成环→强制超时释放) + 死锁区禁入
4. 路口信号: 热点区域(交口)虚拟信号灯, 先到先走/优先级
5. 动态重排: 全局重规划 <5s 内收敛, 避免雪崩(重排风暴)
```

## 交通规则体系（与安全联动）

| 规则 | 实现 |
|---|---|
| 限速区 | 区域属性下发车端 → costmap max_vel → [[局部规划与避障]] |
| 单向道 | 路网边方向约束 |
| 禁行时段 | 时间条件区域（人流高峰） |
| 让行优先级 | 车型（重载优先）/任务（急件优先）/右手规则 |
| 人流高峰模式 | 调度器感知客流（相机计数）全局降速 30% → [[功能安全体系]] |

## 充电与休眠调度（→ [[充电桩与自动充电]]）

- 电量作为约束进分配（任务能耗预估 vs 剩余电量）
- 机会充电：空闲窗口自动去桩（排队上限 2-3 台）
- 峰谷电价优化（夜间满充）
- 长期电池健康：SOC 20-80% 区间运行延长日历寿命 → [[电池与电源]]

## 集群指标（→ [[性能指标体系]]）

- 吞吐曲线（车队规模 vs 出货量）的**拐点**=场地瓶颈，扩车不扩桩/不扩路反而降效
- 死锁次数 KPI 应=0；拥堵率 >15% 触发拓扑改造
- 任务完成时间分布（P50/P95）比平均值更说明问题

## 细节加深（V2）
- **求解器选型**（台账 #80，快照 2026-11-01）：任务分配/VRP 直接上 **OR-Tools**（Apache-2.0，CP-SAT+路由库）——匈牙利/拍卖是教学理解用，工程派 CP-SAT。
- **MAPF 教学库**（台账 #81）：libMultiRobotPlanning（CBS/ECBS/CBS-TA/SIPP 头文件模板库）——把 §MAPF 的学术算法跑起来的最快方式；工程百台级仍是"路网+预约表"（与 V1 结论一致）。
- **让行规则数字化**：把"右手规则/优先级"编码成 cost 项而不是 if-else——否则规则数超过 5 条后互相打架（内部项目 gen_traffic_management 同源教训）。
