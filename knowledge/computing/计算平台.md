# 计算平台

> 机器人的"大脑硬件"。AMR 通常双脑：**工控机/高性能板卡**跑 ROS2 导航栈 + **MCU/实时板**跑底盘控制，中间串口/CAN/以太网相连（→ [[AMR整体架构]]）。

## 平台分级

| 层级 | 代表平台 | 主要职责 | 设计重点 |
|---|---|---|---|
| 实时控制 | STM32、NXP、TI 等 MCU | 电机闭环、编码器采集、I/O、确定性状态机 | 控制周期、定时器/ADC、总线时序、故障处理与安全架构 |
| 嵌入式 SoC | Rockchip RK3588 等 | HMI、轻量视觉、边缘网关、部分 ROS 2 工作负载 | BSP、Linux 内核、NPU 工具链、驱动成熟度、供货与散热 |
| AI 边缘计算模组 | NVIDIA Jetson Orin / Thor 等 | 多传感器处理、视觉推理、复杂规划和具身 AI 工作负载 | 真实模型吞吐、显存/内存、功耗模式、温升、模块生命周期和载板 |
| 工业计算机 | x86 / Arm 工业 PC | 工业网络、较重的导航/应用栈、现场集成 | 环境等级、接口、存储耐久、看门狗、可维护性与长期供货 |
| 开发/训练工作站 | x86 + GPU 工作站 | 仿真、数据处理、模型训练和离线建图 | GPU/CPU/内存/存储配比、驱动兼容、开发环境复现 |

## 代表性 SoC / AI 模组指标（官方口径快照 2026-11-03）

| 平台/准确系列 | AI 指标（必须看精度与模式） | 内存/功耗说明 | 工程备注 |
|---|---|---|---|
| Jetson Orin Nano 8GB | 普通模式最高 40 TOPS Sparse INT8 / 20 TOPS Dense INT8；Super Mode 最高 67 / 33 TOPS | 8GB LPDDR5；模块功率配置 7–25W | Super Mode 需核对 JetPack、载板供电和散热能力 |
| Jetson Orin NX 16GB | 普通模式最高 100 / 50 TOPS Sparse/Dense INT8；Super Mode 最高 157 / 78 TOPS | 16GB；Super Mode 需支持 40W 模式及相应载板/散热 | 不能把 157 TOPS 当作所有功耗模式下的常态性能 |
| Jetson AGX Orin 系列 | NVIDIA 系列页标示最高 275 TOPS | 内存、功率按 32GB/64GB/Industrial 等具体 SKU 核对 | 设计前必须选择准确模块 SKU 并使用对应 datasheet |
| Jetson AGX Thor 系列（T5000/T4000） | 系列最高 2070 FP4 TFLOPS | 系列最高 128GB；可配置 40–130W | FP4 TFLOPS 与 Orin 的 INT8 TOPS 不是同一精度/计量口径，不能直接比较 |
| Rockchip RK3588 | NPU 最高 6 TOPS @ INT8 | LPDDR4/LPDDR4x/LPDDR5 能力；板级容量、功耗和接口取决于具体载板设计 | 核对准确芯片版本、BSP、NPU SDK、驱动和量产板卡资料 |

**算力数字阅读纪律：**

1. TOPS/TFLOPS 是峰值算力指标，不等于 ROS 2 节点吞吐、整机帧率或端到端时延。
2. Sparse 与 Dense、INT8 与 FP16/FP4、GPU 与 NPU 的数字不可直接横向比较；必须同时记录精度、稀疏假设、功耗模式、模型、软件栈和测量方法。
3. 上表为厂商系列/型号的规格入口，不是机器人选型排名。实际性能必须在目标模型、相机/雷达输入、内存占用、并发节点、温度和功耗限制下测量。

## 生命周期与量产选型边界

NVIDIA 官方生命周期页面当前列示：Jetson T5000 模组可供至 2035-08，T4000 至 2036-01；AGX Orin 32GB/64GB、Orin NX 8GB/16GB 和 Orin Nano 4GB/8GB 模组可供至 2032-01。这里的 “Available through” 是厂商当前生命周期信息，不代表开发套件、第三方载板、所有地区库存或每个软件组件都具有同样期限；采购前要复核 PCN/EOL 通知和供应商承诺。

**开发套件不等于量产硬件。** NVIDIA 明确说明 Jetson Developer Kit 用于软件开发和系统原型，不用于生产部署；量产应选用生产规格模块和为最终产品设计/采购的载板，并重新完成电源、热、接口、EMC、环境、可靠性、软件镜像和供应链验证。开发套件上的“能运行”不能作为量产设计放行证据。

## 软硬件协同要点

1. **ROS2 on Jetson**：Isaac ROS GEMs 等 GPU 加速包要按 JetPack、CUDA、TensorRT、ROS 发行版和准确模组版本锁定依赖 → [[ROS与ROS2]]
2. **推理栈**：ONNX/TensorRT 量化后必须用目标数据集复测任务精度、延迟、显存和持续吞吐；不采用统一的“精度损失 <1%”或通用 FPS 保证 → [[视觉感知算法]]
3. **实时性**：普通 Linux 不能自动视为硬实时；确定性控制可由 MCU 或经验证的实时 Linux 方案承担。安全相关停止功能必须有符合风险评估的安全架构，不得仅依赖普通 ROS 节点或应用 MCU 代码 → [[实时系统与嵌入式]]
4. **存储**：按日志写入量、闪存耐久指标、掉电行为和恢复策略选型；OTA/地图分区要有完整性校验、回滚和断电测试 → [[云端协同与OTA流程]]
5. **热与功耗**：在最高持续负载、最高环境温度、密闭外壳和风扇/散热退化条件下测温并观察降频；启用 Super/高功耗模式前重新评估载板供电与热设计

## 典型 AMR 算力分配实例

```
MCU(STM32H7):     电机闭环与底盘运动学（示例频率须按实际控制器/驱动器验证）
                  安全功能由经风险评估和验证的安全链/安全控制器实现，不以普通 MCU 应用程序代替
Jetson Orin NX:   LiDAR驱动 10Hz + 激光SLAM + Nav2 规划控制 20Hz
                  + 深度相机 30fps 3D避障 + YOLO 行人检测 15fps
RK3588(副):       HMI 屏、语音、MQTT 云连接（隔离主算力风险）
```
