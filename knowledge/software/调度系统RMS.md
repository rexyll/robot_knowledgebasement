# 调度系统 RMS（Robot/Fleet Management System）

RMS/FMS 是多机器人系统的车队级管理与调度系统。它通常连接上层业务系统、机器人车队和现场基础设施，负责将业务任务转化为机器人可执行的任务，并协调机器人、路径和共享资源。

**边界先行：** RMS 不是单机导航栈，不是安全控制器，也不等同于 WMS/WES/MES。VDA 5050 是车队控制系统与移动机器人之间的通信接口建议，不是完整 RMS 产品规范；它不定义交通管理算法、安全要求、网络安全措施或与外围基础设施/外部 IT 系统的所有接口。ISO 21423:2026 则面向工业共享环境中 IMR、车队管理器及其他设备/应用之间的通信互操作，明确不覆盖安全和导航要求。两者的范围不同，不能直接视为互相替代或天然兼容。

## 1. 系统分层与责任边界

```text
WMS / WES / MES / ERP
  订单、工单、库存、生产节拍和业务约束
        |
        | 业务接口：API / 消息 / 事件（项目定义）
        v
RMS / FMS（车队管理与调度）
  任务接入、能力匹配、派单、任务状态、交通协调、
  资源预约、充电策略、车队监控、异常恢复
        |
        +--------------------------+
        |                          |
        | 机器人车队接口           | 设施/设备接口
        v                          v
VDA 5050 / 厂商 API           ISO 21423相关互操作/
        |                      电梯、门、设备控制器等接口
        v                          |
机器人端任务执行与导航              现场基础设施
  定位、局部规划、底盘控制、安全功能
```

该图是职责分层示意，不代表所有项目都采用同一部署拓扑。WMS/WES与RMS之间、RMS与设施之间的具体协议、数据模型、事务边界和故障责任，必须由项目接口控制文件（ICD）定义。

| 层级 | 主要职责 | 不应越权承担的职责 |
|---|---|---|
| WMS/WES/MES/ERP | 业务订单、库存/工单、生产或仓储流程 | 不应直接控制底盘运动或绕过RMS资源协调 |
| RMS/FMS | 任务分配、任务生命周期、车队状态、交通/资源协调、异常闭环 | 不应替代机器人本体安全功能或单机实时控制 |
| 机器人端 | 定位、导航执行、动作执行、状态反馈、局部故障处理 | 不应假设中心链路永远在线；需定义断网行为 |
| 现场设施系统 | 门、电梯、输送线、充电设备、工位等设备控制 | 不应仅凭RMS软件状态推断物理设备已安全就绪 |

## 2. RMS核心功能

| 模块 | 典型职责 | 关键设计点 |
|---|---|---|
| 任务接入与编排 | 接收订单、拆分子任务、依赖和优先级 | 幂等、重复订单、取消/暂停/恢复、任务版本 |
| 任务分配 | 选择具备能力且可用的机器人 | 载荷/技能/楼层/区域权限、电量、预计到达时间、任务时限 |
| 交通协调 | 协调走廊、路口、窄道、交叉口和共享区域 | 冲突模型、预约、优先级、死锁检测、保守恢复 |
| 地图与区域 | 管理地图版本、区域、限速区、禁行区和站点 | 坐标系、地图版本兼容、机器人能力约束 |
| 车队监控 | 位置、运行模式、电量、故障、任务状态和通信状态 | 数据时效性、状态可信度、离线/过期数据标识 |
| 充电与能源 | 充电任务、充电桩分配、换电和待命管理 | BMS约束、预计能耗、排队、低电量滞留风险 |
| 设施集成 | 电梯、门禁、输送线、充电设备、工位 | 设备状态确认、超时、联锁、人工兜底 |
| 运营分析 | 吞吐、等待、利用率、异常、人工干预和趋势 | 指标定义、统计窗口、分母、异常分类 |
| 仿真与回放 | 回放任务/车队事件，验证调度策略和异常流程 | 场景覆盖、随机种子、地图/算法版本、仿真与实机差异 |

## 3. 关键接口与标准

### 3.1 ISO 21423:2026

ISO 21423:2026《Robotics — Industrial mobile robots — Communications and interoperability》于2026-10-14发布。ISO公开摘要说明，其目标是在共享工业环境中规范以下对象两者或多者之间的通信要求：

- 工业移动机器人（IMR）；
- IMR车队管理器（IMRFM）；
- 共享工业环境中的其他机器、设备和应用，例如ERP工具、升降机、报警系统和自动门。

其公开范围说明还明确排除娱乐、消费、军事、医疗和公共道路应用；该标准**不是安全相关标准，不包含安全要求，也不覆盖导航要求**。因此：
- 不可用ISO 21423代替ISO 3691-4等适用安全要求；
- 不可将其当作机器人单机导航接口或运动控制协议；
- 需要根据正式标准文本核对对象、消息、状态、错误和接口责任；
- 本页只依据ISO官方公开摘要和生命周期信息说明范围，不声称已完成85页标准全文逐条条款审查或符合性评估。

### 3.2 VDA 5050

截至本页更新日期，VDA官方页面推荐版本为 **VDA 5050 3.0.0（2026年3月）**。它是VDA/VDMA发布的移动机器人与中央车队控制系统之间的通信接口建议，GitHub仓库用于规范文本和JSON Schema维护。旧版本不再被官方推荐或继续开发；具体项目应锁定采用的正式PDF版本、JSON Schema版本和机器人/车队控制实现版本。

VDA 5050 v3.0.0的主要范围和边界：
- 用于中央车队控制与移动机器人之间交换订单、动作、状态等信息；
- 目标是支持异构移动机器人在共享环境中的协同运行；
- v3.0.0扩展了自由导航移动机器人的支持，包括计划路径共享和区域（zone）相关机制；
- **不定义安全要求、交通管理算法、外围设备/外部IT系统的其他通信接口、项目验收流程、运营责任分配或网络安全措施**；
- 规范本身是可选、非约束性建议，不等于认证或合规证明。

### 3.3 VDA 5050与ISO 21423的关系

两者关注面不同：

| 比较项 | VDA 5050 | ISO 21423:2026 |
|---|---|---|
| 文件性质 | VDA/VDMA接口建议 | 国际标准（ISO） |
| 核心通信对象 | 中央车队控制系统与移动机器人 | IMR、IMRFM及共享工业环境中的其他设备/应用 |
| 典型范围 | 车队控制与机器人间任务/状态交换 | 工业环境多对象通信互操作 |
| 安全要求 | 不定义 | 不属于安全相关标准 |
| 导航要求 | 不定义导航算法/导航要求 | 明确排除导航要求 |
| 交通管理算法 | 不定义交通管理逻辑 | 不能仅凭公开摘要推断具体实现要求 |
| 外围设施/外部IT接口 | 明确不在其机器人—车队接口范围内 | 公开范围涵盖其他机器、设备和应用间通信 |

不能根据名称或参与对象重叠就断言二者完全兼容、相互替代或一方取代另一方。落地时应购买/获取适用的正式标准文本，逐项建立对象、字段、消息、状态、错误、能力和安全责任映射，并通过跨厂商互操作测试验证。

### 3.4 其他常见接口类别

| 接口 | 常见用途 | 需明确的边界 |
|---|---|---|
| REST / WebSocket / gRPC | RMS与WMS/WES/MES、运营看板或业务服务 | 业务对象、鉴权、版本、幂等、超时和重试由项目定义 |
| MQTT | 事件、遥测、设备状态或项目自定义接口 | Topic权限、QoS、消息顺序、重复投递、保留消息和离线行为 |
| OPC UA Robotics | 工业机器人/设备信息模型与工业自动化集成 | 核对具体信息模型版本、设备支持范围和信息映射 |
| 厂商私有API | 厂商机器人、设施或RMS集成 | 必须获取接口文档、版本、错误码、速率限制和支持策略 |

“支持某协议”不等于完整互操作。必须核验双方支持的版本、必选/可选字段、扩展字段、能力差异、状态机和异常语义。

## 4. VDA 5050 v3.0.0消息模型概览

VDA 5050通过MQTT与JSON交换消息，MQTT 3.1.1是规范要求的最低兼容版本。v3.0.0定义的Topic包括：

| Topic | 方向 | 状态 | 作用 |
|---|---|---|---|
| `order` | Fleet Control → Mobile Robot | 必选 | 下发订单/路线节点与边及相关动作 |
| `instantActions` | Fleet Control → Mobile Robot | 必选 | 下发即时动作 |
| `state` | Mobile Robot → Fleet Control | 必选 | 机器人状态、订单执行和动作状态 |
| `connection` | Broker/Robot → Fleet Control | 必选 | MQTT连接状态信号；不应用作完整机器人健康检查 |
| `factsheet` | Mobile Robot → Fleet Control | 必选 | 机器人能力/参数等配置辅助信息 |
| `visualization` | Mobile Robot → 可视化系统 | 可选 | 高频位置和计划路径可视化 |
| `zoneSet` | Fleet Control → Mobile Robot | 可选 | 区域集合传输 |
| `responses` | Fleet Control → Mobile Robot | 可选 | 对机器人发起请求的响应 |

**不要将消息频率写成协议固定值。** 状态与可视化的发布策略取决于实现、业务和网络设计；应结合规范要求、设备能力、QoS、带宽、延迟和端到端监控配置并测试。特别是可视化Topic的高频特征不等于可以将其作为安全控制或实时制动链路。

VDA 5050 v3.0.0对MQTT QoS的规定也有区别：大多数业务Topic采用QoS 0，`connection`采用QoS 1。QoS等级不等同端到端业务确认；任务接收、执行、取消和恢复仍需结合消息ID、订单版本、状态回报、超时和重连策略处理。规范指出通信安全需由Broker配置考虑，但不在该指南范围内；项目仍须独立设计TLS、身份认证、Topic ACL、证书/密钥生命周期和网络分区。

### 4.1 v2.x 到 v3.0.0 的兼容性与迁移重点（2026-11-05复核）

VDA官方页面当前推荐 **3.0.0（2026年3月）**；官方GitHub release将3.0.0标记为最新发布版本，发布说明强调本次不只是增加可选字段，而是对多个消息字段、状态机和动作语义进行了重构。不能把 v2.x 与 v3.0.0 当作只增加可选字段的兼容升级。

迁移时至少核对以下变化（以VDA正式PDF为准）：

- **自由导航与交通影响**：新增 zone 概念和 planned/intermediate path sharing；机器人可在指定区域规则下自行规划路径，并向车队控制共享计划路径。RMS必须明确 zone 几何/语义、授权与撤销、路径时效、地图版本、定位可信度和冲突处理。路径共享可以支持交通管理，不因此成为安全制动链。
- **运行模式与动作状态**：运行模式、blocking type、action state均有重构；新增 STARTUP、INTERVENED 等模式以及 RETRIABLE 动作状态；动作状态数组拆分。RMS不能仅靠旧版枚举或“任务成功/失败”二值映射来处理新状态。
- **字段和单位语义**：positionInitialized改为localized；电池状态结构调整为powerSupply，电量字段改为stateOfCharge；时间戳精度从百分之一秒调整为千分之一秒。适配层必须审查序列化、单位、精度、空值和旧字段映射，避免静默截断或把“已初始化”误解为“定位可信”。
- **任务控制和错误语义**：暂停/恢复/取消动作要求、错误等级和错误描述结构均有调整；发布说明新增CRITICAL、URGENT错误级别，并将startPause、stopPause、cancelOrder列为移动机器人必须支持的动作。必须按规范状态转移矩阵处理重复、迟到、冲突和重连后的消息。
- **订单与幂等**：首个新订单的orderUpdateId从0开始；相同orderUpdateId重发与相同ID但内容不同的情况有明确区分；已取消订单不得再次更新。实现应将“网络重发”与“业务新版本”区分开，避免重复执行动作或接受过期订单。
- **版本隔离**：Topic层级包含接口主版本；部署清单应分别记录车队控制器、机器人、Broker、JSON Schema和正式PDF版本。不得仅凭双方都宣称“支持VDA 5050”就推断可互操作；v2/v3并行时应显式隔离Topic命名空间、ACL、转换网关和回滚路径。

**迁移验收至少包含：** 正式PDF与JSON Schema版本/哈希锁定；每个字段与枚举的映射差异表；新旧消息的正向/负向Schema测试；订单更新/重复/取消/断线重连测试；暂停/恢复/介入/可重试动作状态机测试；zone/path sharing与地图/坐标版本测试；时间戳精度和时钟偏差测试；Broker认证、TLS、Topic ACL与异常断连测试。协议层测试通过不等于多厂商互操作、交通安全或现场验收通过。

**版本治理边界：** VDA官方说明旧版本不再推荐或继续开发；GitHub仓库说明其主分支跟随最新发布文档，若仓库Markdown/JSON Schema与VDA发布PDF不一致，以VDA PDF为准。GitHub release notes可用于识别变更点，但不能替代正式规范条文。来源台账 #1098–#1100。

## 5. 任务分配与调度策略

任务分配（谁执行哪个任务）、任务排序/车辆路径（按什么顺序访问任务点）、多智能体路径规划（如何避免路径冲突）和现场资源预约（何时占用窄道/电梯/工位）是不同层次的问题，不能混为一个算法。

| 方法 | 适用问题 | 主要限制 |
|---|---|---|
| 规则/贪心 | 快速基线、简单任务和确定性优先级 | 局部最优，可能饥饿或造成频繁重分配 |
| 匈牙利/线性指派 | 一轮简单的一对一机器人—任务匹配 | 不直接解决多站点VRP、复杂容量、时间窗和持续在线派单 |
| 拍卖/市场机制 | 将机器人能力和任务代价纳入分布式或集中式出价 | 结果依赖出价函数、任务捆绑、冲突处理和通信条件 |
| MILP / CP-SAT | 约束复杂的分配、时间窗、容量和依赖问题 | 规模扩大后求解时间和最优性证明可能受限；需处理超时与可行解状态 |
| VRP/VRPTW求解 | 多站点访问顺序、车辆容量和时间窗 | 不等同于实时交通冲突协调；需连接现场路网与资源模型 |
| MAPF / 交通预约 | 多机器人路径冲突和共享资源协调 | 抽象图路径不自动满足真实机器人footprint、运动学、制动和定位误差 |

Google OR-Tools提供Assignment、CP-SAT和Routing等不同建模工具；应先判断问题模型，再选择求解器。**不采用“50台以下CP-SAT必定毫秒级”等未经基准测试的性能承诺。** 对实际项目，至少记录问题规模、变量/约束数量、硬件、求解时限、求解状态（如OPTIMAL/FEASIBLE/UNKNOWN）、目标值、可行性检查和超时降级策略。

## 6. 交通管制与共享资源

常见资源包括单向/双向走廊、窄道、交叉口、电梯、自动门、工位、缓冲区和充电桩。每项资源应定义：
- 资源ID、地图版本、容量、方向和互斥/共享规则；
- 预约者、任务、预计进入/退出时间、预约版本和确认状态；
- 进入/离开事件、实际位置、定位质量和设施状态；
- 超时、取消、续约、通信失联和人工恢复流程。

**预约超时不等于资源已释放。** 若机器人可能仍在窄道、电梯或工位内，不能只因租约到期就允许其他机器人进入。释放必须结合实际占用/退出确认、设施传感器、机器人状态和故障恢复策略；无法确认时应采取保守锁定并升级人工处理。

死锁、拥堵、重规划风暴和设施故障都应纳入设计。VDA 5050只定义机器人与车队控制之间的通信接口，不替代RMS内部的交通管理算法。Open-RMF可作为ROS 2生态中交通调度、计划轨迹协商和Fleet Adapter集成的参考，但每种机器人/设施仍需实现适配与现场配置。

## 7. 充电、设施与能源调度

派单不能只依据SOC百分比。至少考虑：
- 电池/BMS允许的温度、电流、充放电和健康约束；
- 当前载荷、路线、地面条件、任务类型和剩余任务能耗；
- 回充路线可达性、充电设备能力、占用和排队；
- 任务截止时间、充电机会成本、备用机器人和任务迁移；
- 低电量停滞是否阻塞交通资源，以及失联时的安全处理。

不要把某个SOC阈值、充电队列长度或夜间满充规则作为所有电池体系和业务场景的通用建议；以电芯/电池包/BMS规格、制造商策略和实测数据为准。

## 8. 运营指标与容量规划

建议至少定义以下指标及其分母、统计窗口和排除规则：

| 类别 | 指标示例 | 口径注意 |
|---|---|---|
| 业务 | 订单完成率、任务吞吐量、按时完成率 | 区分订单、子任务和机器人执行次数 |
| 效率 | 任务周期P50/P95、等待时长、空驶比例、机器人利用率 | 说明排队、充电、故障和人工接管是否计入 |
| 交通 | 资源排队时间、阻塞持续时间、死锁/人工恢复事件率 | 按运行小时、任务数或资源占用次数归一化 |
| 能源 | 单任务能耗、充电占比、充电等待和回充失败 | 结合载荷、路线、温度和电池健康状态 |
| 可靠性 | 通信失联、定位异常、故障恢复时长、人工介入率 | 区分机器人、RMS、网络和设施侧故障 |

容量规划不能引用“单RMS支持200–1000台”作为通用上限。规模能力受机器人型号/异构程度、任务到达率、路网拓扑、共享资源瓶颈、状态更新频率、网络质量、数据库/消息架构、冗余部署和运维流程共同影响。应通过目标场地负载模型、压力测试、故障注入和逐步扩容确定。

## 9. RMS采购、自研与集成评估

不要简单按“搬运采购、清洁/服务自研”划分。评估应基于：
1. 机器人类型、厂商数量、异构程度和现有接口成熟度；
2. WMS/WES/MES、门、电梯、输送线等设施的集成复杂度；
3. 交通管制、任务规则、调度策略是否构成产品差异化；
4. 部署规模、可用性、冗余、网络分区和数据治理要求；
5. 供应商接口开放程度、版本兼容、支持周期、许可和退出成本；
6. 安全责任、运维团队能力、故障响应和长期维护成本。

采购、自研或混合方案都需要通过同一组接口、异常、性能、运维和安全验收用例。

## 10. 仿真、集成与验收

建议分层验证：
- **接口契约：** Schema、必选/可选字段、版本兼容、错误码、幂等、重复/乱序消息。
- **任务生命周期：** 创建、分配、接受、执行、暂停、恢复、取消、重派、超时和异常终止。
- **交通资源：** 双向窄道、交叉口、电梯/门、资源预约超时、设施失联和恢复对账。
- **车队负载：** 任务突发、机器人离线、状态风暴、数据库/消息Broker故障和RMS主备切换。
- **现场验证：** 地图/坐标、定位误差、制动与安全功能、无线网络、真实载荷、设施响应和人工接管。

测试记录必须包含软件/协议版本、机器人型号与数量、地图/任务集、网络条件、硬件规格、运行时长、重复次数、原始日志和失败样本。仿真或接口通过不能替代现场安全验证、法规评估和产品验收。
