# 调度系统 RMS（Robot/Fleet Management System）

> 多机器人系统的"交通局+任务局"。单机能力 × 调度效率 = 整场效率；80 分的单机 + 90 分的调度 > 95 分的单机 + 60 分的调度。

## 系统分层（场级视角）

```
WMS/WES(仓库/制造执行: 订单从哪来到哪去)
   ↓ 任务流(出入库单/搬运单/清扫单)
RMS 调度系统(本页): 任务分配+路径管制+车队管理
   ↓ VDA5050 或私有 API
单机导航栈(Nav2/自研) + 云平台 → [[云平台与IoT通信]]
```

## 关键接口标准

| 标准 | 内容 | 现状 |
|---|---|---|
| **ISO 21423:2026** | 工业移动机器人、车队管理器与共享工业环境其他设备/应用之间的通信互操作要求 | 2026-10 发布；范围覆盖工业现场的 IMR/IMRFM/设备/ERP/基础设施互操作；不覆盖安全与导航；与已有接口协议的映射/共存需按标准正文评估 |

## ISO 21423:2026 与 VDA5050 的关系

ISO 21423:2026 是 2026-10 发布的工业移动机器人通信互操作国际标准。ISO 官方摘要说明，其目标是在共享工业环境中规范 IMR、IMR Fleet Manager（IMRFM）以及其他机器、设备和应用之间的通信；示例包括 ERP、升降机、报警系统和自动门。

**重要范围边界：** ISO 官方明确说明 ISO 21423:2026 不属于安全标准（没有安全要求），也不覆盖导航要求。它不能代替 ISO 3691-4、ANSI/A3 R15.08 等安全要求，也不能代替单机导航接口或安全功能验证。它与 VDA5050 的字段、消息、网关和兼容关系必须对照正式标准全文进行逐项映射；在未完成映射前，不得宣称二者完全兼容、互相替代或谁取代谁。

当前实践建议：
1. 将 ISO 21423:2026 纳入新建工业移动机器人车队系统的互操作标准调研。
2. 盘点 IMR、IMRFM、WMS/WES/ERP、电梯、自动门、设备控制器各自的数据责任和接口边界。
3. 建立协议字段/状态/事件/动作的映射矩阵，并验证异常、重复消息、断网和版本升级行为。
4. 将通信互操作验证与安全验证分离管理，分别建立验收证据。

官方来源与版本快照见 [[标准与法规]]（ISO 21423:2026，访问日期 2026-11-03）。

## VDA5050 消息骨架（懂这个就能对接主流 RMS）

```
order      : 下发节点序列(nodes/edges)+动作(pick/drop/charge)
state      : 车端回报(位置/电量/动作状态/错误) @1-2Hz
visualization: 高频位置(可到 5Hz)
instantActions: 即时指令(暂停/继续/取消/紧急)
```

## 性能指标（RMS 的 KPI）

- 整场吞吐（车/h）、任务平均等待/完成时间、拥堵率、死锁次数（应=0）
- 车队规模上限经验值：单 RMS 200-1000 台（拓扑复杂度决定）→ [[多机协同与调度算法]]
- 详见 [[性能指标体系]] · [[多机调度流程]]

## 选型/自研判断

- 纯搬运标准化场景 → 采购成熟 RMS（对接 VDA5050）
- 清洁/服务/特殊工艺 → 自研（业务状态机强耦合，如 [[项目-清洁机器人]]）
- 混合车队（AGV+AMR+叉车）→ 支持多协议适配层是关键

## 细节加深（V2）
- **VDA5050 官方规范入口**（台账 #93，快照 2026-11-01）：github.com/VDA5050/VDA5050（vda5050.org 官网 DNS 当前不可达，以 GitHub 为准）。
- **任务分配求解器直接用 OR-Tools**（台账 #80）：CP-SAT 解批量分配/带时间窗 VRP，Apache-2.0，别手写匈牙利——50 台以下规模 CP-SAT 毫秒级。
- **RMS 的一等公民是"异常"不是"任务"**：接口设计先定义暂停/恢复/取消/重派四件套（对应 VDA5050 instantActions），任务流反而简单。
