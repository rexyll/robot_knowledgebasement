# 09-06 操作系统选型与内核裁剪（从0搭建 · 第六步）

> 目标：给主脑选定 OS 并按需瘦身。**先说结论**：样机阶段用 Ubuntu Server 24.04（ROS2 Jazzy 官方支持）+ 标准内核；量产瘦身用 Buildroot/Yocto 自制系统；控制环硬实时加 PREEMPT_RT。三步走，不要一上来就裁内核。

## 1. 选型决策树

```
需要跑 ROS2 官方 deb 包?
 ├─ 是 → Ubuntu 24.04 (Jazzy 官方支持) ★默认
 │        ├─ 桌面机/调试机 → Ubuntu Desktop 24.04
 │        └─ 车端 → Ubuntu Server 24.04 (无 GUI, 省 1GB+ 内存)
 └─ 否(自研栈/深度定制) →
      ├─ 想要可维护 + 包管理 → Debian 12/13 (arm64)
      ├─ 量产固化 + 秒级启动 + <100MB → Buildroot ★比 Yocto 平缓
      └─ 车规/超大规模产品线 + 层复用 → Yocto (学习成本 2-4 周)
MCU 侧: 裸机 / FreeRTOS / Zephyr (→ [[实时系统与嵌入式]])
```

## 2. 三条路线对比

| 路线 | 镜像体积 | 启动 | 学习成本 | 适用 |
|---|---|---|---|---|
| Ubuntu Server 24.04 | 1.5-3GB | 10-30s | 0 | 开发/样机/ROS2 官方包 |
| Buildroot | 30-200MB | 2-5s | 中（1 周上手） | 量产小系统、专用网关 |
| Yocto | 50-500MB | 3-10s | 高（layer/BSP 概念多） | 车规、多硬件线复用 |

## 3. 内核裁剪实操（Ubuntu 基线上的「轻裁剪」）

> 真正的内核裁剪=make menuconfig 自编译；Ubuntu 上 80% 收益来自下面 4 步（不动内核源码）：

```
Step1 服务瘦身:
  systemctl disable --now unattended-upgrades cups snapd motd-news
  apt purge snapd (车端不需要 snap)

Step2 关交换+降日志:
  swapoff -a && sed -i '/swap/d' /etc/fstab
  journald SystemMaxUse=200M (车端存储金贵)

Step3 只装运行时:
  ros-jazzy-ros-base (不装 desktop), rosdep 按包拉依赖

Step4 启动加速:
  systemd-analyze blame 找大头 → disable 图形等待/网络等待
  目标: 上电到 roslaunch < 20s
```

**进阶（自编译内核）**：`make menuconfig` 里关掉用不到的驱动（显卡/文件系统/WiFi 驱动族）可从 250MB 瘦到 30-80MB，但每次 Ubuntu 内核升级会打架——**生产环境用 Buildroot 锁版本，别在 Ubuntu 上维护自编内核**。

## 4. PREEMPT_RT 实时化（按需）

- 2024 起 RT 补丁已并入主线内核（6.12+），Ubuntu 24.04 可装 `linux-image-rt-amd64`（universe 源）或用 Ubuntu Pro 的实时内核
- 验证实时性：`cyclictest -m -p95 -D 30min`，目标 max < 200μs
- 需要硬实时的只有「1kHz 关节控制」这一层——本样机的 1kHz PID 在 STM32 上，**Jetson 不需要 RT**（→ [[实时系统与嵌入式]] 分层论证）

## 7. 细节加深（V2）
- **Ubuntu 内核版本陷阱**：24.04 GA 内核 6.8，HWE 会滚到更新版本；LiDAR/相机 DKMS 驱动要锁定 GA 内核（`apt-mark hold linux-image-generic`），否则 OTA 升级内核后驱动挂掉。
- **Buildroot 一句话路线**：`make menuconfig` 选 Target(ARM64) → Toolchain → 选 kernel/u-boot 包 → `make`；产出 `sdcard.img` 直接烧——机器人网关类产品 2 周可出可维护镜像。
- **Yocto 心智模型**：metadata(layer) 食谱(recipe) 生成镜像；BSP layer（NVIDIA Jetson 用 OE4T 社区层）+ 自己的 meta-robot 层——第一次别硬啃，先 Buildroot。
