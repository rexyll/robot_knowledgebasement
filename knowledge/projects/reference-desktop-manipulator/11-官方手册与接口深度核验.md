# 11｜官方手册与接口深度核验

## 0. 目的与证据边界

本文件将 25-13 的产品候选由“参数页初筛”推进到“官方手册/接口资料核验”。本轮优先核验 CubeMars AK60-6 V3.0 KV80、ROBOTIS DYNAMIXEL XH430-W350-T、UFACTORY Lite 6 和 Elephant Robotics myCobot 280 M5。

**本文件不是选型批准，也不是安全/性能验证。** 只记录本轮公开可访问的厂商页面和手册入口。尚未下载并归档 PDF/ZIP 原件、核对文件哈希、对实物读回固件/参数、进行总线抓包或台架测试的内容，不得升级为“已验证”。

- 采购前确认每个 STS3215 的准确电压版本、齿比料号（C001/C044/C046）、批次和对应供电；特别确认 leader 固定使用 7.4 V 版本。

- 固定 LeRobot tag/commit、Feetech SDK 版本、Python 环境和控制板固件；对 leader/follower 分别保存电机 ID、零位/标定参数和配置文件。
- 对 3D 打印件记录 STL commit、材料牌号、打印方向、层高、填充、壁厚、打印机和后处理；开展配合、刚度、耐久和紧固件松脱验证。

| 保护 | 堵转大于堵转扭矩 80%持续 2 s 后过载保护；运行电流大于 2 A 持续 2 s 后关闭输出；过压高于 7.4 V 或低于 4 V；温度高于 70°C 关闭扭矩输出 | 过载/过流逻辑描述相近；过压条目写高于 16 V 或低于 5 V；温度高于 70°C 关闭扭矩输出 | 保护阈值出现型号/版本差异，且 C044 的 16 V 与其 5–8.4 V 输入范围需供应商确认是否笔误/配置项；不得当作整机安全保护 |
| 寿命试验 | >100,000 次；60°正转0.25 s、停0.5 s、60°反转0.25 s、停0.5 s；负载为 1/5 堵转扭矩 | >100,000 次；相同或近似循环描述，负载为 1/5 堵转扭矩 | 这是规定单一试验循环下的样本结果，不是现场 MTBF、任务寿命或所有齿比/负载的寿命保证 |

**总线与控制板的当前证据边界：**
- 已确认电机端为三线连接器，规格书将 1=GND、2=Vcc、3=Signal/TTL；但尚未确认 SO-101 套件实际线束的线色、连接器公母端、针脚视角和反接防护。
- LeRobot 文档给出 1 Mbps 与 ID 1–6 的配置示例；Feetech 规格书给出 38.4 kbps–1 Mbps 的串行范围。两者可相互印证配置区间，但不能据此推导六轴轮询/同步反馈的最大刷新率。
- Motor Control Board 的准确制造商/型号/硬件版本、原理图、USB-UART/TTL 收发器型号、总线驱动能力、供电路径、反接/过流保护、板上保险丝、热设计、固件版本和急停行为仍未取得受控资料。
- 目前没有可引用的完整 Feetech STS 协议/控制表，因此不记录未经证实的寄存器地址、字节缩放、指令帧、校验算法、反馈周期或掉线动作。

**必须向 Feetech / 套件供应商书面确认：**
1. SO-101 当前 C001、C044、C046 的实际供货料号、批次、固件版本和各自受控规格书；C046（1/147）目前未取得准确型号规格书。
2. C001 通用规格书的 4–7.4 V 输入范围、7.4 V 过压阈值与 SO-101 推荐供电之间的关系；C044 规格书 5–8.4 V 范围与 16 V 过压保护阈值是否正确。
3. 过载百分比、持续时间、电流阈值、过压阈值和温度阈值能否被固件/批次配置修改；触发后是否锁存、如何清除、清除命令是否会立即重新使能扭矩。
4. 完整协议文档/控制表：寄存器地址、长度、端序、符号、单位/缩放、读写权限、状态返回级别、错误码、指令超时和失联行为。
5. Motor Control Board 的准确型号、原理图、接口针脚、供电额定/峰值电流、USB 隔离/接地、总线拓扑和硬件保护资料。
6. 寿命测试样本量、失效判据、环境温度、安装边界、齿比 SKU 是否逐一测试，以及测试后性能漂移。

**工程判断：** STS3215 可作为低成本串行总线舵机候选，但公开资料尚不足以支持高可靠机械臂的动态选型、力控设计或安全论证。额定负载、堵转参数和保护阈值必须绑定具体齿比 SKU 与固件批次；Motor Control Board 未经识别和验证前，SO-101 的电气接口基线仍不完整。

### 1.7 ST3215 系列协议与控制表（WaveShare 官方文档参考）

**适用范围说明：** WaveShare 官方 ST3215 文档公开了 ST 系列 TTL 串行协议、内存表和兼容开发资源。它补足了协议/控制表层面的公开资料，但不能自动证明 SO-101 套件随附的 Motor Control Board 就是 WaveShare Bus Servo Adapter (A)，也不能证明所有 Feetech STS3215 固件/批次与 WaveShare 文档完全一致。实际使用前必须读回电机固件版本、舵机型号版本和关键寄存器，并与实物抓包比对。

| 项目 | WaveShare 官方 ST 系列资料给出的定义 | 工程边界 |
|---|---|---|
| 物理层/帧 | ST 系列为 TTL；异步串行 8N1；控制器与舵机采用命令/响应方式；单总线多节点用唯一 ID | 与 Feetech STS3215 规格书的半双工 8N1、TTL、ID/波特率范围一致；仍需对目标板确认方向切换/收发器电路 |
| 帧结构 | `FF FF` 帧头，随后为 ID、Length、Instruction、Parameters 和 Checksum 字段；Length=N+2；Checksum 为 ID、Length、Instruction、参数字节求和低 8 位后按位取反 | 这是可实现的协议格式证据，但仍需用目标电机抓包核验兼容性 |
| 字节序 | 磁编码 ST 系列双字节值低字节在前（little-endian） | 不得误套电位器 SC 系列的大端序 |
| 指令 | PING 0x01、READ 0x02、WRITE 0x03、REGWRITE 0x04、ACTION 0x05、SYNC READ 0x82、SYNC WRITE 0x83、RESET 0x0A | SYNC READ 文档注明“部分串行舵机支持”；目标固件是否支持需实测 |
| 重要 EPROM | ID 地址 5；波特率地址 6；返回状态级别地址 8；最高温度地址 13；最大扭矩地址 16；卸载/保护条件地址 19；保护电流地址 28；工作模式地址 33；保持扭矩地址 34；保护时间地址 35；过载扭矩地址 36 | 文档列出的地址、默认值和权限需与目标固件读回值对照；不应未经记录直接写入 |
| 重要 SRAM 控制 | Torque switch 地址 40（0=关闭输出、1=使能、2=阻尼输出、128=当前位置校准为 2048）；加速度地址 41；目标位置地址 42；速度地址 46；扭矩限制地址 48 | “关闭输出”是舵机本体功能，不等同于系统级断能或安全停止；写入配置前应评估重力负载/掉电坠落 |
| 反馈字段 | 位置 56（2B，0.087°/count）；速度 58（2B，单位受 phase 配置影响）；负载 60（2B，0.1%，是驱动输出占空比意义的估算量，不是经校准的 N·m）；电压 62（0.1 V）；温度 63（°C）；状态 65；运动标志 66；目标位置 67；电流 69（6.5 mA/count） | “Load”不可当作外部力矩传感器；速度缩放受地址18 phase 配置影响；位置符号/多圈模式也需按文档与固件核验 |
| 状态位 | 地址 65：bit5 过载、bit3 过流、bit2 过热、bit1 磁编码异常、bit0 过压/欠压；地址 19 可配置相应保护卸载条件 | 这些状态位不提供整机碰撞检测、STO 或安全等级；还要验证清除/恢复行为 |
| 多轴同步 | SYNC WRITE 0x83 可对多个 ID 同时写相同起始地址/数据长度；SYNC READ 0x82 可一次请求多个 ID，响应按 ID 顺序返回 | 六轴控制周期必须计入总线帧长、状态回包、主机调度、USB-UART 延迟和重试；“支持同步指令”不等于 1 kHz 六轴闭环已被证明 |

**对 SO-101 的接口决策影响：**
- 当前可将 STS3215 的候选串行数据契约写成“TTL 半双工、8N1、默认 1 Mbps、12-bit 位置、低字节优先、ST 帧协议”；在实物确认前标注为“厂商/兼容文档参考”，不作为已验证 ICD。
- 必须先识别控制板型号。SO-ARM100 BOM 只写 Motor Control Board，并提供 WaveShare 安装板 STL；这不足以证明电路板型号。WaveShare 官方另有 Bus Servo Adapter (A)、ESP32 Servo Driver、驱动电路原理图和 SDK 资源，它们属于可用的参考实现/资源，不应直接视为 SO-101 套件 BOM 中的指定板卡。
- USB Type-C 只负责数据、不能替代舵机电源输入；WaveShare Adapter 教程建议通过 DC5521/端子给总线供电。此供电说明仅适用于相应 WaveShare 板卡，不能替代 SO-101 实际板卡输入规格。
- 控制板资源页列出通信协议、ST 内存表、驱动电路原理图、Python/Arduino/Linux SDK 和 STM32F103 SDK，可作为后续软件与电气审查入口；本轮没有下载归档这些 ZIP/XLS/PDF 原件，也没有验证目标 SO-101 控制板。
- 当前仍缺失：SO-101 随附板卡准确 SKU/版本、原理图、USB 桥/TTL 收发器型号、供电额定/峰值电流、反接/过流保护、隔离与接地、掉线/复位行为、固件哈希和六轴实际刷新率。

**工程判断：** 协议层已从“只有串行类型和波特率”推进到“可读懂帧结构、指令类型、控制表地址和反馈缩放”的公开资料级别；但这些是 WaveShare ST 系列参考文档，不是对 SO-101 套件板卡和实际 STS3215 固件的实机确认。后续必须做电机型号/固件读回、控制表关键字段核对、抓包和六轴同步读写时序测试。

### 1.8 LeRobot / rustypot 驱动实现与 STS3215 控制表逐项对照

**审查范围与版本边界：** 本节审查 Hugging Face LeRobot `main` 分支的 SO follower 实现、`SerialMotorsBus`、Feetech 行为测试，以及 Pollen Robotics 的 rustypot `develop` 分支 STS3215 定义。它们是可变动的开发分支，不等同于已锁定的 LeRobot 稳定发行版；当前 LeRobot API 文档明确说明 `main` 需要源码安装，`FeetechMotorsBus` / `DynamixelMotorsBus` 是过渡期弃用别名，底层串行通信与型号元数据已由 rustypot 接管。正式项目必须锁定 commit/tag、Python 包版本和 rustypot 版本。源码审查不代表在 SO-101 实物控制板上通过了验证。

| 维度 | LeRobot / rustypot 当前实现 | 对接口/验证的意义 |
|---|---|---|
| 驱动架构 | SO follower 使用 `SerialMotorsBus`；rustypot 提供每型号 ServoDefinition、控制表、串行端口与协议处理；LeRobot 负责归一化、标定和推荐设置 | 不应继续把旧版 Feetech SDK 适配层当成当前 main 的唯一实现；部署时需检查实际安装版本 |
| 型号识别 | rustypot 的 STS3215 model number 为 777；LeRobot connect handshake 检查每个 ID 是否响应预期型号，并检查同一 Feetech 定义下电机的 firmware major/minor 是否一致 | 可在连接时发现缺失 ID、错误型号和同系列固件版本混杂；这不是固件安全认证，也不检查所有参数是否符合 SKU |
| 编码/分辨率 | 4096 steps/rev（12-bit）；little-endian；位置、速度、偏置/回零偏移使用 sign-magnitude 编码；STS3215 的 homing offset 符号方向在定义中为 -1 | 不能只按普通有符号整数解析原始寄存器；必须按型号定义处理符号位、端序和单位 |
| 波特率/模式 | 出厂 1 Mbps；支持表含 1 Mbps、500 kbps、250 kbps、128 kbps、115.2 kbps、57.6 kbps、38.4 kbps、19.2 kbps；位置/速度/PWM/step 模式映射值分别为 0/1/2/3 | 与 LeRobot SO-101 配置示例的 1 Mbps 相符；切换模式应在 torque off 条件下执行 |
| 连接握手 | 默认 connect(handshake=True)：逐个核对 model number，再同步读取 firmware major/minor 并检查同一型号定义下版本一致；失败会关闭已打开串口 | 应将型号/固件读回结果纳入产线和维修记录；“型号正确”不代表具体齿比 SKU、额定电压或批次已确认 |
| 上电配置 | `configure_motors()` 默认将 Return_Delay_Time 写为 0（单位 2 µs；电机出厂文档值 250，即 500 µs），将 STS 的 Maximum_Acceleration 和 Acceleration 写为 254；STS3215 还读取 Phase 并清除 bit4，以维持位置反馈在 [0, 4095] | 这些是软件推荐配置而非厂商对所有 SO-101 版本的安全参数；应记录配置前后寄存器值，确认是否与实际固件兼容 |
| 位置环设置 | SO follower 在 torque-disabled 上下文中配置 position mode，并写 P/I/D 系数；当前配置默认 P=16、I=0、D=32 | 这些是软件默认参数，不代表经过本项目负载谱整定；实际响应、过冲、温升和稳定性需实测 |
| 夹爪保护参数 | 当前 follower 代码对 gripper 写 Max_Torque_Limit=500、Protection_Current=250、Overload_Torque=25，注释分别称为最大扭矩/最大电流的 50% 与过载扭矩 25% | 仅适用于该代码路径中的 gripper 设置；不等于整机扭矩限制或安全功能，单位/寄存器语义还须按准确 SKU 固件核对 |
| 标定 | connect 时假定机械臂处于 rest position，随后可在 torque off 状态手动标定；记录半转回零偏置和各轴范围；wrist_roll 被配置为 full-turn motor | 这是有人工参与的安装/维护流程；不应在负载悬空、可能坠落或未机械支撑的状态下盲目断扭矩 |
| 观测/命令 | follower 的 get_observation 只对 Present_Position 做 sync_read；send_action 通过 sync_write 写 Goal_Position；如配置 max_relative_target，则先读 Present_Position 再裁剪目标 | 当前主观测路径未主动读取 Status、Present_Current、Present_Temperature 等字段；项目若需要故障/热监测，应单独设计采集和联锁 |
| 同步读语义 | rustypot 对同协议、同地址和长度的电机分组发送 Sync Read；LeRobot API 明确提示返回值不保证是同一时刻的同步快照，未支持 Sync Read 的舵机会逐个读取 | 六轴读回存在采样时差；需实测每轴时间戳/总线事务耗时，不能将“sync”理解成零时差同步采样 |
| 同步写语义 | Sync Write 不等待舵机应答，适合控制环，但丢包不会被舵机确认；普通 write 有应答，适合配置 | 位置命令广播后必须用后续状态读回、超时/看门狗和独立安全策略处理执行失败；不能仅凭函数返回认定每个舵机已执行 |
| 故障状态语义 | rustypot 的 STS3215 定义将 status alarms 视为告警而非通信拒绝；LeRobot 测试验证即使 Status 有 overload alarm，普通 read/write/sync_read 仍可继续 | 告警位不会自动等同于 API 异常；应用必须显式读取和解释状态字，避免“通信成功”被误判为“设备健康” |
| 可选目标限幅 | `max_relative_target` 默认 None；仅在用户配置非空时才先读取当前位置并限制相对目标幅度 | 默认配置不启用该软件限幅；即使启用也不是安全认证、碰撞检测、硬件限位或 STO |

**六轴总线频率证据（非保证值）：** rustypot README 报告，在一条 6 电机、1 Mbaud 的总线上，同时有第二个 Python 线程竞争时，将 Python `sys.setswitchinterval` 从默认 5 ms 调至 1 ms，示例吞吐由 126 Hz 提升到 340 Hz。该数字是库作者给出的特定软件/线程条件下观测值，不是 SO-101 官方保证、不是本项目实测，也不能直接作为 6 轴闭环频率承诺。实际性能取决于控制板 USB 延迟、串口适配器、固件回包、总线负载、主机调度、相机线程、重试次数和动作负载。

**与 WaveShare ST 文档的对照结论：**
- rustypot STS3215 定义的寄存器地址与 WaveShare ST 系列内存表在 ID、波特率、Phase、保护、Torque Enable、Goal Position、Present Position/Velocity/Load/Voltage/Temperature/Status/Current 等主要字段上高度对应；这增强了“同属 ST 系列协议布局”的软件证据。
- rustypot 使用的模型号 777、4096 分辨率、小端序、sign-magnitude 编码、homing offset 方向，以及 Phase bit4 处理，属于比一般协议概览更具体的型号实现信息。
- LeRobot 当前驱动并不在每个观测周期读取状态/电流/温度；同时 Sync Write 没有舵机应答，Sync Read 也不是严格同一时刻快照。必须将“命令已发出”“总线读写无异常”“舵机无报警”“关节运动达到目标”作为不同状态处理。
- 当前测试文件中的故障/固件/Phase 测试使用 mock bus；这些是软件单元测试证据，不是实际舵机、控制板、线束或六轴机械臂测试。

**建议写入本项目 ICD 的暂定软件接口契约（待实机确认）：**
1. 每臂独立串口总线，目标速率 1 Mbps；STS3215 型号定义 model number=777，12-bit 4096 steps/rev，小端序，位置/速度/偏置按 STS sign-magnitude 规则解释。
2. 建链时逐 ID 读取型号并核对同型号电机固件版本；记录电机标签、model number、firmware major/minor、ID、波特率、齿比 SKU、电压版本和控制板硬件/固件版本。
3. 运动数据路径使用 Present_Position Sync Read 与 Goal_Position Sync Write；同步读按“批量请求”而非“同一时刻采样”定义，Sync Write 结果需要独立回读/监测。
4. 另设健康监测周期读取 Status、Present_Current、Present_Temperature、Present_Voltage；定义报警位映射、过载/过流/过温/欠压的降级和停机状态机，并实测恢复/清除行为。此项是本项目设计建议，不是当前 LeRobot 默认实现。
5. 为每个总线周期记录发送/接收时间戳、每轴反馈到达时间、丢包/重试/超时和控制周期分布；至少在空载、额定任务候选负载和最不利同时运动条件下测量。
6. 在未明确失联安全行为、重力轴支撑/制动策略、独立急停/断能链之前，不得把 disable torque、disconnect 或软件目标限幅当作安全停止。

## 2. 证据等级和不能推导的结论

| 公开资料事实 | 不能据此推导 |
|---|---|
| 峰值扭矩、堵转扭矩 | 连续扭矩、持续时间、全速度范围可用输出 |
| 额定扭矩/额定功率单点 | 任意速度和环境下的热稳态工作点 |
| 负载 payload | 任意姿态/速度/加速度/重心下的允许载荷 |
| 最高波特率/接口类型 | 多轴网络在给定更新频率下无丢包、低抖动 |
| 温度阈值/过温保护 | 整机风险降低到可接受或满足功能安全 |
| 3D 模型/DH 参数 | 实物零位、安装公差、标定精度与可达性已验证 |
| CE 或页面上的安全宣传 | 本项目具体配置满足适用法规或协作安全要求 |

## 3. 面向桌面分拣任务的统一验证输入

在对比任何产品之前，必须填写 [07 任务负载谱与输入模板](07-任务负载谱与输入模板.csv)。至少把下列数据统一到相同单位和工况：

1. 末端总质量：夹具、线缆、传感器和工件合计。
2. 末端质心：相对法兰/TCP 的三轴偏置。
3. 任务位姿：供料、取料、转运、放料各点的 XYZ/RPY 和姿态容差。
4. 轨迹：每段速度、加速度、减速度、停留时间和循环频率。
5. 工件：质量范围、外形包络、惯量估计、抓取力/摩擦边界。
6. 工作制：每小时循环数、每日小时数、连续运行时长、环境温度和冷却条件。
7. 故障工况：卡滞、掉电、通信丢失、编码器异常、急停和人工恢复流程。

整机候选先做工作空间/姿态/碰撞和任务节拍筛选；关节模组候选再做逐关节重力、惯性、摩擦和外力矩计算。所有计算应保留输入、模型版本、单位、边界条件和审查人。

## 5. 本轮结论与下一步

- 本轮确认了几类官方资料的存在、型号边界、接口类别和部分控制表/手册版本。
- CubeMars 的 V3 手册和安装说明已按型号列出，但尚未下载审读具体 CAN 参数表与完整曲线。
- ROBOTIS e-Manual 已可核对 TTL/Protocol 2.0、温度/电流限制、硬件错误状态和 Bus Watchdog 控制表；这些功能仍需在目标设备上验证。
- UFACTORY 已公开 Lite 6 Hardware Manual v2.6.2、Developer Manual、DH 参数和 3D 文件入口；应下载后与模型坐标/实际固件核对。
- myCobot 280 M5 的工作寿命与机体质量存在需澄清的公开页面口径，不应在方案比较中隐藏。
- SO-101 已进一步核验 Feetech 通用 STS3215（A/0，2020-04-10）与 ST-3215-C044（A/0，2025-04-15）规格书，取得半双工串行、8N1、ID/波特率范围、反馈项目、逻辑电平、1 ms 最大位置更新率及保护/寿命测试口径；但 C001/C044 电压和过压阈值存在版本差异，C046 规格书、完整协议控制表及 Motor Control Board 原理图/硬件版本仍缺失。

**本轮没有产生胜出方案。** 下一步必须取得 07 输入模板中的真实任务数据，下载并归档匹配 SKU 的原始手册/图纸/SDK，完成接口与任务谱匹配；随后再建立 25-04 的定量评价矩阵。未完成以上步骤前，不得推荐采购或冻结 BOM。
