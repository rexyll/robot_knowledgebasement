# 11｜官方手册与接口深度核验

## 0. 目的与证据边界

本文件将 25-13 的产品候选由“参数页初筛”推进到“官方手册/接口资料核验”。本轮优先核验 CubeMars AK60-6 V3.0 KV80、ROBOTIS DYNAMIXEL XH430-W350-T、UFACTORY Lite 6 和 Elephant Robotics myCobot 280 M5。

**本文件不是选型批准，也不是安全/性能验证。** 只记录本轮公开可访问的厂商页面和手册入口。尚未下载并归档 PDF/ZIP 原件、核对文件哈希、对实物读回固件/参数、进行总线抓包或台架测试的内容，不得升级为“已验证”。

### SO-101 配置/采购确认项
- 采购前确认每个 STS3215 的准确电压版本、齿比料号（C001/C044/C046）、批次和对应供电；特别确认 leader 固定使用 7.4 V 版本。

- 获取 Feetech STS3215 完整数据手册及控制表，核对位置/速度/电流/温度反馈、单位/缩放、角度范围、堵转保护、温度保护和掉线响应。
- 固定 LeRobot tag/commit、Feetech SDK 版本、Python 环境和控制板固件；对 leader/follower 分别保存电机 ID、零位/标定参数和配置文件。
- 对 3D 打印件记录 STL commit、材料牌号、打印方向、层高、填充、壁厚、打印机和后处理；开展配合、刚度、耐久和紧固件松脱验证。

**关键澄清与工程解释：**

1. Wiki 的通用 STS 表明确写出“部分参数初始值与取值范围因型号而异”；地址14和19的初始值为空缺。即使某个寄存器被标为读写，也不代表该功能在 C046 固件中一定可写、可关闭或与规格书保护描述完全等价。
2. 地址19的卸载条件是独立使能位：BIT0电压、BIT1磁编码、BIT2过热、BIT3过流、BIT5负载过载。地址65状态反馈属于检测状态；地址20 LED报警又是独立配置。只读到错误状态，不能证明扭矩输出已经安全关闭。
3. 地址28的通用 Wiki 初始值511按6.5 mA/count换算约3.32 A；C046规格书的2 A/2 s若按同一电流单位粗略换算约308 counts，但这只是量纲换算，不是推荐写入值，也不能证明 C046 固件采用地址28/38这套实现。
4. 通用 Wiki 的地址15初始值40（4.0 V）明确注明按低压型号设定；C046规格书写低于5 V保护。两者之间的差异必须通过 C046 出厂寄存器读回和供应商书面确认解决，不可自行把阈值改成50。
5. 通用表的过载配置地址34/35/36与 C046 规格书“80%持续2秒”在数值上相似，但“保持扭矩20%”是通用表示例，不是 C046 规格书承诺。
6. 已追到 Wiki 的“源码定义”链接，指向 Feetech 官方 `ftservo/FTServo_Arduino` 仓库 `SMS_STS.h`。该头文件日期为2024-11-21，定义了 ID、波特率、角度限制、死区、偏置、模式、扭矩开关、位置/速度/负载/电压/温度/移动/电流等基础地址；**该头文件并未定义地址13–20、28、34–38或状态地址65的保护寄存器常量**。因此它不能作为这些保护寄存器在 C046 固件中的实现证明，也不能把 Wiki 表与该头文件描述成完整一一对应的源码实现。
7. 不能跨系列套用内存表；官方 Wiki 特别提示 SMS（RS-485）系列地址定义可能不同。本报告范围仅引用 STS 半双工 TTL 通用表。

**待供应商确认/实测：** 针对每个实际 C046 样件，先在不写寄存器的条件下读取并保存固件主/次版本、舵机型号版本、地址13/14/15/19/20/28/34/35/36/38、状态65及当前电压/温度/电流反馈；由 Feetech 书面确认这些地址对 C046 的支持性、单位、默认值、公差、保护触发/卸载逻辑、锁存与恢复行为。没有书面批准前，不写入保护阈值、不人为制造过压/过流/过热或堵转故障。

**本节结论：** 通用 STS Wiki 提供了可用于制定读回检查表的寄存器映射；官方 SDK 头文件只覆盖部分基础地址，没有为本次关注的保护寄存器提供代码定义。C046 的保护默认参数与固件映射仍属未确认事项，25-14 保持进行中。

- 当前可将 STS3215 的候选串行数据契约写成“TTL 半双工、8N1、默认 1 Mbps、12-bit 位置、低字节优先、ST 帧协议”；在实物确认前标注为“厂商/兼容文档参考”，不作为已验证 ICD。

- USB Type-C 只负责数据、不能替代舵机电源输入；WaveShare Adapter 教程建议通过 DC5521/端子给总线供电。此供电说明仅适用于相应 WaveShare 板卡，不能替代 SO-101 实际板卡输入规格。
- 控制板资源页列出通信协议、ST 内存表、驱动电路原理图、Python/Arduino/Linux SDK 和 STM32F103 SDK，可作为后续软件与电气审查入口；本轮没有下载归档这些 ZIP/XLS/PDF 原件，也没有验证目标 SO-101 控制板。
- 当前仍缺失：SO-101 随附板卡准确 SKU/版本、原理图、USB 桥/TTL 收发器型号、供电额定/峰值电流、反接/过流保护、隔离与接地、掉线/复位行为、固件哈希和六轴实际刷新率。

**工程判断：** 协议层已从“只有串行类型和波特率”推进到“可读懂帧结构、指令类型、控制表地址和反馈缩放”的公开资料级别；但这些是 WaveShare ST 系列参考文档，不是对 SO-101 套件板卡和实际 STS3215 固件的实机确认。后续必须做电机型号/固件读回、控制表关键字段核对、抓包和六轴同步读写时序测试。

### 1.8 LeRobot / rustypot 驱动实现与 STS3215 控制表逐项对照

**审查范围与版本边界：** 本节审查 Hugging Face LeRobot `main` 分支的 SO follower 实现、`SerialMotorsBus`、Feetech 行为测试，以及 Pollen Robotics 的 rustypot `develop` 分支 STS3215 定义。它们是可变动的开发分支，不等同于已锁定的 LeRobot 稳定发行版；当前 LeRobot API 文档明确说明 `main` 需要源码安装，`FeetechMotorsBus` / `DynamixelMotorsBus` 是过渡期弃用别名，底层串行通信与型号元数据已由 rustypot 接管。正式项目必须锁定 commit/tag、Python 包版本和 rustypot 版本。源码审查不代表在 SO-101 实物控制板上通过了验证。

|---|---|---|

| 位置环设置 | SO follower 在 torque-disabled 上下文中配置 position mode，并写 P/I/D 系数；当前配置默认 P=16、I=0、D=32 | 这些是软件默认参数，不代表经过本项目负载谱整定；实际响应、过冲、温升和稳定性需实测 |
| 夹爪保护参数 | 当前 follower 代码对 gripper 写 Max_Torque_Limit=500、Protection_Current=250、Overload_Torque=25，注释分别称为最大扭矩/最大电流的 50% 与过载扭矩 25% | 仅适用于该代码路径中的 gripper 设置；不等于整机扭矩限制或安全功能，单位/寄存器语义还须按准确 SKU 固件核对 |

| 观测/命令 | follower 的 get_observation 只对 Present_Position 做 sync_read；send_action 通过 sync_write 写 Goal_Position；如配置 max_relative_target，则先读 Present_Position 再裁剪目标 | 当前主观测路径未主动读取 Status、Present_Current、Present_Temperature 等字段；项目若需要故障/热监测，应单独设计采集和联锁 |
| 同步读语义 | rustypot 对同协议、同地址和长度的电机分组发送 Sync Read；LeRobot API 明确提示返回值不保证是同一时刻的同步快照，未支持 Sync Read 的舵机会逐个读取 | 六轴读回存在采样时差；需实测每轴时间戳/总线事务耗时，不能将“sync”理解成零时差同步采样 |
| 同步写语义 | Sync Write 不等待舵机应答，适合控制环，但丢包不会被舵机确认；普通 write 有应答，适合配置 | 位置命令广播后必须用后续状态读回、超时/看门狗和独立安全策略处理执行失败；不能仅凭函数返回认定每个舵机已执行 |
| 故障状态语义 | rustypot 的 STS3215 定义将 status alarms 视为告警而非通信拒绝；LeRobot 测试验证即使 Status 有 overload alarm，普通 read/write/sync_read 仍可继续 | 告警位不会自动等同于 API 异常；应用必须显式读取和解释状态字，避免“通信成功”被误判为“设备健康” |

**六轴总线频率证据（非保证值）：** rustypot README 报告，在一条 6 电机、1 Mbaud 的总线上，同时有第二个 Python 线程竞争时，将 Python `sys.setswitchinterval` 从默认 5 ms 调至 1 ms，示例吞吐由 126 Hz 提升到 340 Hz。该数字是库作者给出的特定软件/线程条件下观测值，不是 SO-101 官方保证、不是本项目实测，也不能直接作为 6 轴闭环频率承诺。实际性能取决于控制板 USB 延迟、串口适配器、固件回包、总线负载、主机调度、相机线程、重试次数和动作负载。

**与 WaveShare ST 文档的对照结论：**
- rustypot STS3215 定义的寄存器地址与 WaveShare ST 系列内存表在 ID、波特率、Phase、保护、Torque Enable、Goal Position、Present Position/Velocity/Load/Voltage/Temperature/Status/Current 等主要字段上高度对应；这增强了“同属 ST 系列协议布局”的软件证据。
- rustypot 使用的模型号 777、4096 分辨率、小端序、sign-magnitude 编码、homing offset 方向，以及 Phase bit4 处理，属于比一般协议概览更具体的型号实现信息。
- LeRobot 当前驱动并不在每个观测周期读取状态/电流/温度；同时 Sync Write 没有舵机应答，Sync Read 也不是严格同一时刻快照。必须将“命令已发出”“总线读写无异常”“舵机无报警”“关节运动达到目标”作为不同状态处理。
- 当前测试文件中的故障/固件/Phase 测试使用 mock bus；这些是软件单元测试证据，不是实际舵机、控制板、线束或六轴机械臂测试。

**建议写入本项目 ICD 的暂定软件接口契约（待实机确认）：**
1. 每臂独立串口总线，目标速率 1 Mbps；STS3215 型号定义 model number=777，12-bit 4096 steps/rev，小端序，位置/速度/偏置按 STS sign-magnitude 规则解释。
2. 建链时逐 ID 读取型号并核对同型号电机固件版本；记录电机标签、model number、firmware major/minor、ID、波特率、齿比 SKU、电压版本和控制板硬件/固件版本。
3. 运动数据路径使用 Present_Position Sync Read 与 Goal_Position Sync Write；同步读按“批量请求”而非“同一时刻采样”定义，Sync Write 结果需要独立回读/监测。
4. 另设健康监测周期读取 Status、Present_Current、Present_Temperature、Present_Voltage；定义报警位映射、过载/过流/过温/欠压的降级和停机状态机，并实测恢复/清除行为。此项是本项目设计建议，不是当前 LeRobot 默认实现。
5. 为每个总线周期记录发送/接收时间戳、每轴反馈到达时间、丢包/重试/超时和控制周期分布；至少在空载、额定任务候选负载和最不利同时运动条件下测量。
6. 在未明确失联安全行为、重力轴支撑/制动策略、独立急停/断能链之前，不得把 disable torque、disconnect 或软件目标限幅当作安全停止。

### 1.8.1 LeRobot SO-Follower 保护参数写入范围与健康观测缺口（2026-11-03）

**源码范围：** 本次读取 Hugging Face LeRobot `main` 分支的 `src/lerobot/robots/so_follower/so_follower.py`、`src/lerobot/motors/motors_bus.py`，以及 Pollen Robotics rustypot `develop` 分支 `src/servo/feetech/sts3215.rs`。分支可变；这里记录的是本次网页读取时的代码行为，不是已锁定的软件发布基线或实机结果。正式部署必须记录 LeRobot/rustypot 包版本和 commit。

**SO-Follower 的连接配置路径：**

1. `SOFollower.configure()` 在 `bus.torque_disabled()` 上下文中调用 `configure_motors()`，然后对全部六轴设置 position mode 和 P/I/D（默认 P=16、I=0、D=32）。
2. `SerialMotorsBus.configure_motors()` 对所有电机写 `Return_Delay_Time=0`；对支持相应寄存器的电机写 `Maximum_Acceleration=254` 和 `Acceleration=254`。这些属于 LeRobot 推荐的通用设置，不是 C046 厂商保护参数，也不是经本项目负载谱验证的安全值。
3. 在六轴循环中，只有 `motor == "gripper"` 分支额外写入：
   - `Max_Torque_Limit=500`，代码注释称最大扭矩的 50%；
   - `Protection_Current=250`，代码注释称最大电流的 50%；
   - `Overload_Torque=25`，代码注释称过载时 25% 扭矩。
4. 对照 rustypot STS3215 定义，上述三个名称分别对应地址 16（Max Torque Limit）、28（Protection Current）和 36（Overload Torque）；地址 34 则是另一个独立字段 `Protective_Torque`。因此不能把 LeRobot 的 `Overload_Torque=25` 错记为地址34，也不能把它与地址34的 protective torque 混为一谈。
5. Wiki 给地址28的通用单位为 6.5 mA/count；若按该通用换算，250约为1.625 A。但 LeRobot 注释的“50% max current”不是 C046 规格书对2 A/2 s过流动作的证明；寄存器的实际量纲、比较逻辑和 C046 固件默认/写入行为仍需对具体 SKU 读回及供应商确认。

**关键判断：** LeRobot 当前 SO-Follower 应用层显式写入这三项保护相关参数的对象只有夹爪（ID 6）；肩、肘、腕的五个关节没有在此代码分支中写入同样的三项参数。不能据此推断五个关节没有舵机固件内部保护；只能说此应用层配置没有为它们显式覆盖这些值。也不能将夹爪配置自动推广为所有 C046/C044/C001 电机的推荐值。

**运行时观测与命令路径：**

- `get_observation()` 对 `Present_Position` 执行批量 Sync Read，返回六轴位置；本路径没有主动读取 `Status`、`Present_Current`、`Present_Temperature` 或 `Present_Voltage`。
- `send_action()` 对 `Goal_Position` 执行 Sync Write；Sync Write 不等待每个舵机的状态应答，函数返回动作值不等于每轴执行确认。
- `max_relative_target` 配置默认是 `None`；只有显式配置后才增加当前位置读取和相对目标限幅。该软件限幅不是电流限制、碰撞检测、硬件限位或 STO。
- rustypot 的 STS3215 定义声明状态报警语义（`status_alarms_only`），其 API 也提供带状态错误字节的读写接口；但 SO-Follower 的常规观测特征只暴露位置。本项目不能把“总线请求成功”当作“舵机无告警”，需要独立健康监测和故障状态机。

**对本项目 ICD 的新增要求（建议，不代表现有 LeRobot 已实现）：**

1. 六轴逐只读取并保存地址13/14/15/19/20/28/34/35/36/38/55/65等适用寄存器；将出厂快照、LeRobot 连接配置后的快照分开存档，确认哪些字段被应用层改变。
2. 对 ID 1–6 建立保护参数矩阵，逐轴列出地址16/28/34/35/36/38的读回值、固件版本、准确 SKU 和批次；禁止假定仅因六轴同为 STS3215 型号号就具有相同的电机版本、机械负载或适用保护参数。
3. 为 Status、Present_Current、Present_Temperature、Present_Voltage 设计低频健康监测周期；定义每个状态位的采集时序、连续触发门限、告警/降级/停止状态、通信丢失行为、故障恢复与人工复位流程。监测周期须通过总线负载和热/动态测试确定。
4. 验证 `configure()` 在每次连接时重写哪些寄存器、EEPROM 锁定时写入是否仅临时生效、断电后是否保存，以及重连时是否再次覆盖；任何保护寄存器写入均须经过供应商确认和变更审批。
5. 在实际臂上分别验证肩/肘/腕重力负载、夹爪夹持力、保护触发后扭矩输出、状态字和恢复行为；不可把软件配置注释当成物理保护性能证明。

**源码证据结论：** LeRobot 的夹爪保护设置是明确的应用层参数写入；五个其他关节未在同一分支中获得同样的显式保护参数覆盖。当前 follower 位置观测路径不主动采集状态/电流/温度/电压，形成健康监测设计缺口。此结论是静态源码审查，未运行代码、未连接 SO-101、未读回任何真实寄存器。

### 1.9 SO-101 控制板身份、供电路径与硬件原理图核验

**证据结论先行：** LeRobot 当前 SO-101 官方装配文档明确写出：如使用 WaveShare 控制板，两个跳帽应置于 B（USB）通道；并要求控制板同时连接 USB 数据线、外部电源和舵机三芯线。该文档可证明官方流程支持/说明 WaveShare 控制板，但不能证明所有供应商套件、所有生产批次均随附同一 PCB。WaveShare 官方产品资料将 Bus Servo Adapter (A) 标为 SKU 25514；因此本节将其作为“与官方 SO-101 文档中 WaveShare 控制板相匹配的候选板卡”进行核验，不把它直接写成每台 SO-101 的实物确认结果。

| 维度 | WaveShare Bus Servo Adapter (A) 官方资料 | 对 SO-101 的工程含义 |
|---|---|---|
| 产品身份 | WaveShare 官方文档产品名 Bus Servo Adapter (A)，SKU 25514，尺寸 42 × 33 mm，安装孔 2.5 mm | 应与实物 PCB 丝印、外形、接口和 SKU 标签核对；套件 BOM 仅写 Motor Control Board 时不能自动认定 |
| 主机接口 | USB Type-C 是 USB-to-serial；USB 控制时跳帽置 B；UART 主机控制时跳帽置 A | LeRobot 文档要求 B（USB）通道；跳帽位置错误会导致主机串口路径不匹配 |
| USB-UART | 官方 FAQ 指定 CH343；公开原理图标注 CH343P | 可以确认 USB-UART 芯片家族；仍需对实际 PCB 版本/芯片丝印确认 |
| 单线总线接口 | 原理图将 CH343 TX/RX 通过 SN74LVC1G126DBV、SN74LVC1G125DBV 缓冲/使能逻辑及 MMBT3906R6 控制电路接到 DATA；D/V/G 分别是数字信号、舵机电源正、地 | 这是单线半双工 TTL 总线方向控制/电平缓冲拓扑，不是 RS-485 差分收发器；应与 STS 的单线 TTL 接口对应 |
| 供电输入 | 产品规格页写 9–12.6 V，同时补充“实际 5–8.4 V 也可输入”；支持 DC5521 和绿色端子 | 供电范围表述不够统一，必须按舵机 SKU、电源配置和板卡修订版本确认，不能只根据插头或标签推定 |
| 舵机供电输出 | FAQ 明确没有舵机输出稳压，舵机接口电压等于输入电压；USB-C 只负责串口通信，不能代替舵机供电 | 电源电压直接到达 V 总线；不得将 USB 5 V 当成舵机供电，也不得把板上逻辑电源稳压误认为舵机电源稳压 |
| 板上逻辑电源 | 原理图可见 DC_IN 输入经开关电源器件产生 5 V，AMS1117-3.3 产生 3.3 V 逻辑电源；这与 FAQ 所说“没有舵机输出稳压”并不矛盾 | 板上有逻辑电源变换，但不代表舵机 V 端经过降压/稳压 |
| 过流/额定电流 | FAQ 声称板卡最大可承受电流 5 A；原理图局部网名/标注出现“MAX:6A” | 5 A 与 6 A 标注存在口径差异；在 WaveShare 书面澄清前，设计上不得把 6 A 当作可连续额定值，更不能把 5 A 视为每个插座/线束/接插件均可承载值 |
| 保护电路 | 原理图可见 AO4407 MOSFET、SMAJ15CA TVS、BZT52C6V8S 等器件；但未从现有官方文字资料取得过流保护阈值、反接保护能力、热降额曲线、短路持续时间或自动恢复行为 | 不能仅凭存在 MOSFET/TVS 就声称具备完善反接、过流或短路保护；需向厂商索取保护动作参数并实测 |
| 板载“驱动芯片” | FAQ 明确该板没有独立舵机驱动芯片，主要是串口转换 IC | 不能把该板描述为电机功率驱动器；它是 USB/UART 到单线总线的接口板，并提供舵机电源分配路径 |
| 供电连接 | DC5521 与绿色端子均可给板卡供电，官方 FAQ 表示二者可任选其一；两个舵机总线接口相同 | 不要在未确认接线拓扑前将两路电源同时并联；线束压降、连接器接触电阻和总线分支仍需测量 |

**原理图可确认的电路边界：**
- USB 数据链：Type-C → CH343P USB-UART → TX/RX。
- 单线总线方向控制：CH343 UART 信号经 SN74LVC1G126 / SN74LVC1G125 缓冲使能逻辑及晶体管控制，汇入 DATA 单线端。
- 供电链：外部 DC 输入进入板卡；原理图显示板上另有 5 V / 3.3 V 逻辑电源变换。舵机接口 V 端按官方 FAQ 为输入电压直通，不是稳压输出。
- 原理图中的“MAX:6A”不能覆盖 FAQ 的 5 A 最大电流文字口径，也不能替代温升、连接器、PCB 铜厚和持续电流测试。
- 公开原理图是 WaveShare Bus Servo Adapter (A) 的设计证据，不等于当前 SO-101 套件中控制板的 BOM/PCB 修订版已经逐项确认。

**与 SO-101 软件/装配文档交叉核验：**
1. LeRobot SO-101 文档在 USB 配置步骤中明确提示 WaveShare 控制板跳帽置 B（USB），与 WaveShare 官方 Adapter (A) 的 USB 控制接线说明相符。
2. LeRobot 将电源、USB 和舵机三芯线列为控制板连接检查项；WaveShare 官方说明 USB-C 只负责串口通信，舵机必须由 DC5521 或端子独立供电。二者相互印证。
3. SO-ARM100/SO-101 上游 BOM 早期条目使用泛称 Motor Control Board；仅凭 WaveShare 安装板 STL 或泛称 BOM，不能确认任一实际套件板卡为 SKU 25514。需要实物正反面照片、PCB 版本/丝印、采购 SKU 或供应商 BOM 证明。
4. LeRobot 驱动中的 1 Mbps 是总线默认波特率；WaveShare Adapter (A) FAQ 说明板卡波特率应与舵机一致，厂商舵机出厂默认 1 Mbps。该参数仍应在实机逐 ID 读回，而非假定每批电机保持出厂值。

**必须补齐的板卡与供电验证项：**
- 实物身份：PCB 正反面高清照片、丝印、版本号、板卡 SKU、USB-UART 芯片标记、跳帽位置、连接器标记；与 WaveShare 25514 原理图/STEP 逐项比对。
- 电源：输入电压范围、启动浪涌、六轴同时运动峰值电流、持续电流、插座/端子/线束/PCB 温升、线束压降；在标准 C001、C044/C046 等实际 SKU 上分别测试。
- 保护：反接、短路、过流、欠压、瞬态浪涌、TVS 能量能力、热保护/降额、故障恢复和重复启动行为；明确保护是板级、适配器级还是电源级。
- 通信：USB-UART 芯片驱动与串口延迟、波特率误差、方向切换死区、半双工冲突、总线电平高低阈值、地弹噪声、六轴同时运动时丢包/重试。
- 供应商书面澄清：FAQ 的 5 A 与原理图“MAX:6A”差异；9–12.6 V 与 5–8.4 V 的适用条件；是否有反接/过流保护及其阈值；额定电流是连续值还是峰值、适用连接器/PCB 修订版。

**工程判断：** 对 WaveShare Bus Servo Adapter (A) 的公开身份、CH343P、单线 TTL 方向控制拓扑、外部舵机供电直通及接口已获得官方资料/原理图支持；但 SO-101 实物板卡 SKU、PCB 修订版、5 A/6 A 额定差异和实际供电保护能力尚未确认。下一步应先拍摄并核对实际板卡，再进行电源与通信测试；在此之前不将 Adapter (A) 规格直接写入 SO-101 整机硬件基线。

## 2. 证据等级和不能推导的结论

| 公开资料事实 | 不能据此推导 |
|---|---|
| 峰值扭矩、堵转扭矩 | 连续扭矩、持续时间、全速度范围可用输出 |
| 额定扭矩/额定功率单点 | 任意速度和环境下的热稳态工作点 |
| 负载 payload | 任意姿态/速度/加速度/重心下的允许载荷 |
| 最高波特率/接口类型 | 多轴网络在给定更新频率下无丢包、低抖动 |
| 温度阈值/过温保护 | 整机风险降低到可接受或满足功能安全 |
| 3D 模型/DH 参数 | 实物零位、安装公差、标定精度与可达性已验证 |
| CE 或页面上的安全宣传 | 本项目具体配置满足适用法规或协作安全要求 |

## 3. 面向桌面分拣任务的统一验证输入

在对比任何产品之前，必须填写 [07 任务负载谱与输入模板](07-任务负载谱与输入模板.csv)。至少把下列数据统一到相同单位和工况：

1. 末端总质量：夹具、线缆、传感器和工件合计。
2. 末端质心：相对法兰/TCP 的三轴偏置。
3. 任务位姿：供料、取料、转运、放料各点的 XYZ/RPY 和姿态容差。
4. 轨迹：每段速度、加速度、减速度、停留时间和循环频率。
5. 工件：质量范围、外形包络、惯量估计、抓取力/摩擦边界。
6. 工作制：每小时循环数、每日小时数、连续运行时长、环境温度和冷却条件。
7. 故障工况：卡滞、掉电、通信丢失、编码器异常、急停和人工恢复流程。

整机候选先做工作空间/姿态/碰撞和任务节拍筛选；关节模组候选再做逐关节重力、惯性、摩擦和外力矩计算。所有计算应保留输入、模型版本、单位、边界条件和审查人。
