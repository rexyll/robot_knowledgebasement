# 21-STS3215保护寄存器单位与阈值逻辑核验

> 状态：进行中  
> 目的：核对 STS3215 保护寄存器的地址、数据宽度、单位和保护逻辑，特别区分 `Protection_Current`、`Protective_Torque`、`Protection_Time`、`Overload_Torque`、`Over_Current_Protection_Time`；不得把通用 STS 定义直接等同于 SO-101 所装 C046 的固件默认值。

## 1. 证据边界

本轮采用：
- Feetech 官方 STS3215 产品规格/教程：确认产品级保护动作描述；
- LeRobot / rustypot 源码：确认当前软件使用的寄存器地址、宽度和写入边界；
- 第三方实现：仅交叉核对单位，不作为 C046 固件默认值的唯一证据。

仍未连接 SO-101 实机，未读取 C046 EEPROM，未触发保护，因此任何“默认值”都不能写成目标电机实测值。

## 2. 关键寄存器

| 地址 | 字段 | 宽度 | 当前结论 |
|---:|---|---:|---|
| 13 | `Max_Temperature_Limit` | 1 byte | 温度上限 |
| 14 | `Max_Voltage_Limit` | 1 byte | 电压上限，控制表单位 0.1 V/count |
| 15 | `Min_Voltage_Limit` | 1 byte | 电压下限，控制表单位 0.1 V/count |
| 19 | `Unloading_Condition` | 1 byte | 保护/卸载条件位 |
| 28 | `Protection_Current` | 2 bytes | 保护电流阈值 |
| 34 | `Protective_Torque` | 1 byte | 保护扭矩参数 |
| 35 | `Protection_Time` | 1 byte | 保护持续时间参数 |
| 36 | `Overload_Torque` | 1 byte | 过载扭矩阈值 |
| 38 | `Over_Current_Protection_Time` | 1 byte | 过流保护持续时间 |
| 65 | `Status` | 1 byte | 运行时状态字节 |

## 3. `Protection_Current` 地址28

Feetech STS 通用资料给出的工程量纲为 **6.5 mA/count**。因此：

- `250 count × 6.5 mA/count ≈ 1.625 A`；
- 这个换算可用于理解 LeRobot 的 `Protection_Current=250`；
- 不能仅凭 LeRobot 注释“50% max current”推出 C046 的真实最大保护电流，更不能把 1.625 A 当作已经实测的 C046 触发点。

第三方 STS 硬件接口实现也采用 6.5 mA/unit，但仍只能作为交叉证据。

## 4. `Protective_Torque` 与 `Overload_Torque` 必须分开

地址34和36不是同一个参数：

- 34 = `Protective_Torque`
- 35 = `Protection_Time`
- 36 = `Overload_Torque`

Feetech 官方 STS3215 产品规格描述过载保护为：负载达到堵转相关比例并持续达到设定时间后进入保护，并说明堵转百分比和持续时间可自定义。该描述支持“扭矩比例阈值 + 持续时间”的逻辑，但本轮没有得到 C046 固件逐字段默认 EEPROM 表，因此不能从通用描述反推 C046 当前默认值。

## 5. `Protection_Time` 与 `Over_Current_Protection_Time` 不可混淆

地址35与地址38分别存在：

- 35 = `Protection_Time`
- 38 = `Over_Current_Protection_Time`

Feetech 官方规格对过流保护的产品描述为：运行中电流超过设定值并持续约 2 s 后关闭输出并进入过流保护，同时说明电流值和持续时间可自定义。这个产品规格描述不能替代目标 C046 对地址28/38的实机读回。

## 6. 地址19 `Unloading_Condition`

Feetech 官方教程说明地址19通过 bit 组合启用过载、电流、温度、电压等卸载/保护条件。例如值45由多个保护位组合而成。

因此配置快照应同时保存：

`Unloading_Condition(19) + Protection_Current(28) + Protective_Torque(34) + Protection_Time(35) + Overload_Torque(36) + Over_Current_Protection_Time(38)`。

不能只看到某个阈值就声称“保护已经开启”。

## 7. LeRobot 当前写入边界

当前 SO-Follower 应用层源码中，只有 `motor == "gripper"` 分支显式写入：

- `Max_Torque_Limit=500`（地址16）；
- `Protection_Current=250`（地址28）；
- `Overload_Torque=25`（地址36）。

因此这三个值不能描述成 SO-101 六轴统一的 C046 默认保护参数。其余五轴在该代码分支没有显式写入这三项，不代表固件没有内建保护。

当前常规观测主要读取 `Present_Position`，不主动把 Status/Current/Temperature/Voltage 全部纳入每周期健康反馈；保护配置和运行时状态仍是两条证据链。

## 8. C044 / C046 差异处理

C044、C046 都属于 STS3215 家族并共享大量控制表字段，但不能因为寄存器地址相同，就宣称两者固件默认值、阈值或保护动作完全一致。

证据应分为：

1. 通用 STS3215 控制表：地址、字段名、数据宽度和通用单位；
2. C046 官方规格：C046 产品级机械/电气/保护规格；
3. C046 固件版本资料：固件绑定的默认值/状态语义；
4. C046 实机 EEPROM 读回：目标 SO-101 的真实配置基线。

当前尚缺第3、4项。

## 9. 对 `500 / 250 / 25` 的结论

- `Protection_Current=250`：按通用 6.5 mA/count 约 1.625 A；不能写成已验证的 C046 触发阈值。
- `Overload_Torque=25`：确认写入地址36；不能在缺少 C046 固件证据时进一步声称其具体物理扭矩触发曲线。
- `Max_Torque_Limit=500`：地址16；不能与地址34/36混淆。LeRobot 注释中的“50%”属于代码/控制表口径，不是 C046 实机验证的物理扭矩上限。

因此本项目暂不把 `500 / 250 / 25` 提升为“C046 固件安全参数结论”。

## 10. 保护动作与整机安全边界

Feetech 官方规格描述了过载、过流、过压、过热等内部保护动作，包括关闭输出/进入保护、重新发送位置指令清除部分保护、过压恢复正常后自动解除、过热关闭扭矩输出等。

这些是**舵机内部保护行为**，不能直接等同于 SO-101 整机安全功能。整机安全判定仍需独立记录：

- 总线通信是否健康；
- 协议 error field；
- 地址65 `Status`；
- `Torque_Enable`；
- Current / Temperature / Voltage；
- 控制循环是否停止继续发送；
- 保护后是否需要人工复位。

## 11. 实机验收快照

目标 SO-101 到手后，每轴至少读取：

```text
motor_id
model_number
firmware_major/minor
ID / Baud_Rate
Unloading_Condition (19)
Protection_Current (28)
Protective_Torque (34)
Protection_Time (35)
Overload_Torque (36)
Over_Current_Protection_Time (38)
Torque_Enable (40)
Present_Voltage (62)
Present_Temperature (63)
Status (65)
Present_Current (69)
```

保存：`timestamp + motor_id + firmware + raw register values + converted values + LeRobot/rustypot version + configuration commit`。

保护测试还需保存触发前/触发后快照；没有该证据，不把“保护已验证”写入验收状态。

## 12. 当前结论

1. 地址28、34、35、36、38是五个不同的保护配置字段，不能合并。
2. `Protection_Current` 的公开通用工程单位可按 6.5 mA/count 使用；LeRobot 的250约为1.625 A，但 C046 实际触发阈值仍未验证。
3. 地址36 `Overload_Torque` 与地址34 `Protective_Torque` 不同；地址35与38也是不同时间字段。
4. Feetech 官方规格描述了保护动作，但 C046 目标固件默认 EEPROM 值、地址19开关组合和地址65状态位仍需版本资料和实机读回。
5. LeRobot 的 `500 / 250 / 25` 只在 gripper 分支显式写入，不能提升为六轴 C046 统一默认保护配置。
6. 本轮完成文档/源码层的参数语义收敛，**没有完成实机验收**；25-14 继续保持“进行中”。
