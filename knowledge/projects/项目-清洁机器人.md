# 项目：cleanning_robot（商用清洁机器人全栈）

> **定位**：一台**商用清洁机器人**的完整软件系统：「三端 + 一朵云」。2026-10-30 完成五仓合一重构（Algorithm/App/Chassis/Cloud/Terminal_ros2 从五个独立 git 仓合并为一个仓库）。
> **路径**：`本地工作区路径未公开（公开仓库不记录绝对路径）`　**梳理基线**：项目内 `docs/ARCHITECTURE.md`（重构后基线）+ `docs/INDEX.md`

## 1. 三端 + 一朵云

| 角色 | 载体 | 技术栈 | 职责 |
|---|---|---|---|
| **机器人终端** | Ubuntu + **ROS2 Jazzy** | C++17 / Python3 / **BT.CPP v4** / **Poco** / SQLite | 任务编排、清扫控制、底盘驱动、建图定位导航、本地 HTTP 服务（端口 **9000**，84 个 action） |
| **云端** | Node.js 18+ | Express / **aedes（MQTT broker）** / better-sqlite3 | 设备接入、遥测存储、地图中转、OTA 包分发、App REST（MQTT 1883 / 终端 API 8090 / App REST 8080） |
| **App** | Android 8.0+ | Kotlin / OkHttp / **Paho MQTT** | 远程监控、任务下发、地图、参数、OTA |
| **算法库** | 纯 Python（可被终端 import） | NumPy / OpenCV | 覆盖规划、路径跟随、覆盖率统计、脱困、视觉里程计 |

## 2. 目录结构与包分布

```
Algorithm/robot_algorithms/   纯 Python 算法库(可插拔注册)
Chassis/                      底盘驱动: AckermannChassis / DifferentialWheelChassis
                              / robot_hardware(IChassisDriver 抽象+3 backend) / ros_chassis_control
Terminal_ros2/src/            21 个编译包: ros_framework(HTTP 9000 单进程)
                              ros_iot / ros_ota / fsm_core / ros_vslam / ros_coverage
                              ros_selfchecking / real_robot_bringup / navit_msgs
                              modules/(Core/Server/Devices/Algorithms 框架结构)
Cloud/                        Node.js 云端
App/                          Android(Kotlin)
Hardware/                     display / sensor / voice 板级驱动
scripts/                      29 个脚本(24 构建/部署 + 5 测试/CI)
```

## 3. 可插拔算法架构（Algorithm/ 的设计亮点）

```
iface/:  ICoveragePlanner / IPathFollower / ICoverageStats / IEscapePolicy
coverage/: BoustrophedonDiffPlanner(差速弓字形) + AckermannCoveragePlanner(阿克曼)
           ─ d≥2R 半圆掉头 / d<2R 三点掉头 / Dubins
follower/: DiffPurePursuit / AckermannCurvatureTracker
stats/:    GridCoverageStats(栅格标记+任务多边形口径)
escape/:   StallEscapePolicy(阈值检测+后退/偏转机动)
registry.py: 工厂 create_planner/create_follower(chassis_type)
```

> **换机器人类型只换算法实现，换底盘厂商只换驱动实现，框架与业务节点零改动**——与 [[项目-amr]] 的 Capability 思想同源，与 [[项目-Bozlin视觉框架]] 的插件注册同构。

## 5. 架构工程化亮点（可作为团队范本）

1. **统一错误码契约**（`successed=true ⇒ code=0`）+ 请求级 trace id + `X-Request-Id` 回带
2. **HTTP 鉴权**（ROBOT_HTTP_TOKEN / X-Device-Token）+ /health 白名单
3. **机型 Profile**（`robot_profile.yaml`）取代编译期宏选行为树
4. **三层测试网**：契约（接口形状）→ 冒烟 → 行为（FSM 场景断言）+ `scripts/ci.sh`
5. **仿真验证矩阵**：13 项"真机阻塞项"在 Gazebo 验证（9 可验/2 部分/3 只能真机），底盘串口协议栈用 PTY+虚拟运控板仿真 → [[仿真平台]]
6. **退出序列修复**：退出期死锁 + CLI 线程 + 工作线程可中断（工程细节见 OPTIMIZATION_PROPOSAL §18-24）
