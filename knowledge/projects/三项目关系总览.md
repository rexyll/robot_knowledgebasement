# 三项目关系总览

> 三个项目分别来自三个工作区（`AMR 本地工作区（绝对路径未公开）`、`清洁机器人本地工作区（绝对路径未公开）`、`视觉框架本地工作区（绝对路径未公开）`），现有资料显示三个项目在部分技术栈与架构设计上存在相似性；组织归属和团队关系尚无可公开来源验证。

## 1. 一图看血缘

```
Bozlin Vision Framework V2 (2019-2020, C++)
  Core/Server/Devices/Algorithms 插件四分法 + Poco + GTest + 云升级(VisionGuard)
        │ 蓝本传承(目录结构同构)
        ▼
清洁机器人 modules/ (2026 重构)          amr (2026 能力插件化重构)
  Core/Server/Devices/Algorithms          gen_capability_core/host
  + fsm_core + ros_iot/ros_ota            + gen_plugin_*
  (ROS2 Jazzy + BT.CPP)                   (ROS2 Jazzy + 契约/宿主/插件)
        │
        └──── 共同思想: 设备抽象 / 算法插件注册 / 守护自更新 / 契约化接口
```

## 3. 共同技术基因（谱系证据）

1. **设备抽象 + 插件注册**：Bozlin 的 Devices/Algorithms → 清洁机 modules/ 同名结构 → amr 的 gen_plugin_*，十年一贯
2. **守护与自更新**：VisionGuard/Guardian/Daemon → ros_ota/Cloud → 云端灰度
3. **Poco 出现两次**：Bozlin 框架底座、清洁机器人终端 HTTP 框架（C++ 服务端同源）
4. **契约先行**：Bozlin config.json 接口集 → 清洁机 84 action 错误码契约 → amr CONTRACT_IDL.sha256 + 版本冻结
5. **台账式工程管理**：三项目均有"单一事实源"文档（README/INDEX/ARCHITECTURE + 台账），CI 连文档链接都查——同一团队工程文化的印记

## 4. 差异与各自演进方向

| 项目 | 落后于行业的地方 | 已领先的地方 | 升级方向（→ [[发展趋势]]） |
|---|---|---|---|
| Bozlin | 无 SLAM/导航概念（纯视觉域）；算法以传统 CV+OpenCV 为主 | 多相机抽象、跨平台、云升级 | 算法插件加载 DL/VLA 模型；Faro 点云接 3DGS |
| 清洁机器人 | 单机云调度（无 VDA5050/大规模交管） | 可插拔双底盘算法、三层测试网、仿真正式化 | 接 LIO（FAST-LIO2 类）；污渍识别 DL 化；多机交管 |
| amr | aic_* 旧副本技术债；ROS1 机型资产待迁移 | 能力插件化+故障注入+热切换（行业 SOA 化前列） | localization_slam 引入 LIO/3DGS；数据闭环（rosbag→训练） |

## 5. 若三项目合并（架构收敛建议）

```
统一插件底座: gen_capability_core(契约/宿主/插件) 作为全公司标准
  ├── 导航域: gen_nav_core + 清洁机 coverage 插件(全覆盖=导航插件的一种)
  ├── 视觉域: Bozlin Devices/Algorithms 收编为 capability 插件(设备/算法)
  ├── 底盘域: IChassisDriver 抽象统一双机三底盘
  └── 云域: MQTT(aedes)+ZMQ+protobuf 契约统一, OTA 通道合并
```
