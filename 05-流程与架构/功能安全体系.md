# 功能安全体系

> 安全不是功能，是**属性**：在最坏情况下系统仍不伤人。机器人安全 = 风险评估 → 安全功能设计 → 独立于软件的硬件兜底 → 认证。标准全文见 [[标准与法规]]。

## 安全理念三支柱

1. **纵深防御**：软件避障（预防）→ 安全传感器停车（防护）→ 机械缓冲（兜底）→ 应急处置（事后）
2. **独立通道**：安全功能与业务软件**物理隔离**——MCU 硬线/独立供电/独立断路路径，软件崩溃不影响安全链
3. **等级匹配**：风险越高，安全完整性等级（PL/SIL）要求越高

## 风险评估流程（ISO 12100 方法论）

```
1. 危险识别: 撞人/碾压/挤压(货架间)/坠物/夹伤(货叉)/电击/火灾(电池)
2. 风险估计 S×F×P:
   S=伤害严重度(擦伤1-死亡5) F=暴露频率 P=规避可能性
3. 风险等级 → 决定所需 PL 等级(A/B/C/D/E)
4. 措施设计 → 残余风险验证 → 文档存档(认证审计用)
AMR 典型结论: 撞击类 → PL d(Cat.3); 挤压类 → PL d; 电池火灾 → 预防性设计
```

## 安全架构分层（→ [[AMR整体架构]] 的安全流）

```
L1 硬件安全层(独立): 急停回路/触边回路/安全继电器/安全扫描仪内部逻辑 — 不依赖任何软件
L2 MCU 固件安全层: 心跳/限速/围栏坐标表(独立 Flash 区, 主控只读) — 最简代码, 高覆盖率测试
L3 软件安全层(ROS/导航): 降速/绕行/恢复行为 — 提升体验, 不承担最后防线
L4 调度安全层: 区域准入/车队冲突/人流模式 → [[多机协同与调度算法]]
```

> 常见工程误区：把 L1 的活交给 L3（"软件里判一下距离就停"）——过不了认证，也过不了事故鉴定。

## 认证与合规路径

| 步骤 | 内容 |
|---|---|
| 1. 标准选择 | 移动机器人: ISO 3691-4 / ANSI R15.08; 人机共存: ISO 13482; 器件级: ISO 13849(PL) / IEC 62061(SIL) |
| 2. 安全需求规格 SRS | 每个安全功能的定义/参数/验证方法 |
| 3. 设计验证 | 硬件冗余通道测试、MTTFd 计算、故障注入测试 |
| 4. 型式试验 | 制动距离（不同载重/速度/坡度矩阵）、撞击力（≤ISO/TS 15066 人体模型限值） |
| 5. 认证机构 | TÜV/BV/SGS/中国 CQC；出厂每台例行检验（急停/触边动作测试） |

## 碰撞风险量化（ISO 3691-4 公式核心）

```
安全距离 S = (v·t_total) + v²/(2a_brake) + 余量
t_total = 扫描周期 + 响应时间 + 机械延迟 (典型 0.3-0.6s)
例: v=1.5m/s, t=0.4s, a=1.5m/s² → S ≈ 0.6+0.75+0.1 ≈ 1.45m (保护区半径下限)
满载制动距离↑ → 保护区自动加大(field set 切换)
```

## 事故应急与取证

- 黑匣子：碰撞前 30s 的速度/定位/传感器日志本地持久化
- 视频存证：碰撞触发前后视频云端留存
- 保险对接：出厂安全文件包（风险评估报告+认证证书+测试记录）→ [[标准与法规]]

## 细节加深（V2）
- **安全文件包清单**（出厂随车）：风险评估报告、安全需求规格 SRS、PL 计算书、型式试验记录（制动矩阵）、例行检验规程、ECO 变更记录——审计/保险/事故鉴定全靠它，缺一项都是隐患。
- **故障注入必测六项**：拔 LiDAR、遮相机、断网 60s、急停拍下/复位、触边触发、电池拔到 15%——每项断言「车进入定义好的安全态」（与 [[09-10-系统联调与测试]] L4 对齐）。
