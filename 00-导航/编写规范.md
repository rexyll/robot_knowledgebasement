```markdown
# 标题

> 一句话定位

## 1. 核心内容（原理/分类/参数表——V1 已有，V2 加深）
## 2. 上游板块          ← 必填
## 3. 下游板块          ← 必填
## 4. 细节加深（V2）     ← 高赞文章/官方文档吸收的内容
## 5. 代码实例与开源项目（V2）
## 6. 厂商与资源（V2，硬件类笔记）
## 相关链接（V1 已有，与上游/下游节互为补充：此处放跨板块关联）
```

## 2. 「上游板块 / 下游板块」标准写法

> 上游 = 本板块**依赖/消费**的板块（没有它做不了）；下游 = **依赖/消费**本板块的板块（它做不了会受影响）。每条格式：`[[页面]] —— 一句话说明依赖关系（类型：硬件/软件/算法/流程/行业）`。硬件、软件、算法三类板块在彼此的上下游中必须互相可见。

```markdown
## 上游板块
- [[激光雷达]] —— 提供点云输入（硬件）
- [[ROS与ROS2]] —— 驱动与消息框架（软件）

## 下游板块
- [[导航流程]] —— 消费本页定位输出（流程）
- [[性能指标体系]] —— 重定位成功率等 KPI 定义（参数）
```

```markdown
|---|---|---|---|
| SICK | <URL> | TiM/nanoScan3… | <手册URL> |
> 参数快照日期：YYYY-MM-DD（来源见 [[链接台账]]）
```

## 5. 链接纪律

1. 每条外链写入前必须 WebFetch 验证并登记 [[链接台账]]（全量逐条验证，用户确认）。
2. 页面内引用外链时附带快照日期；价格/版本类信息必标「快照：日期」。
3. 知识库内互链一律 `[[页面名]]`；跨目录同名不存在冲突（V1 已验证唯一性）。
4. 双链校验脚本：Node（TaskPlan H1 节复用）。

## 6. 只增不删原则的文件级体现

1. V1 笔记的既有结论**不删改**；加深内容以「## 4. 细节加深（V2）」等新增小节追加。
2. 发现 V1 错误：在 TaskPlan 优化项区建 `Oxx` 节点，修正记录写入对应笔记「勘误」节，原文保留删除线或括注。
3. 台账三件套：[[TaskPlan]]（任务）· [[链接台账]]（外链）· [[术语表]]（概念），任何新概念先入术语表。
