## v1｜CANopen Bus-Off/restart 与 SDO/NMT 会话恢复专项复核

### 已完成

- [x] 审查 `SocketCanTransport` 对 `CAN_ERR_BUSOFF` 与 `CAN_ERR_RESTARTED` 的订阅、接收和状态迁移；确认 Restarted 通知只把 transport state 设为 Online，没有 epoch/generation 或上层会话失效事件。
- [x] 审查 `CanopenVirtualNode::set_bus_off()` / `set_bus_recovered()`：前者仅置通信故障标志，后者仅清该标志；不重置 segmented SDO 会话字段、NMT state、CiA-402 对象状态或 PDO 映射。
- [x] 审查 NMT Reset 0x81/0x82 路径：只改变 NMT state 为 Initialising，没有调用 SDO transfer reset。
- [x] 对照现有测试：`CanopenRecovery.BusOffInhibitsProtocolAndRecoveryRestoresIt` 仅覆盖新建 PreOperational node；分段 SDO 测试未注入 Bus-Off；SocketCAN 测试未覆盖真实错误帧 BusOff/Restarted 序列。
- [x] 形成 transport/session/motion 分层恢复方案与 fault-injection HIL 验收清单，写入《轨迹优化与运动控制》§26；更新 EXT-001、第14章和根 TaskPlan 至 v11.94。

### 结论

**P1 会话一致性与恢复门禁缺口**：SocketCAN 收到 Restarted 后 transport Online 不能作为 CANopen 应用会话恢复证明。Virtual node 的恢复 helper 保留 SDO 分段状态和 NMT/CiA-402 状态，可能使中断前的旧分段会话继续，或在恢复后仍保持 Operational。该结论针对当前 SIL virtual node 模型和 transport 接口；不能推断所有真实 CANopen 从站都会在 Bus-Off 时重置 NMT/SDO。远端节点可能继续运行，恢复必须显式验证 heartbeat、NMT、PDO、Statusword 并重新授权 motion。
