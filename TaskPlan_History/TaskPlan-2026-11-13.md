### Fast DDS SHM exception path explains the ASan CHECK timing

- [x] Reviewed Fast-DDS 2.14.x `SharedMemTransport::CreateInputChannelResource()` and `SharedMemGlobal::open_port_internal()` source. The shared-memory port startup path intentionally attempts `open_only`; if the segment is absent or incompatible, it catches the exception and proceeds to create a new segment.
- [x] Thus C++ exceptions can be normal control flow during first-time DDS SHM port initialization. The ASan `real___cxa_throw != 0` CHECK aborts while Fast DDS is taking this exception-based open-or-create path, before MoveIt startup.
